## Blockers

### B1 — `tjs` CLI eagerly imports the TypeScript compiler; the binary hard-fails for consumers without it
`src/cli/tjs.ts:20` → `src/cli/commands/convert.ts:23` → `src/lang/emitters/from-ts.ts:33` (`import ts from 'typescript'`). `typescript` is a **devDependency** (`package.json:227`), `files` ships raw `src`, and `bin.tjs` = `./src/cli/tjs.ts`.

Reproduced in a simulated clean consumer install (only `acorn`, `acorn-loose`, `acorn-walk`, `tosijs-schema` present):

```
$ bun src/cli/tjs.ts check t.tjs
error: Cannot find package 'typescript' from '…/src/lang/emitters/from-ts.ts'
```

This fires at **entry**, so `tjs --version` and `tjs --help` are broken too. It is a verbatim repeat of the snowfox production bug class that `src/index-tsfree.test.ts` guards for the *library* entry — the CLI entry has no such guard. Even where `typescript` resolves, it costs ~85ms of the ~120ms cold start on `check`/`run`/`emit`/`types`/`test`, none of which touch TypeScript.

**Fix (one line, sole call site is already `await`ed at `tjs.ts:193`):**
```ts
const { convert } = await import('./commands/convert')
```
Then extend the ts-free guard to `src/cli/tjs.ts` so it cannot regress.

**Secondary, same finding:** the freshly regenerated `benchmarks.md` prints `tjs emit 113.0ms` / `tjs check 110.8ms` against a `42.0ms` baseline while its auto-generated Key Findings says overhead is "none measurable" — the prose at `bin/benchmarks.ts:460` computes overhead only from `tjsxTime - bunTsTime`, so it structurally cannot see the `tjs` rows.

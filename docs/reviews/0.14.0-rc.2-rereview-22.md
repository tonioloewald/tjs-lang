**Verdict: BLOCK.** No finding is rated *blocker*. Three distinct correctness majors are confirmed, all introduced or newly exposed by round 17, and all fail **silently**: an atom runs with missing or wrong-typed inputs and the run reports success. ## Are we converging or diverging?

**Architecturally, converging. By severity this round, worse.**

- **Converging.** Rounds 18–21 each patched another cell of a VM table that classified atoms by *reading their schemas*. Schemas are an open domain, so each new rule broke a shape that already worked. Round 17 moved the primary rule to the transpiler, where the question is decidable from syntax: `foo({…})` is named, `foo(a, b)` is refused. That ends the schema-classification treadmill. None of this round's findings argue for going back to it.
- **Worse this round.** Round 21 found one *loud* regression (a refusal with a misleading message). This round has three *silent* ones, and they belong to exactly the defect class the cycle exists to remove: "atom runs with inputs undefined and reports success".
  - Deleting the VM rule reopened that defect for every AST producer except our transpiler. That includes `vm-ast`, the VM the security model recommends, which never sees source.
  - The emitter still writes `args: []` for `foo()`. callShape used to strip it before it reached a named `args` input, and that guard is gone.
  - The new error message leads people to `foo({ ...opts })`, and the emitter drops a spread silently.
- **Why this still looks tractable.** All three fixes are small and need no schema classification:
  - emit no `args` key for a zero-argument atom call;
  - refuse a spread in an atom-call object literal at transpile time;
  - add a VM check that reads only *presence*.
  The VM check is the round-21 "refuse only what cannot have worked" spec, which was proposed, held for Tonio, and then not implemented.
- **The danger point.** The VM presence check is where the cycle could restart, if "declares no `args` property" gets decided by interpreting schema shapes (`s.any`, records, unions). Write its domain down as an explicit table *before* coding it:
  - object schema with named `properties`, no `args` property, and a non-empty `args` array → refuse;
  - everything else → run as written.
  Then pin each cell on both VMs.

## Blockers (confirmed correctness majors, treated as release-blocking)

### B1. A zero-argument atom call emits `args: []`, which now reaches a named `args` input (correctness, confirmed, regression in this diff)
- **Where:** `src/lang/emitters/ast.ts` ~1406 (the `named` check) and ~2335 (`extractCallArguments`).
- **What:** `withArgs()` against `s.object({ code: s.string.optional, args: s.record(s.any).optional })` returns `[]`, an array delivered into an optional *record* input with no boundary validation. At base, callShape stripped it and the call returned `'none'`. The row covering this cell was deleted from `call-shape.test.ts`, not carried over, and the suite's own `loose` fixture has the same bug.
- **Fix:** when `named` is true and there are no arguments, emit no `args` key. Keep `args: []` only for `POSITIONAL_BUILTINS` (`Error()`). Restore the "named `args` input, empty call → undefined" row on both `vm` and `vm-ast`, and keep the hand-built rc.1 `args: []` row as the persisted shape.

### B2. A spread in an atom-call object literal is dropped silently, and the new error leads people to write one (correctness, confirmed; the drop predates this round but is now on the main migration path)
- **Where:** `src/lang/emitters/ast.ts` ~2318 (`extractCallArguments` handles only `Property`).
- **What:** `const o = {a:1,b:2}; echo({ ...o })` emits `{op:'echo', result:'v'}` and runs successfully with no inputs. `storeGet({ ...{key:'a'} })` calls the store with `key: undefined`. Round 17 refuses `foo(opts)`, so `foo({ ...opts })` is the obvious workaround, and it reproduces the defect.
- **Fix:** throw a `TranspileError` on any non-`Property` member, naming the explicit form `foo({ a: o.a, b: o.b })`, or lower the spread properly. Add `greet({ ...opts })` to `REFUSED_AT_TRANSPILE` in `call-shape.test.ts`. (Per `feedback_predates_is_not_a_reason`, the fact that the drop predates this round is no reason to defer it.)

### B3. With the VM refusal deleted, positional ASTs from any producer except our transpiler silently run named atoms with undefined inputs (correctness and blast-radius, both confirmed, merged)
- **Where:** `src/vm/runtime.ts` ~4757–4760. `callShape`, `isPositionalAtom` and `namedInputs` were deleted from `defineAtom`'s exec.
- **What:** the hand-built v2 AST `{op:'storeSet', args:['k',42]}` → `{op:'return', value:{ok:true}}` returns `{ok:true}`, and the store records `set(undefined, undefined)`. Affected: hand-built ASTs, third-party front ends (which the security model invites), procedureStore/rc.1-persisted ASTs (rc.1 compiled `storeSet('k', v)` to exactly this shape), and every `tjs-lang/vm-ast` caller. The CHANGELOG line "It used to compile, and … reported success" reads as fixed, but it is fixed for one producer only. The VM also never checks received inputs against `inputSchema`, so a missing *required* input passes.
- **Fix (pick one, write the cells down first):**
  - (a) A narrow VM refusal: a **non-empty** `args` array on an atom whose object schema declares named properties and no `args` property. It reads only presence, so it does not misfire on `random()` (empty), `loose` (declares `args`), `Error` or `runCode`. Pin it with AST-level rows, built without `transpile()`, on both VMs.
  - (b) If not policing this in the VM is deliberate, record it as a keep-decision in `docs/vm-budgets.md` / the Security Model and add a CHANGELOG + DOCS-AJS sentence for AST producers: the VM does not detect positional `args` sent to a named atom, and persisted rc.1 positional ASTs will silently no-op.
- **Re-review scope (B1–B3):** correctness and blast-radius over the remediation diff only.

## Diagnosis (filed before acting; HELD for Tonio)

The three blockers share one cause, which the review names in passing: **the VM never checks an
atom's inputs against the input schema the atom declares.** Every "runs with undefined inputs and
reports success" defect in rounds 14–22 is that missing check, met through a different producer:
- the transpiler's positional call;
- `args: []` from `foo()`;
- a dropped spread;
- a hand-built or rc.1-persisted AST.

Each round blocked one producer. The contract itself was never enforced.

**Proposal:** enforce the declared contract at the atom boundary. This is not classification:
the schema is the atom's own statement of what it accepts.
- For atoms whose inputs the VM resolves (`defineAtom`, embedder atoms), validate the resolved
  inputs against `inputSchema`, charged like guest validation. tosijs object schemas say
  `additionalProperties: false`, so a stray `args` is refused by the atom's own schema, and so is
  a missing required input. `s.any` accepts anything, because that is what it says.
- For core atoms (`resolveInputs: false`, whose step values are still expression nodes), check
  KEYS only: required keys present, no undeclared keys. Control keys (`op`, `result`,
  `resultConst`, …) are excluded.
- Transpiler: emit no `args` for a zero-argument named call (B1), and refuse a spread in an
  atom-call literal (B2).
- **Risk:** core atoms whose steps carry keys outside their schemas. Measure that across the
  suite before committing to the core-atom half.

## Decision and plan (Tonio, 2026-10-03)

Tonio chose to enforce the declared contract, then sharpened WHERE:

> "The VM's job is to be correct and safe. AJS's job is to be friendly (help debug bad code) and
> produce correct code. The VM has zero requirement to be friendly." "It's not the VM's job to say
> you wrote code with bad parameters. It's AJS's job to prevent you from writing code with bad
> parameters."

**Plan (round 18):**
- **VM:** no parameter checking. An AST is run as written, and an atom given missing inputs is a
  defect in its producer, not a safety question. B3 is dispositioned on that basis: a hand-built
  or third-party AST is its producer's responsibility, and the AST-producer docs say so.
- **Transpiler: check every atom call against the atom's declared contract** (property names,
  `additionalProperties: false`, `required`), with an instructive `TranspileError`:
  - an unknown key, with the keys it takes;
  - a missing required input.
  - Core atoms use a dependency-free table, `src/vm/core-atom-inputs.ts`, held to `coreAtoms` by
    a test. Embedder atoms use the existing `transpile(src, { atoms })` option, whose atoms carry
    `inputSchema`.
- Already done: positional atom calls refused; no `args` for `foo()`; a spread refused.
- The four playground examples passed `httpFetch({ cache })`, which `httpFetch` never read. Found
  by the (now removed) VM check; fixed.
- **Grokkability** (Tonio): measure REPAIR as well. Can a small model fix a broken program from
  our error messages alone? Card.

## Blockers

### B1 (major, confirmed, correctness): a world-sized response ends the run uncatchably in a middle size band. `src/vm/runtime.ts:4914` (`ingressValue`), with `readBounded` at about line 6799
- **Reproduced on HEAD.** A transpiled AJS agent runs `try { httpFetch({url}) } catch { return {caught:true} }`.
  - 1 MB body: `{ok:true}`.
  - 3 MB body: **the run halts** with "Capability boundary rejected the return of 'httpFetch': the value exceeds the 4194304-byte membrane budget".
  - 5 MB body: `{caught:true}`.
- **Cause:** `readBounded` caps *raw* bytes at `membraneMaxBytes`. After decoding, the membrane bills a string at `length*2`, a parsed JSON array at roughly 8 B per 2 raw bytes, and a dataUrl after base64 expansion. So bodies from about cap/2 up to cap get past the atom and are refused at ingress. Round 35 turned that refusal into `haltRun`; at `d37176e` it was catchable.
- **Impact:** a remote server or model can kill an agent outright, and the agent has no defence. This contradicts DOCS-AJS: halts are for "bugs in the program rather than failures of the world… a fetch that fails… [is] caught by try/catch".
- **Fix:** keep the ingress halt for broken host contracts (data that isn't plain data, cross-realm values). Make an oversized *world* payload an ordinary Error inside the atom: bound the decoded size (text at cap/2, account for base64 expansion, estimate or cap the parsed JSON size) and do the same for battery/LLM atoms. Add rows for 1, 3 and 5 MB bodies to `membrane-halt.test.ts` (transpiled), asserting that 3 MB behaves like 5 MB. Then take the cycle stop above: decide in one place which ingress refusals are contract breaks and which are world failures, rather than patching httpFetch alone.
- **Re-review scope:** correctness and security over the remediation diff.

### B2 (major, confirmed, security): a capability's thrown value bypasses the membrane. `src/vm/runtime.ts:5351` (exec catch), with `AgentError` at about line 114 and the `try` bind at about line 5655
- **Reproduced on HEAD.** An io atom throws `{ message: obj }`, where `obj` shares an array with host state and has a getter. Guest code: `try { boom({}) } catch (e) { e.list.push(99); out = e.x }`.
  - The host's `shared.list` became `[1,2,3,99]`.
  - The host getter ran (its counter went 0 to 1, and the run returned `"ran host getter"`).
  - The value also skips the `membraneMaxBytes` limit.
- **Cause:** `error = e.message || String(e)` leads to `new AgentError(error, op, e)` (the message is not coerced), which leads to `{[param]: ctx.error.message}` bound with no crossing. This is latent from before the diff. But round 35's headline claim, "the boundary is a closed set of crossings", and its guard `membrane-doors.test.ts` only enumerate callers of `membraneValue`, so this route is invisible and the guard reports the boundary closed.
- **Fix:**
  - Reduce a non-`AgentError` throw to a string: `typeof e?.message === 'string' ? e.message : String(e)`, capped at the budget.
  - Have the `AgentError` constructor apply `String()` to `message` as a backstop.
  - Do not keep a host `cause` anywhere a guest bind can reach it.
  - Add rows to `guest-values.test.ts` / `membrane-halt.test.ts` for: a `{message: objWithGetter}` throw, a `{message: hugeString}` throw, and an Error subclass with a non-string message.
  - Widen `membrane-doors.test.ts`, or its header, so it names the throw path as a crossing.
- **Re-review scope:** security and correctness over the exec catch, `AgentError` and the try bind, plus a check that the doors test, or its documented blind spots, covers the throw route.

## Round 36 — plan (written before any code, per the cycle STOP)

**Tonio's decision (2026-10-04): inbound refusals split by WHO got it wrong.**
- A host contract break ends the run: the capability returned non-data (a function, a getter, a
  class instance, a cycle or nesting past the depth limit).
- Size and protocol drift are the world's, and are ordinary catchable failures: a return over
  `membraneMaxBytes`, and an IO atom's output that does not match its declared schema.
- Outbound refusals still all end the run: the guest built the value.

**The underlying problem.** Round 35 applied one rule ("halt") to a boundary that has two parties
on its far side: the host's code and the world it talks to. B1 is the world being treated as the
host. B2 is a crossing that is not a walk (a thrown value), invisible to a guard that only looks
for walks.

1. **Classify a refusal by KIND, in the type, never by its message.** A failed `MembraneResult`
   REQUIRES `kind: 'size' | 'shape'`: `overBudget` is `'size'`, and every other refusal is
   `'shape'`. Like `walked`, a refusal path that does not say its kind does not compile. A
   regex on the reason was round 31's defect, so it is ruled out here.
2. **One billing rule for every inbound walk, accepted or refused:** the walked bytes are charged
   as fuel at the allocation rate (not as transient heap: the copy IS the value that will be
   bound, and the bind does the heap accounting). Non-finite fuel is guarded, and the meter is
   floored at zero. A catch-and-retry loop on an oversized or mismatched return now pays fuel in
   proportion to the walk, every time. Accepted returns were unbilled for their walk before;
   that is the same amplifier for a mismatch loop.
3. **`ingressValue`:**
   - a `'shape'` refusal ends the run (`haltRun`);
   - a `'size'` refusal is a catchable `AgentError`;
   - an output-schema mismatch is a catchable `AgentError`.
   - Rows (transpiled, through `httpFetch` against a local server): 1, 3 and 5MB bodies in
     `try` are all caught (3MB behaves like 5MB); a returned function or getter still ends the
     run; the catch-and-retry loop on an oversized return pays at least c × walk per retry and
     ends by fuel; a mismatched output is caught.
4. **B2, a thrown value:** `exec` reduces a non-`AgentError` throw to a STRING (`message` when it is
   a string, else `String(e)` inside a guard), capped. The `AgentError` constructor applies
   `String()` as a backstop.
   - The catch bind already exposes only `message` and `op`; the host `cause` stays on the
     host-facing error.
   - `membrane-doors.test.ts` names the throw path as a crossing, and a parse checks that `exec`'s
     catch reduces before constructing.
   - Rows: `{ message: objWithGetter }` (getter never runs, host array never mutated), a huge
     string message (capped), and an Error with a non-string message.
5. **Minors:** pin the top-level string's bill and message against a nested one, and update the
   docs (CHANGELOG, DOCS-AJS, CLAUDE.md, vm-budgets) for the split.

Re-review scope: correctness + security over the round-36 diff.

## Round 36 — implemented (2026-10-04)

- **The refusal kind is in the type.** A failed `MembraneResult` REQUIRES `kind: 'size' | 'shape'`
  (`overBudget` is `'size'`; every other refusal, nine sites, is `'shape'`). No message is parsed.
- **`ingressValue` splits by who got it wrong** (Tonio):
  - `'shape'` (non-data from the host) ends the run;
  - `'size'` is a catchable `AgentError`;
  - an output-schema mismatch is a catchable `AgentError`.
  - **Every inbound walk is billed**, accepted or refused, as fuel at the allocation rate (not
    transient heap: the copy is the value the bind accounts for). Accepted top-level strings now
    report their bytes, so a large string return is billed.
  - Rows: 1M/3M/5M-char returns in try all behave as world failures (the 3M case halted in round
    35); a catch-and-retry loop on an oversized return pays about 200 fuel per walk and ends by
    fuel within 6 calls; a returned function or getter still ends the run (the getter never
    runs); an output mismatch is caught; an accepted 2MB walk bills over 90 fuel.
- **B2, thrown values:** `exec`'s catch reduces a caught value with `reduceThrown` (its `message`
  if that is a string, else `String(value)`, capped at 8KB, never throws). `AgentError` coerces as
  a backstop.
  - `membrane-doors.test.ts` now also PARSES every catch clause that builds an `AgentError` from
    the caught value and requires `reduceThrown`. That found two more sites (the VM's own regex
    and TypeError conversions), now routed through it.
  - The checker's first version matched the parameter name as a SUBSTRING (`e`) and flagged
    `vm.ts`; it now matches the identifier.
  - Rows: the review's `{ message: objWithGetter }` (no host mutation, getter never runs), a 1MB
    message (capped), and a non-string Error message.
- **Minor:** a top-level string refusal has the same kind, reason and bill as a nested one (row).
- **Mutants caught:** thrown value not reduced, size halting (round 35), shape catchable, inbound
  walk unbilled, output mismatch halting.
- **Docs:** DOCS-AJS, CHANGELOG and CLAUDE.md state the split; the httpFetch decoded-size band
  disappears with it (every size refusal is the same catchable failure).
- **Lanes:** lint, typecheck, make, test:fast (7352), dogfood, and the full suite without the live
  LLM (7350, 0 fail).

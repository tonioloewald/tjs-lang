## Blockers — fix before tagging

### B1. `trackHeapWrite` identity fast path lets in-place mutation bypass `maxHeapBytes` entirely
`src/vm/runtime.ts:1868` — **correctness / security · REGRESSION in this diff**

`push` (`runtime.ts:3090`) mutates the array in place and returns **the same reference**; the `exec` wrapper writes that result through `setStateVar` → `trackHeapWrite`, which now short-circuits on `prevEntry.ref === value && typeof value === 'object'` and returns `true` without re-measuring. The ledger freezes the array at its first-bind size forever while it grows unbounded.

Verified: an accumulate loop with genuinely-allocated values **survived the default 64MB ceiling while retaining 105.5MB RSS** (measured with `Bun.gc(true)` on both sides). Proof the bytes are live: appending `varSet copy = list` (a fresh key, which cannot hit the fast path) immediately raises `Heap limit exceeded`. At `v0.13.0-beta.1` `trackHeapWrite` re-measured unconditionally, so this accounted correctly.

`maxHeapBytes` is documented in CLAUDE.md as *the space budget and the OOM guard* for untrusted agent code, and the single most ordinary agent program shape evades it.

**A plain revert is wrong.** The fast path's own comment documents the real quadratic it fixed (500 rebinds of a 300k-element array = 28.8s for 50.2 fuel). Preserve it for genuinely-unchanged values and invalidate on mutation: have `push` drop/refresh the ledger entry for its operand, or store a cheap change-witness (`length`) alongside `{size, ref}`. Pin the push-in-a-loop case in `src/vm/heap-scope.test.ts`.

### B2. `bun run make` fails at HEAD — `tjs-batteries` bundle no longer builds
`scripts/build.ts:62` — **build / release integrity**

On a pristine `git archive HEAD` tree: `✘ Could not resolve "node:path" — src/batteries/audit.ts:46` → `✖ Build failed: 1 bundle(s) did not build — tjs-batteries`. Succeeds at `v0.13.0-beta.1`. Commit `713e27c` added `cacheDir()` with a **bare** `await import('node:path')` (the two pre-existing ones are inside `try{}`, where esbuild downgrades to a warning), while the `tjs-batteries` target externalizes only `['tosijs-schema', 'node:readline']`.

Consequences, all verified:
- **GitHub Actions run 31946562079 (HEAD, 49216a4) is RED** — `Build` fails, `Test (fast lane)` fails with `tjs-batteries.js: claimed in README but not present in dist/`.
- `make` starts with `rm -rf dist`, so a publish after a real build has **no** `dist/tjs-batteries.js` → `import 'tjs-lang/batteries'` hard-fails for every non-Bun consumer.
- Publishing from the current tree instead ships the **pre-fix** bundle: `npm pack --dry-run` includes a 9.8kB `dist/tjs-batteries.js` still containing `process.cwd()` and zero occurrences of `probeVersion` — i.e. two CHANGELOG "Fixed" entries (lines 204–209) are **false for the published artifact**.

Fix verified: adding `'node:path'` (and `'node:fs/promises'`) to that target's `external` builds it at 10.0 KB, matching the README's row, with `XDG_CACHE_HOME` and `probeVersion` present. Then re-run `bun run make` and `git diff --exit-code` over the generated set.

*(One sub-claim from the report is corrected: the CI "Generated artifacts are current" step does run and pass — every step carries `if: always()` and the artifacts it checks are produced before the failing esbuild step. Its green is still meaningful.)*

### B3. A literal-union parameter plus a `:` return annotation hard-fails `tjs check` / `tjs()`
`src/lang/emitters/js-tests.ts:590` — **dx**

Reproduced during triage on a one-line file:

```
$ echo "function pick(x: 'yes' | 'no'): '' { return x }" > u.tjs
$ tjs check u.tjs
✗ u.tjs
  Transpile-time test failures:
  Function signature example is inconsistent:
    Expected "" at 'pick', got { expected: "\"yes\" | \"no\"", actual: "number" }   (exit 1)
```

`extractSignatureTestInfos` builds arguments with `new Function(\`return ${p}\`)()` over the raw annotation text — and `new Function("return 'yes' | 'no'")()` is JavaScript **bitwise OR**, evaluating to `0`. Numeric unions are equally wrong (`1 | 2` → `3`).

Blast radius is wider than the CLI: plain `tjs(source)` **throws** (runTests defaults to throw), so the playground, `tjs emit`, `tjs test` and any programmatic consumer fail. Every return-annotation form fails except `:!`. Literal unions are announced under **Added** in this release and documented in `CLAUDE-TJS-SYNTAX.md` §Literal Unions — where **every example omits a return annotation**, which is exactly why nothing caught it.

*(The bitwise-OR bug itself predates the release — it reproduces on 0.12.0 — but this release makes the broken combination newly reachable and newly recommended.)*

Fix: consume the parsed `TypeDescriptor` (which already carries `kind: 'literal-union'`, `values`, `example: 'yes'`) instead of re-evaluating source. **Defensive floor:** per `PRINCIPLES.md`, treat an argument that fails its own parameter's check as *inconclusive*, not a failure — that rule alone would have downgraded this to a non-event.

### B4. Declared `Type` with example + predicate rebuilds its JSON Schema on every `.check()`
`src/lang/parser-transforms.ts:2431` — **efficiency**

The schema gate is emitted **inside** the per-call arrow:
`globalThis.__tjs.validate(v, (globalThis.__tjs.inferOpen ?? globalThis.__tjs.infer)(0))`.
The IIFE hoists the *guard*, not the schema. Measured (200k warm iters, real runtime): **3232 ns/call** vs 19.8 ns for example-only, 6.8 ns for a plain `n: 0` — ~97% of the cost is re-deriving a compile-time constant (`inferOpen` = 3355 ns: `structuredClone` + full recursive walk). This release also switched the emission from `infer` to the 16x-more-expensive `inferOpen`.

The comment directly above the emission asserts the opposite of what the code does ("constructed once via an IIFE, not per call"), and the *correct* pattern already exists in this release — CHANGELOG line 124 says the sibling type-argument path is "built once rather than per call".

This is emitted `.js`: every consumer bakes the per-call cost into their shipped output, on the release's headline "annotations now check" feature. Hoist into the existing IIFE with lazy memoization (so a late `installRuntime()` still works), then fix the comment. *Severity is arguable at major — kept as a blocker because the fix is small and low-risk and the cost ships into consumers' artifacts.*

## Confirmed majors — fix now or file (all adversarially verified)

1. **`findSignatureReturn` name-searches the whole file** — `src/lang/emitters/js.ts:761`. An unrelated earlier `const NAME = (…)` steals the anchor; the function silently loses its `returns` metadata, `:?` return wrapper and safety marker. `tjs check` reports the file clean. Regression from the old `function\s+NAME\s*\(`-only anchor. Also affects non-first declarators (`const a = …, b = …`). *Fix: start the balanced-paren scan from the acorn node, not a name regex.*
2. **`callLocal` re-walks every argument in full on every call** — `src/vm/runtime.ts:2878`. Fresh per-call `heapPerKey` defeats the identity fast path. Measured 400 calls with an unchanged 20k-element arg: **2.5 ms / 120 fuel (0.12.0 and beta.1) → 1358–2659 ms / 24,181 fuel (HEAD)**, ~200x fuel. Landed *inside this window* (70ab7fd + 2dd3e2c + ef500ec). Same shape in `agentRun`'s two child contexts (`:3636`, `:3666`). Hosts that sized `fuel` on 0.12.0 now exhaust it after ~0.5% of the calls they used to afford.
3. **`reduce` re-walks the accumulator every iteration → O(n²)** — `src/vm/runtime.ts:3036`. Fuel at N=1000→16000: `231→3681` (0.12.0, linear) vs `734→131721` (HEAD, quadratic). Excess fuel matches `sum(1..N)` to within 0.03% — proven, not inferred. `map`/`filter`/`find` are fine (the `alias` fix works); `reduce` with a growing accumulator is the one loop left paying it. `cost-invariant.test.ts:353` still lists `reduce` as SIZE_INSENSITIVE — a promise the code no longer keeps.
4. **`dts.ts:splitParams` is a third, still-literal-blind copy → syntactically invalid `.d.ts`** — `src/lang/emitters/dts.ts:502`. `constructor(sep: ',', pad: 0)` emits `constructor(sep: string, ': any, pad: number);`. `tsc --noEmit` on the output: **TS1002 "Unterminated string literal"** ×2 plus TS1003/TS1005/TS1138 — a hard failure for every TS consumer. Methods are corrupted too, not just constructors. `js-tests.ts:splitParams` was moved onto `maskLiterals` this release and its comment names `parser-params.ts` as *the* sibling; this third member was never counted. This release *newly promises* tsc-compilability (`dts-compiles.test.ts`, commit 8ec3b53), and none of its 12 cases uses a comma inside a class param example.
5. **`validateNoNew` re-derives its own `new X` regex** — `src/lang/parser-transforms.ts:4721`. `tjs convert` emits `new Shape.Circle(2)` verbatim (correctly — `dropRedundantNew` exempts member access), then `tjs check` rejects it with a remedy that is **runtime-fatal** if followed (`Shape.Circle(…)` → "Cannot call a class constructor without |new|") and names the wrong class. Also re-introduces a quadratic: 747ms vs 6ms on 160 classes (~125x), on a browser-hot path. `declared-classes.test.ts`'s CASES array omits the member-access form.
6. **`unwrapBoxedVM` is a fourth hand-written copy, in the security-critical VM** — `src/vm/runtime.ts:22`. `src/unwrap-boxed.ts` was created **this release** as "ONE definition"; commit `b9c3472` deduped `src/lang/runtime.ts` and `js.ts` and left the VM behind. It is byte-identical, imports nothing from the module, and is not in `unwrap-boxed.test.ts`'s differential corpus. No test under `src/vm/` uses a lying `valueOf`, a `getPrototypeOf` Proxy or a `Symbol.hasInstance` trap — reverting the hardening would be caught by nothing. There is no bundle reason (`runtime.ts` already imports the sibling leaves `../redos`, `../forbidden-keys`). *Bonus: `__oneOf` (js.ts:1613) is a further un-deduped copy and is **not** fail-soft.*
7. **`src/cli/playground.ts` has 0% coverage; the hardlink-corruption fix shipped with no test** — commit `b92a2f3` touched only `playground.ts` and a review doc ("Verified end to end" = manual). The module is *structurally* untestable: `defaultOutDir` is unexported and line 312 is a top-level `main()`, so importing it starts a build and a `Bun.serve`. The sibling fix in the same session (`port.ts`, 6596ae3) got a 258-line test. Violates CLAUDE.md's "Always create a reproduction test case before fixing a bug". Latent bug a test would have caught: `rootDir.includes('node_modules')` misclassifies any repo checked out under a path containing `node_modules`.
8. **`literal-union` is dropped from every downstream artifact** — `src/lang/emitters/js.ts` `serializeType()` copies `items`/`shape`/`members` but not `values`. Verified: `__tjs` emits `{"kind":"literal-union"}` with no members; `generateDTS` emits `x: any` (the one TJS construct with a *lossless* TS mapping); `functionMetaToJSONSchema` emits `properties: {x: {}}` — accept-anything. `json-schema.ts` has no `literal-union` case either. A TS consumer calls `pick(42)`, compiles clean, gets a MonadicError.
9. **`tjs-playground --force` can SIGKILL a stranger's server** — `src/cli/port.ts:55`. `OUR_SERVERS = /tjs-playground|cli\/playground|bin\/dev\.ts/` is unanchored against full argv.

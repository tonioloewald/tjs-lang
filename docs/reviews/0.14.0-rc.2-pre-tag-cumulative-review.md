## Blockers

### B1. A path-relative URL skips the configured allowlist and the scheme check on the host-fetch path (confirmed, security + correctness)
- **Where:** `src/vm/runtime.ts` ~6292–6316, `admitFetchUrl`, called at ~6425 as `admitFetchUrl(url, allowedDomains, !ctx.capabilities.fetch)`.
- **Defect:** when `new URL(url)` throws and `destinationRequired` is false, the function resolves the URL against `RELATIVE_BASE` (`https://relative.invalid/`). If the resolved host is `relative.invalid`, it returns with a bare `return`, before either the http/https scheme check or the `allowedDomains` check runs.
- **Reproduced:** two independent lenses reproduced it. Setup: `allowedFetchDomains: ['a.test']`, or Eval/SafeFunction `fetchPolicy: { domains: ['api.example.com'] }`, plus a recording host fetch. These URLs all reached the host fetch unchanged: `/admin/secrets`, `admin`, `?x=1`, `../x`, `#frag`, `%2F%2Fevil.com/x`, `/%5Cevil.com`, `//relative.invalid/x`.
- **Impact:** in a browser, the host's fetch resolves the URL against the page origin. That gives same-origin reads with ambient cookies, which can then be exfiltrated through an allowed domain. On Electron, Tauri, Capacitor or an extension page the base scheme is `file:`, a custom scheme or `chrome-extension:`, which breaks the CHANGELOG promise of "http/https only, every path, always". It also contradicts round 26's "a configured allowlist never silently stops applying" and the eval.ts advice to "check the hostname, **or** set `fetchPolicy.domains`".
- **Tests:** none cover a relative URL combined with an allowlist. Line ~851 tests a relative URL with no allowlist; line ~857 covers only the protocol-relative `//evil.example`.
- **Fix:** when `allowedDomains` is set, refuse any URL that does not parse as absolute, with an error saying an allowlist requires absolute URLs. A host that wants same-origin access can opt in explicitly, for example with a `'self'` entry. With no allowlist, keep "host owns the destination", but document that the scheme check can't see what a relative URL resolves to.
- **New test rows** in `fetch-admission.test.ts`: relative URL × {`allowedFetchDomains`, Eval `fetchPolicy.domains`, SafeFunction `fetchPolicy.domains`}, each asserting the host fetch is called 0 times. Mutation-check every row by restoring the early return. Then correct the CHANGELOG and the `admitFetchUrl` comment.
- **Re-review scope:** security + correctness over `admitFetchUrl` and the host-fetch branch, cumulative over all httpFetch admission since rc.1, as re-reviews 5 and 6 asked.
- Per the STOP above, find the underlying problem before patching. This is the third consecutive pre-tag round where admission held on one fetch path and not another.

## Majors (fix before tag unless explicitly deferred)
- **M1. Alias-in-loop rebind is quadratic in fuel and time** (efficiency, confirmed). `src/vm/runtime.ts` `trackHeapWrite` (~4130); the finding anchors at ~3599. Binding under a NEW name (a per-iteration `let p = o`) has no `prevEntry`, so each bind runs a full `estimateBytes` walk, and that walk is charged. Shape: `o.items.push({k:i}); let p = o`. At N=4000, HEAD takes 985 ms and 18.5k fuel; rc.1 took 8 ms and 5.8k fuel. Programs that fit their budget at rc.1 can now run out of fuel.
  - Fix: make a rebind of an already-measured reference O(1). For example, key the witness and ledger on the value with a `WeakMap<object,{witness,bytes}>`.
  - Add a scaling row (fuel(2N)/fuel(N) ≈ 2) to cost-invariant or vm-budgets.
  - If the cost is accepted instead, document it in `docs/vm-budgets.md` and the CHANGELOG.
  - Re-review: correctness + security (heap soundness).
- **M2. llmVision forwards guest image URLs to the LLM backend with no admission** (security, plausible). `src/vm/atoms/batteries.ts:231-270` passes them to `buildUserMessage` (`src/batteries/llm.ts:31-50`). Backends built on vLLM or mlx-vlm (the documented MLX direction) fetch http(s) `image_url` server-side, so a guest can get a GET to `169.254.169.254` and the like that never passes through the allowlist, method/header or private-range gates. The re-review-6 item asking for an in-scope/out-of-scope decision on this is still open.
  - Fix: admit `data:image/…;base64,` by default. Admit http(s) only through `admitFetchUrl` with the run's `allowedFetchDomains`, and refuse it when no allowlist is set.
  - Add a test row with a recording stub `llmBattery`.
- **M3. `publish.yml` has drifted from the shared template** (blast-radius, confirmed). The copy was synced at practices `1ee82fd`; the template has since gained `890c0fc`. The copy is missing:
  - (a) the `INTEGRITY != PACKED_INTEGRITY` refusal;
  - (b) the exact npm pin (it uses a floating `npm@^11.15.0` in the job that holds the credential);
  - (c) staged-bytes-derived name, version and dist_tag;
  - (d) the tarball upload right after Pack. The copy uploads it after smoke, install and doctor, so later steps can alter it.
  - Fix: re-copy the template at practices HEAD before tagging. Re-review: Tier 0 + security over the workflow diff.
- **M4. `deploy:site` doesn't build the commit it names** (blast-radius, confirmed). In `bin/deploy-site.ts:49`, the worktree's `node_modules` is a symlink to the repo's, and its `tjs-lang -> ..` self-link points back into the MAIN checkout. As a result:
  - `tjs-lang/browser`, `/browser/from-ts` and `/editors/codemirror` all resolve to the main checkout's gitignored `dist/` and `editors/`;
  - if those are missing, the build falls back to the CDN at tosijs-ui's pinned version;
  - so the public site, stamped "built from `<sha>`", serves a transpiler from a different tree.
  - Fix: make `tjs-lang` resolve to the tree itself (a real `node_modules` dir with per-entry links, `tjs-lang` → tree), or build `dist/` in the tree. Then assert that the resolved path starts with the tree path.
  - Re-review: correctness + blast-radius over deploy-site.

## Blockers

1. **[security + correctness, confirmed] The X- branch of `admitHeaders` is still an open denylist.** `src/vm/runtime.ts:6203-6212`
   - **What the code does:** `X_HEADER_REFUSED = /^x-(?:forwarded|original|rewrite|host|real-ip|http-|method|client-ip|agent-depth|proxy|cluster-client-ip)/`. Any `x-*` name it does not match is admitted.
   - **Confirmed admitted with bun/node:**
     - Routing: `x-envoy-original-dst-host`, `x-envoy-internal`, `x-envoy-original-path`, `x-upstream-host`, `x-backend-host`, `x-override-url`
     - Identity: `x-originating-ip`, `x-true-client-ip`, `x-remote-addr`, `x-remote-ip`, `x-azure-clientip`
     - Scheme: `x-scheme`, `x-url-scheme`
   - **Why it matters:** behind Envoy with an ORIGINAL_DST cluster and `use_http_header`, `x-envoy-original-dst-host` lets a guest route past the hostname allowlist. That is the same class as the guest-`Host` defect that started this series of fixes.
   - **Why it contradicts the round's own fix:** the round-23 comment says "every proxy invents another routing header, so 'refuse the routing ones' never closes". The X- branch is exactly that shape.
   - **Documentation is wrong:** CHANGELOG lines 139-143 say "Anything else is refused", which is false.
   - **Fix direction (the structural one):** admit X- names by a positive list (X-API-Key, X-Api-*, X-Request-Id, X-Correlation-Id, X-Requested-With, …). Optionally let the host widen the list per run, with a closed default. Patching the regex again is the non-converging option the STOP line warns against.
   - **Required alongside the fix:**
     - Refused rows for every name listed above.
     - A mutation check on the rule.
     - Corrected CHANGELOG, `guides/patterns.md` and DOCS-AJS.
   - **Re-review scope:** security plus correctness over admitHeaders and its rows.

## Plan (round 24, filed before acting)

**Underlying problem:** round 23 implemented "allowlist plus non-routing X- names" with a DENYLIST
inside the allowlist, the open-ended shape Tonio's decision was meant to close. A closed default
with host widening is the structural version.

- **Headers are a closed list,** X- names included: the common API headers, plus `x-api-key`,
  `x-request-id`, `x-correlation-id` and `x-requested-with`. A host widens it per run with
  `context.allowedRequestHeaders` (exact names, case-insensitive), as it does with
  `allowedFetchDomains`. `x-agent-depth` stays refused even if a host lists it. The regex is
  deleted.
- **The allowlists (headers, methods) bind the BUILT-IN client only.** A host's own
  `capabilities.fetch` is the documented escape hatch and receives what the guest sent, except
  that a guest `x-agent-depth` in any case is still refused, because the VM owns that header.
- **Redirect classification:** only `opaqueredirect`, or 301/302/303/307/308 with a `Location`,
  counts as a redirect. 304, 300 and others return normally. `location` is resolved to an
  absolute URL.
- The method is sent upper-cased; there is a test that `credentials: 'omit'` is passed; the
  header comment in the test file is corrected.
- **Rows** for every name the review found (routing, identity and scheme headers, as refused), a
  host-widened row, near-miss names, a custom-fetch row, and a 304 row. Mutation-checked.

**Correction to the round-23 notes:** the claim that rows existed for `X-Original-Host`, `X-Host`,
`X-Real-IP`, `True-Client-IP`, `X-Forwarded`, `Cookie` and `Origin` was FALSE. The scripted edit
that added them did not match (Prettier had reflowed the array) and was not checked. From round
24, every scripted edit asserts its match.

## Blockers

### B-1: A named predicate passed to a declared Generic rejects every value *(verified)*
`src/lang/parser-transforms.ts:4104` (markGenericInstantiations) and the inline `__k` in `src/lang/emitters/js.ts:2103`.

`const B = Box(isEven)` now emits `Box(__tjs_rt.__k('ref', undefined, () => isEven))`. The `ref` check is `__match(x, a())`, and `__match` has no case for a plain function, so it falls through to `v === ex`, which is always false.

- `B.check({value:2})` was true at base and is false at HEAD. This happens standalone and with the runtime installed.
- The inline form `Box(v => …)` still works.
- This contradicts the property stated in `type-argument.test.ts:10`.

**Fix:** either unwrap `ref` in the Generic stub's `c`, or make `__match`/the ref check call a function-valued referent. Alternatively, do not mark bare identifiers in Generic call arguments. Add tests for `Box(namedPredicate)`, `Box(0.0)` and `Box(string)`; `markGenericInstantiations` currently has no test at all.

### B-2: A recursive `ref` check both hangs and fails open, because it relies on stack overflow *(verified; efficiency blocker plus security major, merged)*
`src/lang/emitters/js.ts:2103`, where the check is `m.check=x=>{try{return __match(x,a())}catch(e){return true}}`. There is no visited set and no depth bound.

- **Hang (efficiency):** on cyclic data, each sibling branch recurses to the stack limit again, so the cost is about b^depth.
  - `Type Node = { left: Node|null, right: Node|null, v: 0 }` with `n.left = n.right = n`: `check` does not return (killed after more than 20–40s).
  - One back-pointer costs 2.7–9.7ms per call.
  - It is reachable from plain TS: `interface TreeNode { parent: TreeNode|null; children: TreeNode[] }` through fromTS plus `TjsStrict` hangs on a root with two children.
  - At base this was unreachable, because fromTS emitted `null` for self-references and TjsStrict did not validate.
- **Fail-open (security):** the deepest `ref` frame catches the RangeError and reports true.
  - With `Type Node = { id: 0, child: Node | undefined }`, a 20,000-deep chain whose innermost node is `{id:'NOT A NUMBER'}` gives `Node.check(deep) === true` and `take(deep) === 'ok'`.
  - The same happens after a `JSON.parse` round trip, so a hostile request body of a few tens of KB passes validation.
  - The only nearby test (`example-kinds.test.ts:193`) asserts `not.toThrow()`, so it would pass whether the answer is right or wrong.

**Fix:** make the check coinductive. Keep an in-progress set of (value, marker) pairs for each top-level check, and treat a revisited pair as satisfied. That is O(nodes × types), and every node is still checked. On a RangeError, or past a depth bound, **fail closed** (return false) and record the event through `__tjs.record` (`source:'type'`, severity warning). Degrade open only on a genuine TDZ ReferenceError; see m-2.

Tests to add:
- a self-cycle and a two-branch cycle, with a time bound
- the fromTS TreeNode + TjsStrict parent-pointer case
- a deep acyclic JSON payload with an invalid leaf, which must be **rejected**
- a cyclic value with an invalid member, which must be rejected

**Re-review scope:** correctness, efficiency and security over the `__k`/`__match` remediation diff, plus the type-identity and differential tests, because the inline stub is the shipped semantics.

## Majors (verified; fix before publish)

### M-1: The splicing in markGenericInstantiations/markExampleKinds breaks legal JS *(verified)*
`src/lang/parser-transforms.ts:4124` and markExampleKinds. This violates TJS ⊇ JS, and in one case it silently changes behaviour.

- (a) `part.replace(arg, marked)` interprets `$` patterns in the replacement.
  - `Box({ s: '$&' })` is a SyntaxError.
  - `Box($$a)` emits `() => $a`, a different binding. The ref's try/catch then swallows the resulting error, so the argument is silently unchecked.
- (b) Shorthand properties (`Type T = { x }`, `Box({ value })`) splice to `{ __tjs_rt.__k(...) }`, which is a SyntaxError.
- (c) The regex `(?<![\w$.])Box\s*\(` matches method definitions, so `class C { Box(y){} }` and `{ Box(y){} }` stop transpiling.
- (d) It is not scope-aware: `function f(Box = v => v) { return Box(q) }` returns a marker object instead of 7.
- No literal-blindness row was added for this new source-rewriting pass.

**Fix:**
- Splice by offset with `slice`, never with a replacement string.
- For shorthand properties (`p.shorthand`), emit `key: marker`.
- Find call sites from an acorn parse, keeping only CallExpressions whose callee resolves to the module-scope Generic.
- Add `literal-blindness.test.ts` rows for `$&`, `$$ident`, shorthand and a same-named method.

### M-2: The schema path and the matcher disagree *(verified)*
`src/lang/emitters/js.ts:2104` (`__kjs`). In `__kjs`, `undef` and `pred` (literal unions) fall through to `{}`.

- `Type T = { mode: 'on'|'off', b: ''|undefined }` gives `T.toJSONSchema()` with `mode: {}` (the enum is lost) and `b: {anyOf:[{type:'string'},{}]}`, which accepts anything.
- With the runtime installed, adding a `predicate(x){return true}` makes the type *more* permissive: `V.check({b:42}) === true`, while `__match` rejects the same value.
- fromTS now emits `X | undefined` for every optional interface member. So every converted interface publishes its optional members as unconstrained, and `toJSONSchema` and `functionMetaToJSONSchema` are consumer-facing artifacts.

**Fix:**
- Drop `undef` from `anyOf` (the key is already not required).
- Store literal values on the `pred` marker and emit `{enum: values}`.
- Add a differential test over every `example-kinds.test.ts` CASES row, asserting that the `__match` verdict equals the validate-path verdict and that the schema is at least as strict.
- Record any remaining gap in `type-identity.test.ts` KNOWN_DISAGREEMENTS, with a reason.

### M-3: TjsStrict now validates, and it rejects valid TypeScript because fromTS mis-types common shapes *(verified)*
`src/lang/parser.ts:362` (`if (!safetyExplicit) moduleSafety = undefined`). The fromTS gaps below were harmless while TjsStrict did not validate.

- `f(o: { a?: number; b: string })` loses the `?`, so `f({b:'x'})` returns "Expected number for f.o.a".
- `f<T>(x: T[])` becomes `[null]`, so `f(['a'])` is rejected.
- `f(x: object)` becomes `{}`, so `f([1])` is rejected.

These errors are *returned*, not thrown, so a caller can silently ignore them. TjsStrict is the documented TS ladder step (`TJS-FOR-TS.md:580,758`).

**Fix:**
- Emit `T | undefined` (or the `?` marker) for optional members of inline object types in annotation position.
- Emit `any` for unconstrained generic array items.
- Emit an object predicate that accepts arrays for TS `object`.
- Add `tjsstrict-safety.test.ts` rows asserting that valid calls are **not** rejected.
- As a last resort, document the over-rejection in the CHANGELOG.

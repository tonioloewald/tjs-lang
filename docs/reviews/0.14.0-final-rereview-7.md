## Blockers (release-blocking majors, all confirmed)

### M-1: the global ternaryColons memo is thrashed by nested distinct sub-sources, making the AJS colon pass quadratic again (security, **confirmed**)
- **Where:** `src/lang/expression-context.ts:78` (`if (ternaryMemo.size > 16) ternaryMemo.clear()`), called from `src/lang/parser-params.ts:~969` (`isTernaryColon(source, j)`).
- **Mechanism:** each recursion level passes a new substring. With more than 16 levels of nesting, the inner keys clear the outer source's entry, so every outer group pays maskLiterals plus the O(n) forward pass again. The total is O(groups × n). The strip-comments mask/scan caches (16/24 LRU) are thrashed the same way.
- **Measured (Eval, fuel 10, timeoutMs 1):** unit `'('×d + 'a' + '):0'×d + ','`.
  - d=17 is linear: 17 / 16 / 29 ms at 15 / 30 / 60 KB.
  - d=30 is quadratic: 133 / 477 / **1738 ms** at 15 / 30 / 60 KB.
  - Each run fails with a parse error, fuelUsed 10, so the whole cost is paid before fuel.
  - This is over admission.test.ts's own 1500ms bound, and contradicts the commit's claim that "every preprocess pass is LINEAR".
- **Fix:** compute `ternaryColons(source)` once per `transformParenExpressions` call and keep it in that call frame, as `parenMemo`/`classBodyMemo`/`classBracketMemo` already are. Remove the process-global map; that also ends retention of up to 17 guest sources of 64KB each across runs and tenants. Audit the other per-position callers into `maskLiterals`/`scanLiterals` for the same dependence on the memo not being thrashed. Add admission rows with more than 24 nested distinct levels (to exceed SCAN_CACHE_MAX as well) through every source entry. Re-run the fuzz with nested-distinct shapes.

### M-2: `vm.run` ignores a caller `options.signal` that is already aborted (security + correctness, **confirmed**; two findings merged)
- **Where:** `src/vm/vm.ts:~411–416`. The external signal is linked only through `addEventListener('abort', …)`, which never fires for a signal that is already aborted. Nothing reads `options.signal.aborted`. `ctx.signal` is the internal controller, which is never linked, so the new per-step check never trips and io atoms receive a live signal.
- **Measured:** with a pre-aborted `ac.signal`, an io atom `mark` gives `calls=['pre']`, `result {b:1}`, error undefined. A compute loop returns normally.
- **Why it blocks:** this diff fixed exactly this shape for `timeoutMs: 0` ("a spent deadline is spent NOW") and left the signal sibling open. A cancelled caller still gets outbound IO. The same applies to a nested agentRun given an already-aborted parent `ctx.signal` (runtime.ts:~3842).
- **Fix:** next to the `armed === 0` block, add `if (options.signal?.aborted) controller.abort()` without setting `timedOut`. Map a non-deadline abort to its own message instead of the current "Execution timeout after …ms" mislabel; `timedOut` can now tell the two apart. Add rows for a pre-aborted signal on a compute-only agent and on an io agent, asserting no step runs and no capability is called.

### M-3: the per-step abort check in `defineAtom`'s exec wrapper has no test that fails without it (correctness/coverage, **confirmed by mutation**)
- **Where:** `src/vm/runtime.ts:~2684–2687`.
- **Mechanism:** deleting the check leaves the suite green (382/382 targeted), because the `timeoutMs: 0` admission row asserts only the returned message, and the race produces that message by itself. The effect of the check is a side effect: without it, a first-step io atom runs once after the deadline (`calls=['zero']`). No test mentions "Execution aborted".
- **Fix:** add a `timeoutMs: 0` row with an io atom as the first step, asserting it was never invoked plus the timeout message. Add a helper or map body with a slow first atom and a recording second atom, asserting no call after the deadline. Also **move the abort check above the quota increment (2a)**. At present an aborted step consumes a `quotaUsed[op]` slot, and with a counter shared across nested runs each aborted run takes a phantom call.

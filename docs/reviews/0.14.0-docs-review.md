## Blocker

### B-1. Explicitly listed source docs are silently dropped from the corpus, and the playground's AJS Docs nav is now empty (verified)
`tjs-site.config.ts:61`, lenses docs and coverage.

**What happens:**
- `SOURCE_DOCS` lists individual `.ts` files, but tosijs-ui `extractDocs({ paths })` only scans `/*# */` blocks when given a directory. I reproduced it:
  - `extractDocs({paths:['src/vm/runtime.ts', …]})` returns `[]`.
  - `extractDocs({paths:['src/vm']})` returns runtime.ts.
- `demo/docs.json` went from 13 `src/` entries at 551c290 to 2 at HEAD. The two left are the `.tjs` files, which `bin/site.ts` finds with its own scan.
- Lost: `src/vm/runtime.ts` (the atom reference) and `src/store/{index,interface,memory,indexeddb}.ts`.

**Why it matters:**
- `demo/src/demo-nav.ts` `getAjsDocs()` matches only the filename `runtime.ts`, so the live Firebase playground's AJS Docs section renders empty after the next hosting deploy.
- That breaks decided constraint (e). The config's own comment says "src/vm/runtime.ts must stay".
- The `/*{"parent":"ajs.md"}*/` metadata added to those five files does nothing, so the new site loses the same pages.
- The guard can't see it. `src/doc-site-structure.test.ts` builds its corpus with the same `extractDocs(config.docPaths)` call, its apparatus check is only `> 80`, and `docs-fresh` compares only `.md` entries.

**Severity:** the verifiers split, one at blocker and one at major (the playground still loads). I keep it at blocker. It breaks an explicit maintainer constraint that the code's own comment names, it reaches the live site without any signal, and the fix is small.

**Fix:**
1. Extract the parent directories and filter to `SOURCE_DOCS`, or have `bin/site.ts` pull `/*# */` blocks from listed `.ts` files the way it already does for `.tjs`.
2. Add a guard, and confirm it goes red on the current tree first:
   - every `SOURCE_DOCS` entry yields at least one doc in the site corpus and in `demo/docs.json`;
   - every filename `demo-nav.ts` matches by name (`runtime.ts`, `CONTEXT.md`, `PLAN.md`, and the TJS/ASYNCJS/PATTERNS substrings) hits at least one visible entry.

**Re-review scope:** correctness and blast radius over the remediation diff, plus a re-diff of `demo/docs.json` against 551c290. The `src/` entries should be runtime.ts, the four store files and the two `.tjs` files. The test files and `rbac/index.ts` were removed on purpose.

## Major, should be fixed in this release

### M-1. Every code example in the new Safe Eval chapter is wrong about the real `Eval`/`SafeFunction` API (verified)
`guides/safe-eval.md:74`, lens docs. Each snippet was reproduced against `src/lang/eval.ts`:
- **`SafeFunction({inputs, output, body})`:** `inputs` and `output` don't exist; the real option is `params`. So `add(1,2)` returns `{result: NaN, …}`, where the chapter says 3.
- **`Eval({…, output: 0})`:** returns `{result, fuelUsed}`, not the bare value, and there is no `output` option. So "typed inputs/outputs, validated at runtime" describes nothing.
- **Opening example:** fails with "fetch is not available. Use the httpFetch atom."
- **Capabilities example:** fails with "Cannot use keyword 'await' outside an async function".
- **"Both return errors as values":** false for SafeFunction, which throws on a syntax error and on oversized source.
- **Guarantees list:** dated "as of v0.12.0" and leaves out `maxHeapBytes`, quotas and abort-on-exit.

This text was moved rather than written new, but it is now a book chapter that opens with the thesis. README has the same broken first example.

**Fix:** rewrite the snippets against the real signatures, drop or implement the typed-I/O claim, update the guarantees list, put the chapter's fences under `src/doc-snippets.test.ts` (or an equivalent that executes them), and fix README's copy too.

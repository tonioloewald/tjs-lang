## Blocker

### B-1: Run arguments cross the membrane with no byte cap and no fuel charge, an unmetered pre-fuel O(n) walk of request data *(verified; security. Efficiency's argument-cost findings merged in)*
`src/vm/vm.ts:276`, `membraneValue(args, Infinity)`, added in b45bdcb.

- **Measured:** a 10MB body `{"items":[1×5M]}` sent to `Eval({ code: 'items.length', context: args, fuel: 1000 })` took 2.3–2.4s at HEAD and about 38ms at base. Both runs end in 'Out of Fuel' at varsImport, so all of that CPU is spent before the budget has any say. `membraneValue` alone takes about 3.3s. `structuredClone` alone takes about 75ms, so the cost is in the descriptor pre-walk (per-element stack push, WeakSet, byte bookkeeping), which comes to 30–70× JSON.parse of the same bytes.
- **Reach:** `functions/src/index.tjs` `page` builds `args` from `req.query` and `req.body` for public stored functions (no auth, CORS `*`). The only condition is that the stored code names a key. `run` and `agentRun` expose it to any signed-in account, because the caller controls both the code and the args. Nested `vm.run` calls pay the cost again.
- **Why the rationale fails:** the comment says args are "bounded by its request size". That bounds the bytes, not the cost per byte.
- **Test gap:** `args-membrane.test.ts` covers hostile shapes only. It has no oversized or wide-argument test.

**Fix:** give the argument crossing a finite budget that fails fast during the walk. Either default it to `membraneMaxBytes`, or add a dedicated `argsMaxBytes` run option with a finite default that hosts can raise. Consider charging the walk to fuel. Consider a fast path for dense primitive arrays and JSON-shaped data. Add a hostile-size test that asserts the refusal is **cheap** (wall-clock or fuel), not just that it happens.

**Re-review scope:** security and efficiency over the vm.ts argument crossing and its Eval, SafeFunction and functions callers.

## Majors (resolve before GO)

### M-1: A `return` inside a for...of body is silently swallowed, because for...of lowers to the same `map` op that now runs in callbackScope *(verified; correctness and security merged)*
`src/vm/runtime.ts:3273` and `src/lang/emitters/ast.ts:~685` (`transformForOfStatement`).

- **Scalar-return probe:** `for (const u of users) { if (u == 'bad') { return false } } return { allowed: true }`. At base this failed closed ("Agent must return an object"). At HEAD it returns `{ allowed: true }`.
- **Object-return form:** `return { allowed: false }` inside the loop was already swallowed at base. The remediation removed the last case that failed closed.
- **Eval:** the `CALLBACK_OPS` skip in `wrapReturnValues` also stops boxing a for...of return, which will conflict with any later fix.
- **Related, also silent and pre-existing (found during verification):** `let s = 0; for (const x of [1,2,3]) { s = s + x } return { s }` returns `{ s: 0 }` at both base and HEAD. An assignment to an outer `let` from a loop body is lost. Same root cause: a loop body gets callback/child-scope semantics, not loop semantics.

**Fix:** make the AST distinguish a loop from a callback, for example `loop: true` on the node (a v1 VM can read it) or a distinct op. Loop bodies should propagate `output` and outer assignments, and stop iterating on return. Exclude loop nodes from `CALLBACK_OPS`. Until real early exit exists, reject `return` inside for...of at transpile time. Add tests for scalar and object returns and outer-`let` accumulation, both in the VM and through Eval statement form. Coordinate this with the AST v2 decision recorded in db50cf6.

### M-2: Arguments silently lose data that lives behind the prototype, and a negated rbac rule flips from deny to allow *(verified; correctness. The unverified private-field `{}` finding from blast-radius is merged in)*
`src/vm/vm.ts:276`.

- **Timestamp-shaped class** (own `_seconds`, prototype getter `seconds`):

  | Rule | Base | HEAD |
  |---|---|---|
  | `doc.createdAt.seconds` | 50 | undefined |
  | `doc.createdAt.seconds < 100` | true | false |
  | `!(doc.expiresAt.seconds < now)` | deny | **ALLOW** |

  None of these report an error. The real dependency has this shape: the Firestore `timestamp.js` reaches `functions/src/store.tjs:45` through `docSnap.data()` and then Eval at `rbac.tjs:200`. It is latent until functions/ moves off `^0.13.11`.
- *(unverified)* `class Acct { #b = 5; get balance() {…} }` crosses as `{}` with no error.
- An OWN getter is refused loudly, so prototype getters are handled inconsistently. The CHANGELOG says only that the prototype is dropped.

**Fix:** on the argument path, refuse objects whose prototype is not Object.prototype, null, Array, Date, Map, Set, RegExp or a typed array, with an AgentError that names the path. This makes the loss loud and consistent with own getters. Also have `rbac.tjs` normalise Firestore values (Timestamp to millis) before calling Eval. Add a test with a prototype-getter argument and a test with a private-field argument.

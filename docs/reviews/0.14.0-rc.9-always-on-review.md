### TODO.md / Virta board (correctness, security)

- [ ] **(minor, unverified) `patternLabel` emits a .d.ts that does not compile for nested array elements and quoted keys.** File: `src/lang/emitters/js.ts:3911`.
  - `export function b(k: 0, [{ x }, { y }])` produces `[ _, _ ]: any[]`, and tsc reports TS2300 (duplicate `_`).
  - `export function a(k: 0, { 'a-b': x = 0 })` produces `{ "a-b" }: {  }`, and tsc reports TS1005. The `'a-b'` member also drops out of the checked shape.
  - In rc.8 the array parameter was simply omitted (valid TS, wrong arity). Now the declaration file fails to compile.
  - Fix: emit unique placeholders (`_0`, `_1`) or render nested patterns recursively. Write a non-identifier key as `{ 'a-b': _k }`, or fall back to a generated name. Add both shapes to `src/lang/dts-compiles.test.ts`.
  - Do this one first: it is the only finding that makes shipped output invalid.
- [ ] **(minor, unverified) The CHANGELOG [Unreleased] entries are stale and incomplete.**
  - Line 110 in the #3443 entry still says "An ARRAY pattern's annotation is still erased unchecked (#3497)." This is confirmed present. The #3497 entry and the code say it is now checked, so delete the line.
  - Add a **Behaviour change** marker to #3411. `function f(xs = [Book])` accepted Book-shaped values in rc.8 and refuses them now; the spelling for a list of Books is `xs: [Book]`.
  - Then run `bun run docs`, or `demo/docs-fresh.test.ts` goes red.
  - This is a docs line that can be fixed now, before the tag, without a re-review.
- [ ] **(minor, unverified; merged from the correctness and security lenses) `scripts/attested.ts` decides whether a tag push skips the full suite, and nothing tests it.**
  - Add `scripts/attested.test.ts` on the scratch-repo pattern of `release-stamp.test.ts`.
  - It should pass one valid case and an annotated-tag sha.
  - It should refuse: other files changed in the commit, a parent tree that differs from `att.tree`, a version mismatch, `test:full` missing or with a non-zero exit code, a root commit, and invalid JSON.
  - Harden two edges: refuse an `att.tree` that is not 40 hex characters, so two empty strings cannot match. Refuse when the tag's `package.json` has no version, since `undefined === undefined` currently passes.
- [ ] **(nit, unverified) A Type-valued default produces a misleading .d.ts.** File: `src/lang/emitters/dts.ts`.
  - `xs = [Book]` renders as `xs?: () => any[]`; it should be `(() => any)[]`.
  - `t = Book` is declared as a required parameter.
  - Fix: in `typeDescriptorToTS`, parenthesize function and union element types inside arrays. Record `hasDefault` for non-literal defaults so the parameter is declared optional.
  - Both renderer bugs already exist in rc.8, but #3411 now sends every Type-valued default through them.
- [ ] **(nit, unverified) A destructured array parameter that fails its check gets a list-level message at the function path.** File: `src/lang/emitters/js.ts:3881`.
  - Ordinary list parameters got the per-element #3407 diagnosis (`f.xs[1]`); destructured ones did not.
  - Fix: prepend `listElementDiagnosis` in the failure branch of `destructuredArgChecks`.

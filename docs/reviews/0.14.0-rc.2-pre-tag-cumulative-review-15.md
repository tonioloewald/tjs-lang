## Blockers

### B1 (correctness, verified): `BUILTIN_ADVICE` reads `SharedArrayBuffer.prototype` at module scope. `src/vm/runtime.ts:878`
- **Effect:** browsers leave `SharedArrayBuffer` undefined unless the page is served with COOP/COEP headers. Evaluating the module then throws `ReferenceError: SharedArrayBuffer is not defined`.
- **Reproduced:** `delete globalThis.SharedArrayBuffer` and then importing either `src/vm/runtime` or `dist/tjs-vm-ast.js` throws.
- **Where it ships:** dist/index.js, tjs-vm.js, tjs-vm-ast.js (the recommended VM), tjs-eval.js, tjs-from-ts.js and tjs-browser-from-ts.js. This also breaks the doc site's `ajs` dialect. The base had no reference to SharedArrayBuffer.
- **Why no lane caught it:** every lane runs on Bun or Node, where the global always exists.
- **Fix:**
  - Add the entry only when `typeof SharedArrayBuffer !== 'undefined'`.
  - Audit the map and the rest of runtime.ts for other module-scope reads of globals that some hosts lack.
  - Add a subprocess row that deletes the global and imports both the source and `dist/tjs-vm-ast.js`.
- **Re-review scope:** correctness over the remediation diff, plus Tier 0 (the rebuilt dist bundles).

## Major (must fix before tag)

### M1 (security + correctness, verified): putSlot writes copies by plain assignment. `src/vm/runtime.ts:866`
Since this diff, every key except `__proto__` is written with `(parent as any)[key] = c`. Round 39 used `defineData` for every key. Two reproduced effects:
- **(a) An accessor on Object.prototype runs and drops the key.** A polyfill or host-side pollution is enough. `membraneValue({ hook: {secret:1}, a: 1 })` returned ok with own keys `['a']`. The host setter ran twice with guest or capability data, and `hook` was silently missing from the copy. That is host code running inside the membrane plus silent thinning, the M-2 class.
- **(b) Frozen intrinsics refuse ordinary JSON.** This covers SES lockdown, `--frozen-intrinsics`, or any non-writable prototype property. `{ toString: 'x' }`, `{ valueOf: 1 }` and the like throw "Attempted to assign to readonly property". That becomes kind 'shape', so ingress or egress halts the run. Arrays carrying a non-index key behave the same when `Array.prototype` is frozen; that case was inferred, not run.

The guest-key-writes ALLOWED reason ("no prototype setter runs") is true only for `__proto__`.

- **Fix:** use `defineData` for any key the fresh copy already has through its prototype (`key in parent`), or simply for every non-index key. Correct the ALLOWED reason. Add membrane-invariant rows for an Object.prototype accessor and a frozen Object.prototype, inbound and egress, asserting: no setter is called, the key survives, nothing is refused.
- **Re-review scope:** correctness and security over the putSlot/readArrayData diff, plus a re-run of the membrane perf measurement that justified switching to assignment.

## Minor (verified): fix now or file

### m1 (correctness/security, verified): the egress headroom ignores the live heap. `src/vm/runtime.ts:4873`
- `headroom = maxHeapBytes - heapAccount.transient` leaves out `heapAccount.bytes`.
- Reproduced with a cap of 100KB, about 90KB live, and an 81KB egress: the whole copy is built, then `allocate()` reconciles and refuses.
- With a raised `membraneMaxBytes`, the peak can approach 2x the ceiling.
- This contradicts the new comment ("never BUILT larger than the heap gate would let it be") and the I1 exception in docs/vm-budgets.md.
- Bounded by min(membraneMaxBytes, payable fuel), which is 4MB by default.
- **Fix:** reconcile first, or use the reconciled live figure, because `bytes` is a grow-only over-estimate and subtracting it raw could refuse falsely. Otherwise narrow the comment and the doc to what is actually guaranteed. Add a row with a non-zero live heap.

### m2 (blast-radius, verified): the I1 heap bound reached only one of the membrane's three callers
- `ingressValue` (`runtime.ts:4947`) builds its copy within `membraneMaxBytes` alone, and run-argument admission (`vm.ts:408`) builds within argsBudget alone. Neither has a heap term.
- With `maxHeapBytes` at 1MB, a 3MB capability return is fully copied before the bind refuses it.
- docs/vm-budgets.md's general I1 sentence is false for ingress.
- **Fix:** put the headroom into the shared crossing, or document ingress and arguments as deliberate exceptions in the code and the door list. Add an ingress I1 row next to the egress row in membrane-halt.test.ts.

## Round 41 — plan (written before any code, per the cycle STOP)

**The underlying problems.**
1. **B1: module scope assumed a host.** Every lane runs on Bun or Node, where every global
   exists, so nothing tested loading the VM in a minimal browser global environment. The fix is
   the guard, plus a test that loads the source AND the shipped bundles with the
   optional globals deleted (`SharedArrayBuffer`, and any other a host can lack), so the next
   module-scope read of an optional global fails in a lane.
2. **M1: the copy was written by `[[Set]]`, which consults the prototype chain.** Round 40
   switched from `defineProperty` to assignment for speed, and assignment reaches inherited
   setters and read-only properties. The fix that keeps the speed: **build every copy with a null
   prototype**, where assignment can only create own data properties (no prototype to consult,
   no setter, no read-only check), and **give each copy its real prototype
   (`Object.prototype`/`Array.prototype`) once the walk ends.** No assignment ever happens on an
   object that has a prototype, so the setter class is closed by construction, not per key.
   - The `Date` constructor is captured at module load (a host replacing `globalThis.Date` cannot
     change what the membrane builds).
   - Rows: an `Object.prototype` accessor (and an `Array.prototype` index accessor) is never
     called and the key survives; under a frozen `Object.prototype`, `{ toString: 'x' }` crosses;
     both directions.
3. **m1 + m2: one crossing budget for every caller.** A shared `crossingBudget(ctx, cap, op)` is
   the smallest of the cap, payable fuel (egress) and the heap headroom. The headroom uses the
   LIVE heap: when the grow-only estimate would make the headroom bind, it reconciles first
   (charged), so it does not refuse falsely. Both `egressValue` and `ingressValue` use it, and
   run-argument admission adds `maxHeapBytes` to its budget. Rows: egress with a live heap near
   the cap, and an ingress return larger than the heap ceiling (refused at the walk, catchable,
   since it is a limit).
4. **Minors:** a refusal names the binding budget ("heap", "fuel" or "membraneMaxBytes"), and one
   primitive cost table is used everywhere.

Re-review scope: correctness + security over the round-41 diff, plus Tier 0 on rebuilt bundles.

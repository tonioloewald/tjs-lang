## Blocker

### B-1. A refused outbound-membrane walk is charged only for a byte-budget refusal (CONFIRMED, correctness + security; merged)

`src/vm/runtime.ts:4778-4781`, `egressValue`.

`membraneValue` (around line 702) can also refuse for these reasons. Each returns `{ok:false, reason}` after walking everything popped before the failure:
- depth (`MEMBRANE_MAX_DEPTH` = 10,000)
- function, symbol or bigint
- accessor
- class instance
- Map/Set subclass
- not-cloneable

`egressValue` charges the walk only if the reason matches `/-byte membrane budget/`. The walk is LIFO, so the guest can put the offending element where it is reached last, for example `[deepChain].concat(wide)` or `{ a: deep, b: wide }`. It then loops `try { storeSet({ key: 'k', value: big }) } catch {}`.

Two independent reproductions on `transpile()` output:
- **Correctness lens:** 100 extra refused calls cost about 594 fuel (about 6 each, which is the base cost) and about 4 s of CPU. Charging the bytes walked would be about 160 fuel per call, so this is about 27x under-charged.
- **Security lens:** about 160 ms per call, or about 28 ms per fuel. The default timeout assumes 10 ms per fuel.

This makes the round-31 CHANGELOG line "a call that is refused is charged for the walk it caused" and the `docs/vm-budgets.md` door row false for every refusal kind except byte budget. `egress-cost.test.ts` only covers an accepted call and a schema refusal. The schema refusal happens after a copy that has already been charged.

**Fix direction**, which should come out of the STOP plan rather than a patch:
- Have `membraneValue` report the bytes walked on EVERY failure path, e.g. `{ ok:false, reason, bytes }`, or charge through a hook on every exit.
- Have `egressValue` charge those bytes on every refusal. Remove the reason-string regex; the coupling is itself a defect (see completeness gap 7). Keep the "Out of Fuel" mapping when the payable amount is under the cap.
- Add an egress-cost row built from `transpile()`: N refused calls on a value with a wide part of about a MB plus a depth-over-limit chain must cost at least c x N x size fuel. Mutation-check it against the current regex gate.
- Add similar rows for the function and accessor refusal kinds.

**Re-review scope:** correctness + efficiency + security over the remediation diff (`membraneValue` failure paths and `egressValue`).

**The underlying pattern for the STOP plan:** rounds 29 to 31 each closed one egress path, and each fix had a residual "free when refused" or "unchecked" branch. Billing that depends on the outcome (charge only on a particular refusal) is the shape that keeps failing. The property should be "every walk is billed for what it touched, independent of outcome", enforced structurally, for example by a walk primitive that takes a meter.

## Minor / nit (non-blocking; scheduled below)

- **M-1 (CONFIRMED, minor, correctness). Key-less `cache` is keyed by a digest of its STEPS, not of the data they read** (`runtime.ts:7299`, `blockKey`). Reproduced: the same block run with args `{x:'A'}` and then `{x:'B'}` on one store returned `{"a":"A"}` both times. That is a persistent entry (24 h TTL) crossing runs, and crossing tenants if the store is shared. `memoize` in a loop shows the same behaviour within one run. It is narrower than the old shared `cache:undefined` key, but the CHANGELOG "Fixed" entry reads as though key-less cache is now safe.
- **M-2 (unverified, minor). `cache` now FAILS the step when the result can't cross egress** (`runtime.ts:7444`). A computed, paid-for result over `membraneMaxBytes` or the depth limit turns into a run error, where before it was returned. Decide between returning the result uncached (charged, with a flight-recorder 'vm' notice) and documenting a bounded result, and pin the choice with a row.
- **M-3 (unverified, minor; correctness + security, merged). The egress-doors ratchet is per-atom, not per-call-site** (`src/vm/egress-doors.test.ts:76-95`). It only requires `egressValue` to appear somewhere in a SELF_EGRESS atom. A second `store.set(otherKey, result)` in `cache` or `agentRun` would stay green. The review-5 M-1 fix specified a per-call check. The file list is also hand-maintained and omits `src/vm/atoms/browser.ts`, which has six IO atoms (completeness gap 5).
- **M-4 (unverified, minor, security). The `cache` key reaches the host store with no `membraneMaxBytes` cap** (`runtime.ts:7397`). A guest-built 30 MB string key goes to `store.get` and `store.set`. The same key through `storeGet` is capped.
- **M-5 (unverified, minor, blast-radius). DOCS-AJS.md (around line 1086) never tells custom `effects:'io'` atom authors using `resolveInputs:false` to route capability arguments through `egressValue`.** The rule exists only in CHANGELOG and CLAUDE.md (not shipped), and the ratchet covers only this repo's own atoms.
- **M-6 (unverified, minor, efficiency). The build prints no size delta against the last release** (`scripts/build.ts:231`). This round's growth is justified; the tooling gap lets repeated small growth add up unseen. No action needed on this diff.
- **N-1 (unverified, nit). Cost and timeout FUNCTIONS now receive the live, unvalidated resolved input** (`runtime.ts:4930`), because egress moved after the base cost to fix B-1. That contradicts the `egressValue` docstring "a host never holds a live guest object". The likely fix is to narrow the docstring.
- **N-2 (unverified, nit). The `digestHex` fallback without `crypto.subtle` is a 32-bit hash** (`runtime.ts:7552`). Distinct key-less blocks can collide on http:// pages. Digest keys also share the `cache:` namespace with explicit keys.
- **N-3 (unverified, nit, blast-radius). Orphaned `cache:undefined` entries remain in persistent host stores** from before the fix.

## Round 32 — plan (written before any code, per the cycle STOP)

**The underlying problem.** Billing depended on how a walk ENDED: `egressValue` charged only when
the refusal reason matched `/-byte membrane budget/`. Rounds 29–31 each closed one egress path
and left a branch that was free or unchecked. The property has to be "every walk is billed for
what it touched, whatever the outcome", and it has to hold structurally:
- `membraneValue` reports the bytes it walked on EVERY result, success or refusal;
- `egressValue` charges them unconditionally, with no reason-string coupling.

Tonio's decisions (2026-10-04) fold in, all as refusals:
- an IO atom must declare an input schema;
- an IO atom's input schema may not contain `pattern`, which would run on the host's regex
  engine over guest-chosen strings (the JSON Schema direction is Pattern, `docs/pattern.md`);
- key-less `cache` is refused.

1. **B-1.** Every exit of `membraneValue` carries `bytes`, the bytes walked so far, from one
   variable. `egressValue` charges `min(bytes, budget)` on every refusal. When the walk reached
   the budget and fuel was the binding limit, the refusal is `Out of Fuel`. The regex is removed.
   - Rows from `transpile()`: N refused calls on `{ deep: <chain past the depth limit>, wide:
     <~MB> }`, ordered so the wide part is walked first, must cost at least c×N×size.
   - Direct rows for the kind refusals a guest cannot build (function, accessor, class
     instance).
   - Mutation-checked against restoring the regex gate.
2. **Refusals at `defineAtom`, so the host hears about it at registration, not on the first
   call:**
   - an `effects: 'io'` atom with no input schema (`uuid` and `clearExpiredProcedures` get
     `s.object({})`; `return` is declared `pure`, which the core sweep already makes it);
   - an IO atom whose input schema contains `pattern` or `patternProperties` anywhere.
   - Both get rows, and the CHANGELOG lists them as breaking for embedders.
3. **Key-less blocks.** `cache` without a key is refused, by the builder's type (the key becomes
   required) and by the VM. `memoize` without a key is refused too: in a loop it returned the
   first iteration's result for the same reason (a steps digest is not the inputs). `blockKey` is
   removed and `digestHex` stays for `hash`, which also makes N-2 (the 32-bit fallback) moot.
   - The `cache` key crosses `egressValue`, so it is capped like `storeGet`'s (M-4).
   - A result that cannot cross fails the step, consistent with refusing; that is now decided
     and pinned by a row (M-2).
4. **M-3, the ratchet per call site.** In a SELF_EGRESS atom, every argument of a call through
   `ctx.capabilities.*` or `storeOf(ctx)` (aliases included) must be a literal, an `egressValue(...)`
   call, or a name/property bound to one. An apparatus row plants a live call. The source file
   list is derived by parsing for `defineAtom` calls, not maintained by hand.
5. **Docs and smaller items.**
   - M-5: the `egressValue` rule goes into DOCS-AJS's custom-atom guidance.
   - N-1: narrow the `egressValue` docstring to "what a capability receives" (cost and timeout
     hooks see the resolved input).
   - N-3: a CHANGELOG line on stale `cache:undefined` entries.
   - The CHANGELOG "Fixed" wording becomes "refused".
   - Completeness gap 6: a heap row showing egress transient bytes are released per step (many
     large egress calls under a small `maxHeapBytes`).
6. **Carried:** M-6 (build size delta) joins #2848.

Re-review scope: correctness + efficiency + security over the round-32 diff.

## Round 32 — implemented (2026-10-04)

- **B-1: billing no longer depends on the outcome.** `egressValue` bills a refused walk its whole
  budget, whatever refused it: the walk never reads past its budget, so the budget bounds the
  work. The reason-string regex is gone.
  - A throw from inside the charge (`allocate` refusing a copy over the heap ceiling, which it
    does before charging anything) is billed the same way.
  - This is a deliberate overcharge for a small refused value: refusing is never cheaper than
    the walk could have been. That beats the plan's "report bytes walked on every exit", which
    would have threaded a counter through every return of the walk and its helpers, the shape
    that kept leaving a branch out.
  - Rows: direct refusals for depth (which a guest can build; measured once through transpile()
    at ~216 fuel and ~250ms each), function, accessor, class instance, and the heap-ceiling
    throw; plus transpiled rows for the heap-refused copy and for over-budget refusals.
- **Tonio's refusals (2026-10-04):**
  - `defineAtom` refuses an IO atom with no input schema. `uuid`, `clearExpiredProcedures` and
    `return` declare theirs.
  - `defineAtom` refuses `pattern`/`patternProperties` anywhere in an IO atom's input schema.
    The walk distinguishes keyword positions from property names, so `properties: { pattern }`
    passes (`regexMatch` has an input named `pattern`).
  - `cache` and `memoize` require a key, both in the builder's type and in the VM. `blockKey` no
    longer digests the steps.
  - Fixtures in `admission.test.ts` (14 atoms) declare `s.object({})`.
- **M-2:** decided as a failed step, and pinned. **M-4:** the cache key crosses `egressValue`, and
  an oversized key never reaches `store.get`.
- **M-3:** `egress-doors.test.ts` checks every call site. In a SELF_EGRESS atom, each argument of
  a call through `ctx.capabilities.*` or `storeOf(ctx)` (aliases followed) must be a literal, an
  `egressValue(...)` call, or a name, property or template built only from those.
  - It has an apparatus row (a planted live call).
  - The file list is DERIVED by parsing for `defineAtom` calls, with three non-shipped files
    listed with reasons.
  - Mutants caught: a second live `store.set` in `cache` (the review's own example), and
    agentRun forwarding the raw id.

  that fits one pass; with the release removed, the row fails.

  narrowed (N-1); CHANGELOG rewritten from "Fixed" to the breaking refusals, plus the stale

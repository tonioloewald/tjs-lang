## BLOCKER (1) — must be fixed before tagging

### B1. `writeEmitted` guards only the leaf, so a symlinked output **directory** still escapes the named tree — data loss reported as `0 failed`, exit 0
`src/cli/walk.ts:143-150` · verified ×3 independently · **re-reproduced this session**

```
out/sub -> ../precious   (precious/b.js = "DO NOT LOSE ME")
tjs emit src -o out -r
→ "1 emitted, 0 failed, 0 skipped", EXIT=0
→ precious/b.js now contains transpiled JS; precious/b.md newly created
```

`existsSync(dir)` follows the link (no mkdir), `lstatSync(outputPath)` resolves `sub` *through* the link and sees a regular file, `writeFileSync` writes through. A symlinked output **root** (`ln -s /elsewhere out`) escapes the same way with no victim file required. `tjs convert` is identical.

This is precisely the escape `readEntries`' own docstring forbids ("descending escapes the tree the user named"), and `CHANGELOG.md:59-63` asserts the class is closed ("Writes now go through one `writeEmitted` boundary that unlinks a symlink rather than following it"). The funnel landed; the guard behind it did not. All three new `walk.test.ts` symlink cases place the link at the leaf, so the suite is green over it.

**Fix:** containment, not per-leaf unlink. Resolve `realpathSync(dirname(outputPath))` once against `realpathSync` of the user-named `-o` root and refuse — loudly, counted as a failure, non-zero exit — on escape. Note the fix must be *containment* rather than "refuse any symlinked component": `-o dist` where `dist -> /build/dist` is a legitimate, common setup travelling the same code path. Add `walk.test.ts` rows for (a) symlinked output root, (b) symlinked intermediate directory with a pre-existing victim file.

## MAJORS (12)

### Correctness / coverage — fix now (these are why the verdict is BLOCK-adjacent)

**M1. `tjs emit -o <path>` overwrites its own JS output with the generated markdown whenever the path does not end in `.js` — exit 0** · `src/cli/commands/emit.ts:174,200` · verified · re-reproduced

```
tjs emit a.tjs -o out/a.mjs  →  EXIT=0, "✓ a.tjs -> out/a.mjs"
out/a.mjs contents:  ```tjs / function add(a: 1, b: 2): 3 / ```
```

`docsPath = outputPath.replace(/\.js$/, '.md')` does not match `.mjs` or an extensionless path, so `docsPath === outputPath` and the docs clobber the module. With `--dts` it happens twice (`.d.ts` clobbers first). `.mjs` is the normal ask for a `"type":"module"` package. Derive siblings from the input stem (`outputPath.replace(/\.[^./\\]+$/, '')`), and **refuse to write when a derived path equals `outputPath`** — that is a bug, not a user choice.

**M2. Both `emit` and `convert` drop the `#!` line on the stdout branch, and `emit` can interleave narration and guest output into the artifact** · `emit.ts:216`, `convert.ts:152` · verified · re-reproduced
*(merges 5 findings across correctness / coverage / dx / blast-radius)*

- `tjs emit bin.tjs > bin.js` → first line is `class MonadicError extends Error{…}`; the shebang is gone, exit 0. The `-o` path is correct. **This is a regression inside the release line** — at 0.13.1 `result.code` carried the line and both paths worked.
- The idiom is first-party and documented: `src/cli/tjs.ts:72` (`--help`, the *first* emit example), `docs/WASM-QUICKSTART.md:59`, `guides/tjs-examples.md:314`, and `functions/package.json` `build:transpile` literally runs `emit "$f" > "${f%.tjs}.js"`.
- Worse: signature tests execute the module in-process, so a top-level `console.log` lands on fd 1 *inside the artifact* (`node --check` → `SyntaxError`), and `--jfdi` writes the test report into the artifact at **exit 0**. The comment at `emit.ts:104` promising "Warnings to STDERR, so `tjs emit file.tjs > out.js` still produces clean output" is false.

**Fix:** funnel both branches through one `emitArtifact(sink, code, hashbang)`; route the test narration at `emit.ts:116-134` through `console.error`; capture guest stdout during signature-test execution. Add a `check.test.ts` row that redirects stdout and runs `node --check`.

**M3. `src/cli/port.test.ts` is genuinely RED, and the one lane that triggers it swallows the failure** · `src/cli/port.test.ts:114` · verified · **re-reproduced this session** (`19 pass, 1 fail`)

```
(fail) finding who holds a port > does NOT call the test runner ours, even though it is bun
       Expected: false   Received: true
```

`isOurServer` = `OUR_SERVERS.test(args) && args.includes(OUR_ROOT)`; an argv carrying absolute repo paths satisfies both, so `tjs-playground --port N --force` will SIGTERM/SIGKILL a stranger process that merely references this installation — falsifying `playground.ts:78`'s shipped promise. Relative argv hides it, which is why `test:fast` is green. It **is** hit in CI: `bun run test:dogfood` prints `original : 3548 pass, 1 fail` while the harness (`dogfood-tests.test.ts:317`) only feeds `pass`/`asserts` into assertions and drops `before.fail` — its own docstring baseline says `0 fail`. Not waved away as pre-existing: it is red now, in the shipped tree, and the gate that should catch it launders it.

**Fix:** assert `before.fail === 0` in `runSuite` with the failing lines in the message; tighten identity to require the matched entry point *itself* under `OUR_ROOT` as a whole argv token; add a port.test.ts case with absolute repo paths so it reproduces in the fast lane. Also correct `TODO.md:2251`, which still blames "the LIVE LLM lane" — a wrong diagnosis that will get the next red gate waved off.

**M4. `tjs convert`'s hashbang restore — a headline 0.13.2 fix — ships with zero tests** · `src/cli/commands/convert.ts:88` · verified

No test anywhere exercises `convert` with a shebang; the fix is a second hand-rolled copy of the `js.ts:1980` extraction with nothing pinning them together. Deleting the `hashbang` argument leaves the whole suite green while restoring the exact 0.13.1 defect. Review 8's M3 explicitly prescribed this test; the code landed, the test did not.

### Dryness — the shape that keeps producing the above

**M5. `emitDirectory`/`convertDirectory` are structural twins, and this is the third release where the same defect had to be fixed twice** *(unverified)* · `emit.ts:236`

**M6. The `#!` scanner exists in three places, two byte-identical** *(unverified)* · `parser.ts:123`, `js.ts:1980`, `convert.ts:88`

Export one `splitHashbang(source): { hashbang?, body }` / `hashbangEnd(source)`, call it from all three, add `hashbang` to `FromTSResult`, and add a row to `literal-blindness.test.ts`.

## MINORS (11)

1. **Emitted `#!` files are written 0644** — `./bin.js` → `permission denied`, exit 126 (re-verified: `-rw-r--r--`). `check.test.ts:90` is titled "…so the output is still executable" and `chmodSync(out, 0o755)` at line 115 — the property is manufactured by the test and can never go red. Review 8 offered fix-or-caveat; 0.13.2 shipped neither.
2. **`writeEmitted` deletes a user's symlink with no receipt** — destructive, rare, silent, no opt-out. The docstring says "refuses to write THROUGH", which reads as *declines*; it destroys. Emit one stderr line, or refuse by default behind `--replace-links`.
3. **`result.hashbang` is documented only in the CHANGELOG** — absent from CLAUDE.md, `llms.txt`, `DOCS-TJS.md`. Consumers who write `tjs(src).code` to disk now silently produce shebang-less bins with no diagnostic. Also: `src/cli/walk.ts` (three single-source rules) is in neither index, and `write-boundary.test.ts` is missing from CLAUDE.md's Guardrail Tests list.
4. **The hashbang/symlink *policy* is unexported** — `writeEmitted` lives in `src/cli/walk.ts` with no `./cli` subpath export, so every downstream build script re-hits 0.13.1's bug by doing the obvious thing. Ship an `attachHashbang(result)` / safe-write helper from `tjs-lang/lang`.
5. **"Every file the CLI writes goes through one `writeEmitted`" is false** *(verified, adversarially downgraded major→minor)* — `src/cli/create-app.ts` (published bin `create-tjs-app`) makes **7** raw `writeFileSync` calls and `write-boundary.test.ts:23` scans only `commands/`. *No live hazard: `create-app` refuses an existing path and writes only into a directory it just created — verified against both live and dangling symlinks.* The defect is the over-broad sentence (in the tarball **and** `demo/docs.json`) plus a guard whose title over-promises its scope. Widen the scan to `src/cli/**` with an allowlist-with-a-reason, or narrow the sentence.
6. **`write-boundary.test.ts` hand-rolls a fifth comment stripper** *(verified)* — demonstrated false negative: a literal containing `/*` blanks the real `writeFileSync(` call. `literal-blindness.test.ts:372` misses it twice over (excludes `.test.ts`; its detector doesn't match this spelling). Use `maskLiterals` from `src/strip-comments.ts` — *note: the finding recommends `maskLiteralsKeepComments`, which is wrong; that view reintroduces the comment-mention false positive.*
7. **The guard's pattern is a bare substring** — misses `Bun.write(`, `appendFileSync`, `fs/promises.writeFile`, `createWriteStream`.
8. **CHANGELOG:71 says 0.13.0 "**will be deprecated on npm**"** — registry read-back shows it already is. `TODO.md`'s "Publish-time npm steps for 0.13.1" block still has every box unchecked, so the repo's record disagrees with the registry in both directions.
9. **`walk.ts`'s module docstring contradicts its own code** *(verified)* — says `emit`/`convert` are "deliberately NOT routed through this" while all five commands import from it and it now owns the write boundary; the file argues with itself 100 lines later. `findFiles`' JSDoc is orphaned (a second block was inserted between it and the function).
10. **The Bun directory-listing-cache bug is still unfiled** with a complete two-version repro, and the workaround it forces caps genuine-ESM coverage in `emitted-module-scope.test.ts`.
11. **`tosijs-coding-practices#5` has zero comments** since 2026-08-16; two port-reclaim rules owed since 2026-08-19 remain unwritten, and this release earns a third of identical shape (*the write side of a tool must honour the same symlink policy as its read side*). The over-loose identity check is still live in `tosijs-ui/src/doc-system/site/dev-server.ts`.

## NITS (5)

1. `writeEmitted` uses exception-driven control flow (`lstatSync` throws ENOENT per file) and pairs a redundant `existsSync(dir)` with an idempotent recursive `mkdirSync`. Use `lstatSync(p, { throwIfNoEntry: false })` — removes the try/catch that currently swallows *any* lstat error.
2. The blanked shebang line is left in `result.code`: `tjs('#!/usr/bin/env node\n…').code` starts with 19 spaces, so every emitted bin carries a dead line and every embedder gets one.
3. `writeEmitted` lives in `walk.ts`, whose header is exclusively about walking — the next author greps for a write helper, finds none, reaches for `writeFileSync`.
4. `README.md:225` "**Measured at v0.13.0**" is two patches stale; `bundle-size.test.ts:124` only asserts the semver *shape*, so the stamp stays green forever.
5. Two durable lessons this release earned live only in a code comment and a CHANGELOG blockquote: the *enumeration-escalation* rule (when the where-else lens misses the same shape twice, write the test that enumerates the siblings) and the *6-of-8 recidivism rate* (the strongest available evidence for the RC stop).

## Blockers (all confirmed)

### B1. egressData is recursive and has no cycle guard for wrappers, so a guest can make vm.run THROW a RangeError
`src/vm/runtime.ts:2745` (call site `src/vm/vm.ts:644`). This merges correctness #2, efficiency #1 and security #1.
- **Set self-cycle:** `const s = Set([1]); s.add(s); return { s }` at fuel 20 throws `RangeError: Maximum call stack size exceeded`. The cause is that the wrapper is never put in `seen`, and each `toJSON()` returns a fresh array that contains the wrapper again.
- **Deep nesting:** a 100k-deep chain, linear to build at about 70k fuel, overflows the stack. Base 9baa21e returns ok on the same AST; depth 10k–20k passes on both.
- **Why it blocks:** the throw escapes vm.run, Eval and SafeFunction outside the monadic error path. A host that does not catch it gets an unhandled rejection, and a default Node process exits on one. This breaks "errors are returned, not thrown". It is the only recursive walker over guest data; estimateBytes, the membrane, countPaths and assertGuestData are all stack-based.
- **Fix:** make the walk iterative with an explicit stack. Put each wrapper in `seen` (wrapper → placeholder) before expanding its `toJSON`, so a cycle comes out as a cyclic array. Wrap the egress in vm.run so any failure becomes an AgentError.
- **Rows to add:** `s.add(s)`, a Set → object → Set cycle, and a 100k-deep result built both as a literal and in a loop. Each must return or error, never throw.

### B2. egressData calls setGuestKey on every copied key, so an own `__proto__` key in the result makes vm.run throw
`src/vm/runtime.ts:2777`
- **Repro:** `const o = JSON.parse('{"__proto__":1,"a":2}'); return { v: o }`. Base returns the object. HEAD throws `Security Error: '__proto__' is not allowed as an object key` out of vm.run.
- **Reach:** any untrusted JSON can trigger it (httpFetch, LLM output, store data), and a guest can trigger it on purpose. The throw happens before `changed` is known, so even a copy that would be identical triggers it.
- **Fix:** write keys with `Object.defineProperty` (own data property), as the membrane does. Combine this with B1's try/catch wrapper.
- **Rows to add:** a `__proto__`-keyed result on its own, and one next to a Set.

### B3. For `Object.assign`, assertGuestData walks the whole TARGET with no cap and no charge, which breaks cost-invariant
`src/vm/runtime.ts:4703`
- **What happens:** `args[0]` is already-checked guest state, but it is walked in full on every call. `accountMutation` charges only `args.slice(1)`.
- **Measured:**
  - 200k target, 200 × `Object.assign(big, {})`: 188ms at base vs 11,603ms at HEAD, for an identical 6953 fuel.
  - Deep 5k-entry target: about 5.8ms per call for about 4.5 fuel, more than 100x amplification.
- **Cost shape:** the guest pays for the target once and then repeats the walk, so CPU grows quadratically in fuel. The timeout still fires between calls, and the 64MB heap ceiling bounds each walk, so this is amplification rather than a single unbounded stall. It is still the "fuel ≥ c × work" class that earlier rounds blocked on.
- **Fix:** `assertGuestData(method === 'assign' ? args.slice(1) : args)`. Better, fold the check into the charged walk (see m1).
- **Row to add:** repeated `Object.assign(bigTarget, {})` either charges in proportion to the walk or does not walk the target.

## Majors (confirmed; fix before tagging)

### M1. The Set/Date-to-data egress is applied only to the vm.run result; every other guest-to-host exit still hands over live wrappers
`src/vm/vm.ts:644`, `src/vm/runtime.ts:6404` (storeSet), the agentRun capability fallback (~6659), and cache. This merges correctness M, blast-radius M, and security minor "child-run boundaries" (unverified).
- **Measured:** `storeSet({ value: { s: Set([1,2]), d: Date(...) } })` into a store that structuredClones gives `{ s: { size: 2 }, d: {...} }`. The Set's items are silently lost, the same defect as rereview-16 M1. `agentRun({ input: { s: Set([3]) } })` gives `{ s: { size: 1 } }` at the cross-process child-run boundary.
- **Persistence:** cache persists the damaged value for 24h. The internal VM Symbols also reach host code.
- **Child runs:** (unverified) an inline child returning a Set is refused by the membrane. That fails closed, but it contradicts the plan's item 4.
- **Docs:** DOCS-AJS.md:265 ("a Set or Date leaving the program becomes plain data") and the CHANGELOG/plan claim of "child-run boundaries" overstate what shipped (lens 7).
- **Fix:** add one egress choke point where io atoms hand resolved inputs to `ctx.capabilities`, mirroring the membrane on returns. Also apply it to childCtx.output in agentRun and runCode, once B1 is fixed. Otherwise narrow the docs to "the run result".
- **Rows to add:** structuredClone what each capability receives (store, cache, agent.run, fetch body).

### M2. agentRun resolves an already-resolved input a second time, so code-shaped data is evaluated in the caller's scope
`src/vm/runtime.ts:6559`. This is pre-existing (identical at 9baa21e), but "predates" is not a reason to defer.
- **Repro:** payload `{"q":{"$expr":"ident","name":"secret"}}` from JSON.parse. The agent.run capability receives `{ q: 'TOPSECRET' }`. `$kind:'arg'` also reads raw args, and under v1 a bare string resolves by name.
- **Impact:** a prompt-injection exfiltration path, and it breaks "data shaped like code stays data". This is the only site that resolves a value twice.
- **Fix:** copy the own keys of `rawInput` with `setGuestKey` and do not resolve them again.
- **Row to add:** a JSON-parsed `$expr`/`$kind` payload reaches the capability, and an inline child's args, byte-identical.

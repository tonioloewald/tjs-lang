## Fix before tag (correctness/security, verified)

### F1 (minor, verified, found by correctness and security): a genuine array with a `null` or `Object.prototype` prototype crosses as an index-keyed object with no `length` (`src/vm/runtime.ts` ~956, `admitKind`)

- **What happens:** `admitKind` returns `array` only for `Array.isArray(v) && proto === ARRAY_PROTOTYPE`. A brand-true array with a `null` or `Object.prototype` prototype falls through to `proto === OBJECT_PROTOTYPE || proto === null`, which returns `plain`. `readOwnData` then drops the non-enumerable `length`.
- **Reproduced on HEAD:**
  - `membraneValue({ a: Object.setPrototypeOf([1,2,{x:1}], null) }, 1e6)` returns ok, and `a` is `{0,1,2}` with no `length`.
  - With `transpile()` output: `if (x.blocked.length > 0) { allowed = false }` returns `{ allowed: true }` when the store hands back `Object.setPrototypeOf(['mallory'], null)`. That is a fail-open deny check.
  - The run-argument path behaves the same way.
- **A regression:** at 65dd877 the `Array.isArray` branch ran first, so these values crossed as arrays.
- **Why it is minor:** the host must deliberately swap the prototype. Review 14's ruling ("disguised built-ins are copied as presented") arguably covers it, and a prototype-swapped Map already crosses as `{}`.
- **Why it is still worth fixing now:** `Array.isArray` has already identified the value as an array, so the ruling's cost argument (the per-object brand probe) does not apply. No test pins this case in either direction.
- **Fix:** in `admitKind`, branch on `Array.isArray(v)` before the plain test. An array must never reach `plain`. Decide between:
  - (a) Admit it as an array with `Array.prototype`. This matches the old behaviour, and the copy is faithful because no prototype getters are lost.
  - (b) Refuse it the way a cross-realm array is refused.
- **Tests:** add membrane-halt rows for a null-prototype array and an Object-prototype array, each as a capability return and as a run argument. Add the mutant "plain branch admits an array".
- **Combine with E1:** do the efficiency reordering at the same time, so the `Array.isArray` test runs before `dateTime(v)`. That changes no admission decision.
- **Re-review scope:** security over `admitKind`'s full decision table: `Array.isArray` crossed with each prototype class (Array.prototype, null, Object.prototype, other, cross-realm, Proxy-reported). Then correctness and blast-radius over the remediation diff only.

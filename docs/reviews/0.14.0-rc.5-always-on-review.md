# 0.14.0-rc.5 always-on review (base v0.14.0-rc.4, fast depth)

**STATUS: CLEARED** (2026-10-08) — both findings fixed in d8bba99, each with a row that fails when the fix is reverted.

**Verdict: GO_WITH_FOLLOWUPS.** No blockers. Two confirmed regressions, both from `7dfb775` (the `==` / `!=` rewrite moved from a text scanner in `preprocess` to an AST pass in `bool-coercion.ts`).

Lenses: correctness, blast radius (tier `always-on`, depth `fast`). Run because this release rewrites a core transform.

## Major

### M-1: a wasm block's implicit JS fallback used `Eq`/`NotEq`, so it disagreed with the compiled WASM on NaN
- The wasm-body mask in `preprocess` covered only the passes that stayed there; the emitter's AST pass saw the lowered implicit-fallback IIFE and rewrote `arr[i] != arr[i]` to `NotEq`, which treats NaN as equal to NaN.
- `nanMark` on `[1, NaN, 2, NaN]`: WASM `[0,2,0,2]`, fallback `[0,0,0,0]`; rc.4 agreed.
- **Fixed:** the implicit fallback arrow carries an unused `__tjs_wasm_js` parameter and the equality rewrite skips it. An explicit `fallback {}` keeps TJS semantics (documented in DOCS-WASM). Row: `wasm-semantics.test.ts`, "== and != in a wasm body compare as the WASM does".

## Minor

### m-1: an outer patch overlapping a type-annotation deletion was dropped with its nested `==` rewrites
- `const C = globalThis.NOPE || class { f = (x: 0) => x == '1' }; new C().f(1)` returned `true` (JS `==` coerced).
- **Fixed:** the rewriter takes the deletion spans, applies them inside a node it rewrites, and leaves a node alone when a deletion is its own operator text; the emitter drops a contained deletion instead of the patch. Row: `equality-invariants.test.ts`, "== inside an annotated node keeps TJS semantics".

## Found while fixing (pre-existing, filed)
- #3147: arrow annotations inside an expression are never processed: `(x: '' | null)` as an operand becomes the default `'' | null`.
- #3148: `f(code = '' || null)` emits the logical OR (default `null`) while its metadata says `''`.

## Lesson
When a transform moves between passes, every exclusion mask the old pass relied on has to move with it. The wasm mask comment in `parser.ts` described a rewrite that no longer happened there.

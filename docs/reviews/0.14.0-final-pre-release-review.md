## Blockers

### B1. A custom `pure` atom can return an own `__proto__` key, so #4099's route is still open (security, confirmed)
- **Where:** `src/vm/runtime.ts:5411` (`pureReturnRefusal`).
- **What happens:**
  - The new #3991 check walks own data descriptors and never looks at keys.
  - The `__proto__` refusal from #4099 lives only in `membraneValue`, which runs only for `effects: 'io'` atoms.
- **Reproduction:**
  1. Define `defineAtom('parseJson', …, async ({text}) => JSON.parse(text), { effects: 'pure' })`.
  2. Run a guest that calls `parseJson({ text: '{"__proto__":{"polluted":true}}' })` and returns `{ o }`.
  3. The run succeeds. In the host, `Object.assign({}, result.o).polluted === true`.
  - The skeptic reproduced this in a scratch probe.
- **Why it blocks:** it is a functional defect in the sandbox, and it is exactly the class fixed as a 0.14.0 blocker (69f0744e). The CHANGELOG line 40 claim "on any route" is false.
- **Fix:**
  - Refuse an own `__proto__` key in `pureReturnRefusal`.
  - Then **close the class instead of adding a sixth row.** Either check the run result once at `vm.run` exit, or pin by parsing every host native in `src/vm/**` that creates keys from guest data (`Object.fromEntries`, `JSON.parse`, `Object.assign` and `defineProperty` onto a fresh object, regex `groups`). This also covers the unverified regex named-group route.
  - Add a pure-atom row to `proto-key-routes.test.ts`.
  - Correct the CHANGELOG wording.
- **Check that clears it:** the pure-atom row fails with the fix reverted.
- **Re-review scope:** security plus correctness, over the remediation diff and `proto-key-routes.test.ts`.

## Fix before the tag (verified majors; no re-review needed)

- [ ] **M1. An `extend` method call inside a template literal fails to transpile** (correctness, confirmed regression from rc.10).
  - Where: `src/lang/parser-transforms.ts:3926` (`rewriteExtensionCallsByAst`).
  - Cause: the code finds `.` and `(` in the `maskLiterals` view, which blanks the template's `${…}` content. The splice then cuts unrelated source. With `extend String { shout() {…} }`, `` `${'b'.shout()}` `` printed `"B"` on rc.10 and fails at HEAD with "Unterminated template" or "Unexpected token", depending on layout. A layout where the mangled text still parses would silently miscompile.
  - Fix: take both positions from the raw source between AST offsets, skipping comments.
  - Clears when: a literal-blindness row (literal receiver and variable receiver, output byte-identical) fails with the fix reverted.
- [ ] **M2. The `TJS_CONVERT_TS=1` preload (`tjs-lang/bun-plugin`) crashes in every layout** (correctness, confirmed on Bun 1.4.2).
  - Where: `src/bun-plugin/build-plugin.ts:73`.
  - (a) In-repo, linked or in a workspace, the `/\.[mc]?ts$/` hook matches tjs-lang's own sources, so the lazy `import('../lang/emitters/from-ts')` recurses into a `RangeError`.
  - (b) Installed under node_modules, the skip branch returns `undefined`, and Bun's runtime plugin API rejects it with `onLoad() expects an object returned`.
  - Fix:
    - Return `{ contents, loader: 'ts' }` on skip.
    - Exclude the plugin's own package tree, resolved from `import.meta.dir`.
  - Clears when: a subprocess test runs `bun` with the preload and `TJS_CONVERT_TS=1` against a `.ts` entry, in both layouts.
  - If this is not fixed, stop documenting the env var.
- [ ] **M3. safe-eval.md and ajs-host.md contradict two BREAKING security changes** (docs, confirmed by running `Eval`).
  - `guides/safe-eval.md:297-299` says an allowlisted `127.0.0.1` "is fetched". It is refused (#3991).
  - The fetchPolicy row (line 180) and `guides/ajs-host.md:319` omit `privateNetwork`. The ajs-host context table (lines 265-268) omits `allowPrivateNetwork`.
  - The `capabilities` default is given as "none", but `src/lang/eval.ts:72` grants `systemClock` and `systemRandom` by default (#4091).
  - Clears when:
    - The pages are corrected.
    - A drift test asserts that the documented fetchPolicy keys equal the `FetchPolicy` type's keys, and that the ajs-host table lists every `ctx.context?.X` the runtime reads.
- [ ] **M4. Seven Security entries in [Unreleased] do not name the affected shipped versions** (docs, confirmed; gate 5 of review.md, step 2 of releasing.md).
  - Entries missing a range: #2262–#2264, #2261, the import-resolver cache deletion (shipped v0.11.0 through rc.10, verified at three tags), #4099, #4091, and both #3991 entries.
  - The section has 10 bullets, not the 11 the lens counted.
  - Fix: add "**Affected:** … through 0.14.0-rc.10", or "not a shipped defect" where true (#2261).
  - Clears when: a release-doctor/Tier 0 check that every `### Security` bullet carries `Affected:` fails without the edits.

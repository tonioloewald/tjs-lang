## Fix before the tag

- [ ] **The nested `Book | null` now refuses null, which rc.6 accepted.** (major, verified, correctness) Location: `src/lang/emitters/js.ts:593`.
  - **Cause.** The `promote` closure in `promoteNested` replaces `{kind:'any', unresolved:'Book', nullable:true}` with a bare `{kind:'declared', typeName}`, which loses the `nullable` flag. The top-level promotion (around line 609) and the union-member promotion have the same bug. The top-level one already did this in rc.6.
  - **Reproduced on HEAD:**
    - `f(s: { top: Book | null })` called with `{top:null}` returns "Expected declared for 'f.s.top', got null".
    - `g(b: [Book | null])` called with `[null, {t:'a'}]` is refused.
    - Converted TypeScript (fromTS + TjsStrict) is hit the same way.
  - **Fix.** Carry the flag in `promote`, in the top-level promotion and in the union promotion: `{ kind: 'declared', typeName, ...(inner.nullable ? { nullable: true } : {}) }`. `generateTypeCheckExpr` already honours `nullable`.
  - **Check that clears it.** Add rows to `src/lang/list-element-types.test.ts`:
    - `[Book | null]` accepts `[null, {t:'a'}]` and refuses `[5]`.
    - `{ top: Book | null }` accepts `{top:null}` and refuses `{top:5}`.
    - Top-level `b: Book | null` accepts `null`.
    - One of these rows run through fromTS + TjsStrict.

    Every row must fail when the fix is reverted. Re-review scope, if any: correctness and blast radius over this remediation diff only.

## Follow-ups: this repo (Virta board, `--project tjs-lang`; TODO.md is only a pointer)

Correctness and blast-radius findings, in severity order:

- [ ] **(minor, unverified: verify first) Some checks do not see through tosijs proxies, so they disagree with single-signature parameter checks.** Location: `js.ts:803`.
  - Polymorphic dispatch: adding an overload makes `f(calculator.x)` return "no matching overload".
  - A `:?` return check refuses its own proxy return.
  - Members and elements are not unwrapped: `{a: calculator.x}` and `[calculator.x]` are refused.

  Fix: route the dispatcher tests, the return check, and member/element reads through `__tv`. Otherwise, state the limits in the CHANGELOG and `docs/type-identity.md` and pin each one with a test row. As written, the CHANGELOG claims proxy see-through for parameter checks without qualification.
- [ ] **(minor, unverified) Error labels name the mechanism or contradict themselves.** Location: `js.ts:3328`.
  - A promoted member reports "Expected declared for 'f.s.top'".
  - The dict-default path reports "Expected array …, got array of number".
  - A list of shapes reports "Expected array of object, got array of object", with no element index or member name.

  Fix: use `expectedLabel(memberType)` in `generateMemberCheckLines` and on the dict-default member path, and name the failing element and member for lists of shapes.
- [ ] **(minor, unverified) Nested declared Types are promoted for parameters but not for return annotations.** Location: `js.ts:602`. `function f(x: 0):? [Book] { return [5] }` returns `[5]` unchecked. The `:? Book` case predates this change. Fix: apply the promotion to the return descriptor, or file a card. Add a row either way.
- [ ] **(minor, unverified; two lens reports merged) The tosijs unwrap exists in four hand-kept copies, and no test compares them.** Locations: `src/unwrap-boxed.ts:59`, `js.ts:2430`.
  - The four copies: `unwrapTosi`/`TOSI_VALUE`, the `__ubxv` branch of `UNWRAP_BOXED_SOURCE`, the inline `__xv`/`__tv`, and the `expect` prelude in `src/lang/tests.ts`.
  - Nothing compares `__tv` with `unwrapTosi`, so a later edit to one could split `Type.check` from parameter checks in shipped `.js` without any test noticing.

  Fix: export an `UNWRAP_TOSI_SOURCE` string, emit it in js.ts and the `expect` prelude, and add it to the agreement corpus in `unwrap-boxed.test.ts`.
- [ ] **(minor, verified, blast radius) tosijs interop is not tested against real tosijs.** Location: `src/unwrap-boxed.ts:50`.
  - The tests use only hand-made stand-ins. Their comment says tosijs "needs a DOM to load", but `@happy-dom/global-registrator` is already installed and loads it in one line.
  - Fix: add one test that loads real tosijs under happy-dom and asserts `tosi({m:{x:3}}).m.x[Symbol.for('xin-value')] === 3`, so a rename upstream fails a test here.
  - Change the CHANGELOG and test comments that call the key "documented"; tosijs does not export it.

  The upstream half is under the next heading.
- [ ] **(nit, verified) A default that contains the Type itself now fails its own check when called with no arguments.**
  - `function f(b = [Book])` then `f()` returns "Expected array of Book, got array of function".
  - The dict-default form returns "Expected array for f.o.books".
  - In rc.6 both returned the (useless) Type object.

  Decide whether a Type inside a default is legal. If it is not, warn or refuse at transpile time. If it is, skip the element check when the default itself is used.
- [ ] **(nit, unverified) Signature examples run in every dialect in the build, but in the test runner only for native TJS.** Location: `js.ts:1205`. Under `dialect: 'js'`, `testResults` reports a failing "add signature example" while `testRunner` is undefined. Gate both on the same condition, preferably by not running return examples in the js dialect. Add a differential row with dialect js.

## Blockers (confirmed)

### B1. `isNetworkPath` misses tab, LF and CR inside the leading slashes, so the round-29 network-path refusal can be bypassed (correctness + security, merged)
- **Where:** `src/vm/runtime.ts:6309-6313` (`isNetworkPath`), reached from `admitFetchUrl` at :6488. The raw string is forwarded to `ctx.capabilities.fetch` at :6513.
- **Repro (confirmed by two independent verifiers):** call `admitFetchUrl(u, undefined, false)` (host fetch, no allowlist). It ADMITS `'/\t/evil.com/x'`, `'/\n\\evil.com/x'`, `'\\\r\\evil.com/x'` and `'/\r\\evil.com/x'`. These resolve to `https://evil.com/x`, `file://evil.com/x` or `capacitor://evil.com/x`, depending on the page's scheme. The control input `'//evil.com/x'` is refused.
- **Impact:** a cross-host request that borrows the page's scheme, which is what round 29 states is "refused on every path". Any host fetch that treats relative URLs as same-origin (for example, attaching auth or cookies) leaks them to the named host. An allowlist still blocks it, and so does the built-in fetch (`destinationRequired`).
- **Why the tests miss it:** `fetch-admission.test.ts:991-997` covers only whitespace before the first slash.
- **Fix direction:** stop mirroring WHATWG preprocessing by hand. Resolve the input against sentinel bases (one special, e.g. `http://sentinel.invalid/`, and `file:///`) and refuse it if the resolved host is not the sentinel's. A simpler interim option is to refuse any relative URL that contains `\t`, `\n`, `\r` or `\`. Add tab, LF and CR rows for all five existing shapes and mutation-check them. Then sweep `src/vm/**` for any other hand-rolled URL-shape check, including `admitImageUrls`.

### B2. `llmPredictBattery` `system`, and `llmVision` `prompt`/`system`, are forwarded without admission (correctness)
- **Where:** `src/vm/atoms/batteries.ts:~196`. Both atoms are `resolveInputs: false` (:430-442), so the declared `s.string.optional` only ever checks the unresolved `$expr` node, never the value.
- **Repro (confirmed):** `const s = [{ type: 'video_url', video_url: { url: 'http://169.254.169.254/v' } }]; llmPredictBattery({ system: s, user: 'hi' })` runs without error. The capability receives the array. `src/batteries/llm.ts:121-127` then sends it as `{ role: 'system', content: system }`. `llmVision({ prompt: s, images: [] })` forwards the array as `user.text`.
- **Impact:** this reopens the video_url / metadata-address path that cumulative review 3 blocked on, through the one argument round 29 did not rebuild.
- **Fix direction:** admit `system` and `prompt` as strings and refuse anything else. Structurally, check whether **any** `resolveInputs: false` atom validates its *resolved* inputs against its declared schema. If none does, every declared field type on those atoms is decoration, and validating resolved inputs centrally closes the whole class. Add array and object rows to `battery-output-shape.test.ts`.

## Major (confirmed; must be fixed with the blockers because it is the same class)

### M1. `tools`, `responseFormat` and the `llmPredict` options are admitted, then forwarded as the guest's LIVE objects (security)
- **Where:** `src/vm/runtime.ts:3194` (`admitResponseFormat`) and `:3234` (`admitTools`) return the guest object itself. `llmPredict` (~:6769) and `llmPredictBattery` (`batteries.ts:200-214`) forward it.
- **Repro (confirmed):** use `timeoutOverrides: { llmPredict: 50 }` and a host `predict` that awaits 300ms before serialising. The guest catches the timeout and runs `arr.push({ $ref: 'http://169.254.169.254/x' })`. The host then serialises a tool schema containing `$ref`, which `admitGuestSchema` would have refused if it had been present up front.
- **Scope:** the shipped battery stringifies synchronously, so it is not exposed. Host capabilities that await before serialising are exposed.
- **Fix direction:** apply round 29's rule everywhere: forward a copy *built from* what was admitted. Admission should emit a fresh object. As defence in depth, give each atom call its own AbortController and abort it on the atom's timeout, so host work does not outlive a step the guest has already caught. Add timeout-and-mutate rows for llmPredict, llmPredictBattery and llmVision that assert what the mock **received**. Re-review every capability-forwarding site as a whole (httpFetch body and headers, all LLM atoms, store atoms), not as a delta.

## Plan (round 30, filed before acting)

Three remaining forms of "admitted is not forwarded":
1. **A hand-rolled imitation of the URL parser.** Delete `isNetworkPath`. A relative URL is
   resolved by the REAL parser against two sentinel bases, a special one
   (`http://sentinel.invalid/`) and `file:///`. If either resolution names a host other than the
   sentinel's, the URL is refused. What is forwarded is the PATH-ONLY reference the parser
   produced (pathname + search + hash), never the raw input with its tabs and backslashes.
2. **Declared fields never checked after resolution.** The battery atoms resolve their own
   inputs, so `system` and `prompt` are now admitted as strings. The sibling sweep covers every
   `resolveInputs: false` atom that forwards a resolved value to a capability.
3. **Live objects forwarded.** `admitTools` and `admitResponseFormat` RETURN fresh copies
   (`structuredClone` of the admitted value), so a guest that catches a timeout cannot mutate
   what a slow host is about to serialise. Rows assert what the mock received after a guest
   mutation.

Plus the efficiency minor: `reconcileHeap` re-seeds `measured` with the values its walk counted
(they are in the live total by definition), so rebinding a large value near the cap stays
linear. A scaling row covers it.

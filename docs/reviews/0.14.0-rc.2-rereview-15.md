## Blocker

### B1. "A method is never a value" holds at one read site; host functions get into guest state by many routes (correctness and security, confirmed)

`src/vm/runtime.ts`: the guard exists only in evaluateExpr `case 'member'`. Reproduced at 95ac399 with `transpile()` output on a plain AgentVM, fuel 1000, no capabilities. Routes:

1. **Dot-path names** (`resolveName`, ~L1314, used by `varGet` L5212 and `varsExport`/`varsImport` L5269/5273). `const s = Set([1]); varGet({key:'s.add'})` gives typeof `'function'`. The same holds for `'s.toUpperCase'`, `'a.push'` and `'m.max'`.
2. **Bare ident reads** (`case 'ident'`, ~L4208, `return builtins[node.name]`). `const g = parseInt`, `Set`, `Date`, `encodeURIComponent` and `filter` are all live host functions.
3. **Namespace enumeration and copy.** `Object.values(Math)` (43 entries) and `Object.assign({}, JSON)` produce arrays and objects that hold host functions.
4. **Method shadowing in methodCall.** methodCall dispatches to `obj[method]`, which can be a property the guest owns. `{ hasOwnProperty: g }.hasOwnProperty(x)` runs the host function under `hasOwnProperty`'s NONE_SIG bound, which is not in `MUTATING_METHODS`. Measured: a stolen `Set.add` grew a Set by about 6MB under `maxHeapBytes` = 1MB, with no error and about 2144 fuel. The control (`s.add` called directly) is refused. With `encodeURIComponent` as the stolen function, each call amplifies its input about 9x with no charge.
5. **`toJSON`.** `JSON.stringify({k:{toJSON: encodeURIComponent}})` makes the host call a function the guest placed. The SIGS comment "no replacer (guest code has no functions)" rests on a false premise.
6. **`join` leaks VM source.** `[Set].join('')` returns 1433 characters of VM source, and `[filter].join('')` returns the source of `convertExampleToSchema`. This contradicts the CHANGELOG's claim that builtin `toString` source leaks are fixed. join's bound does not count a function's printed size: doubling `[Set]` built a 188MB string for about 940 fuel.
7. **Outbound to capabilities.** Atom inputs are resolved with no function filter. `sink({v: parseInt})`, `sink({v: Object.assign({}, JSON)})` and `sink({v: Object.values(Math)})` all hand live host functions to a custom `effects:'io'` atom.
8. **Return path (blast-radius major, folded in).** `let o = JSON; return {v: o}` gives the host `{parse: fn, stringify: fn}`. For `Math`/`console` the host gets the throwing builtin proxy, and `JSON.stringify(result)` throws `"Math.toJSON is not supported in AsyncJS"`. `functions/src/index.tjs` (`res.json(result.result)`) turns that into a 500. Guest data causes a host-side throw, which breaks the rule that guest outcomes are monadic.

These routes are older than the diff. That is not a reason to defer: the CHANGELOG, `docs/vm-budgets.md` and the rereview-14 plan all claim the general class is closed, and it is not. The only hostile test (`guest-schema.test.ts`) covers `'a'.toUpperCase` only.

**Required direction** (the remediating agent plans it under the STOP above). Make the rule one structural choke point, not a guard per read site:
- (a) A value written into guest scope or guest data may never be `typeof 'function'` or a builtin namespace proxy. This covers varSet/constSet/varsLet/varsImport, object and array literal construction, static-method results, and atom-input resolution.
- (b) Ident reads of function-valued builtins are allowed only in callee position.
- (c) methodCall never dispatches to a property the guest owns. Look up the native implementation by receiver kind.
- (d) Data-argument types (`any`, `objOrArr`, array elements) and `treeBytes` refuse functions.
- (e) Correct the "guest code has no functions" comment and the CHANGELOG/vm-budgets wording.

Ratchet: a parsed or behavioural test that tries every read route (member, dot-path, ident, enumeration/copy, toJSON, shadowing, join, atom input, return) and asserts that no function reaches state or the host.

RE-REVIEW SCOPE: security and correctness over the remediation diff, at whole-subsystem depth for ident, methodCall dispatch, scope writes and data typing. Blast-radius over AJS examples and docs that pass builtins as values.

## Remediation plan (round 11), written before acting

**Root cause.** "A method is never a value" was enforced where ONE instance was observed (the
`member` read), not where the class is produced. Host functions and builtin namespaces become
guest values through every expression that can yield one (idents, dot-paths, enumeration/copy of
namespaces and VM wrappers), and methodCall dispatched to whatever property the receiver owned.

**The invariant, stated where values are produced:** *a guest value is data* — JSON-like values
and the VM's own wrappers (Set, Date, regex) — *never a host function or a builtin namespace.*

1. **One choke point.** Every `evaluateExpr` result is checked; a function or a namespace is
   refused. The ONLY exemptions are the two positions that name something to call: the receiver
   of a method call and the object of a member read (whose own result is then checked). Dot-path
   reads (`resolveName`: `varGet`, `varsImport`, v1 string references) are checked the same way.
   Atom inputs and return values are produced by these, so they inherit it.
2. **VM wrappers expose no function values.** Set/Date wrapper methods become non-enumerable, so
   `Object.values`/`assign`/spread/`JSON.stringify` cannot harvest them.
3. **Dispatch to intrinsics, never to guest-owned properties.** methodCall resolves the callee by
   receiver KIND (the native prototype, the VM wrapper's method, or the namespace), so
   `{ hasOwnProperty: f }.hasOwnProperty(x)` calls `Object.prototype.hasOwnProperty`.
4. **Ratchet:** a behavioural test that tries every route (member, dot-path, ident, enumeration
   and copy, `toJSON`, shadowing, `join`, atom input, return) and asserts no function reaches
   guest state, a capability, or the host's result.

**Majors and minors in the same round:** per-method Schema bounds (isValid charges the admitted
schema, not 32× the data — M1); llmPredict option keys and tool shapes allowlisted (M2);
`countNodes` replaced by a per-occurrence, capped count (M3); return-path rows for namespaces
(M4); validation fuel calibrated to the VM's own rate; `filter` validates the admitted copy; dead
builder code removed; the flaky heap row isolated; the migration mapping for builder modifiers.

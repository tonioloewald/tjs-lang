## Blocker

### B1. `crossingBudget` sizes and reconciles the crossing budget wrongly (src/vm/runtime.ts ~5061-5081; callers egressValue ~4877, ingressValue ~4948)

The two parts were reported as separate findings and both were confirmed:

1. **False rejection: a correctness regression against ebf6a93.**
   - The membrane charges 8 B per primitive plus `k.length*2+8` per key.
   - `estimateBytes` charges a primitive number nothing beyond its slot.
   - Example: an IO atom returns a 2000-key object of numbers. That is 33,796 B by `estimateBytes` but 49,796 B by the membrane.
   - With `maxHeapBytes` 40000 or 45000, HEAD refuses it with "exceeds the 44896-byte membrane budget, set by the heap ceiling (maxHeapBytes)". ebf6a93 binds it.
   - This breaks the heap ceiling's guardrail property "no false rejection" (`heap-reconcile.test.ts`).
   - Egress has the same skew: the copy is then charged through `allocate()` at membrane scale.
2. **Per-crossing full-heap reconcile.**
   - The trigger is `max - bytes - transient < budget`, with the budget starting at `membraneMaxBytes` (4 MB). The crossing's actual size plays no part.
   - With `maxHeapBytes <= membraneMaxBytes`, every egress and every ingress runs `reconcileHeap`, so each io call walks the whole heap twice.
   - Reconciling cannot raise the headroom above `max - live`, so the cost never amortises.
   - Measured, with transpile() output:
     - 200 `ping({})` calls holding a 20k array under 1 MB: +39% to +79% fuel against the base.
     - 200 storeGet calls holding N objects under 3 MB, with the trigger forced off for comparison: about 10-31x wall time.
   - The reconcileHeap docstring ("after it, the next one is at least (cap − live) charged bytes away") is now false.
   - A program that fit its fuel under round 40 can now run out of fuel only because the host set a small heap ceiling.

**Why it blocks:** part 1 is a confirmed correctness regression of a documented invariant, introduced by this diff. Part 2 makes a docstring false and changes the fuel cost of existing programs. Neither is safety-breaking (the walk is metered), but "correct over fast" applies and the fix is small.

**Fix (one change):**
- Size the copy from the estimate without reconciling up front.
- If the walk refuses with `kind: 'limit'` bounded by the heap, reconcile once and retry with the live headroom. This is the same reconcile-on-real-failure shape that `chargeHeap` and `allocate` already use.
- Express the heap bound in `estimateBytes` scale, or convert the headroom into membrane scale explicitly.

**Rows to add:**
- (a) Differential: a value whose `estimateBytes` fits the headroom must cross, on both ingress and egress.
- (b) Cost: K small crossings under a near-ceiling live heap, and under `maxHeapBytes < membraneMaxBytes`, cost fuel and time linear in K + live, not K x live.
- (c) A reconcile that runs out of fuel inside a crossing ends through haltRun / monadic error on every caller. Callers: exec wrapper ~5470, agentRun ~7475, cache ~7854, leaf IO ~5119. This also closes the nit below.

**Re-review scope:** correctness, security (the I1 heap bound must still hold for the copy) and efficiency over the `crossingBudget` remediation. Include round 40 and round 41's `membraneValue`/`putSlot` changes as one combined change, since nothing has reviewed them together yet.

## Blockers (must clear before tagging)

### B1 — Parameter side channel collides across functions, silently deleting JS defaults
`src/lang/parser-params.ts:45` · correctness · **confirmed, re-reproduced during triage**

`paramSideChannelKey` keys `requiredParams` by `name` + normalised value text, so any two parameters in one module sharing a name **and** an identical literal are indistinguishable. Reproduced at HEAD:

```
function scale(factor: 1) {…}
function grow(factor = 1) { return factor + 1 }
→ emits `function grow(factor)`; grow() returns a MonadicError instead of 2   [REGRESSION vs af46fa2]

function step(amount: 1) {…}
class Counter { bump(amount = 1) { return amount } }
→ emits `bump(amount)`; new Counter().bump() returns undefined — no error,
  no warning, no recorder entry                                              [NEW breakage]
```

Also hits `function a({x: 2})` + `function b({x = 2})` (the verbatim case 462711f's message claims to fix — only fixed where the values *differ*) and `function a(n: 0)` + `const b = (n = 0) => n + 1`.

Collision needs only a shared param name plus a shared literal (`0`, `1`, `''`, `[]`, `{}`), which is ordinary code. Every case is legal JavaScript whose meaning changes silently — a **PRINCIPLES.md TJS ⊇ JS violation** — and the suite is green on all four.

**Fix:** stop keying by text. Carry the parameter's source *position* (the offset of the `:`/`=` in the preprocessed source acorn parsed) or an owning-function identifier, so `scale`'s marker cannot reach `grow`, `bump`, or an arrow. `src/lang/param-sidechannel.test.ts` only pairs values that *differ* — add all four cases above.

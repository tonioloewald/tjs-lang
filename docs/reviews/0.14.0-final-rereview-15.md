## Blocker

### B-1. `vm.run` reads the options bag twice: once to validate, once to use (correctness + security, confirmed and reproduced)
- **Where:** `src/vm/vm.ts:210` calls `validateRunOptions(options)`. After that, the run reads the live bag again: `options.fuel` (279), `options.timeoutMs` (284), `argsMaxBytes` (361), and `snapshotTable(options.quotas / costOverrides / timeoutOverrides)`, `quotaUsed`, `membraneMaxBytes` and `maxHeapBytes` (457-467).
- **Failure (reproduced):** `get quotas(){ return m++===0 ? {ping:1} : {ping:NaN} }` passes admission. `ctx.quotas.ping` is then NaN, `used >= NaN` is never true, and 4 of 4 calls run under a quota of 1 with no error. A getter-backed `fuel` also gets past admission. The verifier saw partial containment ("Out of Fuel", but only after 1 call where the baseline allows 0, with `fuelUsed: NaN`).
- **Why it blocks despite the host-only threat model:** it contradicts the CHANGELOG line "Quota tables are checked over exactly what the VM reads", and it is the invariant re-review 14 blocked on ("the set a check walks must equal the set the read resolves"). The security skeptic's nit rating is noted and reasonable on exploitability, but the claim being shipped is false.
- **Fix (one fix closes B-1 and M-1):** admit the bag **once** at the top of `run()`:
  - Read each `RUN_OPTION_KINDS` key a single time through its own data descriptor, and refuse accessors, as `tableEntries` already does.
  - Validate those values.
  - Return a frozen record whose tables are frozen null-prototype objects built **from the `entries` `tableEntries` returned**, not by re-reading.
  - Everything downstream (`startFuel`, `timeoutMs`, `argsCap`, `ctx.*`) reads only that record.
  - As a second line of defence, check `quota` with `isBudget` at the read in the exec wrapper (`runtime.ts` ~2687), the way `quotaCount` checks the counter.
  - Tests: add rows for a getter-backed `fuel`, a getter-backed `quotas`, and a Proxy table whose descriptor changes between reads.
- **Re-review scope:** correctness + security over the `run()` prologue in `vm.ts`, `admission.ts`, and the exec-wrapper quota block, **including 0b253b9**.

## Major / minor findings

### M-1. `snapshotTable` re-reads the caller's table instead of freezing the checked entries (correctness + security, confirmed and reproduced; deduped)

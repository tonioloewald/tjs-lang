## Blockers

### B-1: The ref checker is UNSOUND; a stale tentative success is reused after its stack index is recycled (correctness; confirmed)
`src/lang/emitters/js.ts:~2147` (`__kRef` / `tent` / `low`).

**Repro:**
```
Type R { example: { a: A, b: B, bad: 0 } }
Type A { example: { r: R, e: E } }
Type E { example: { a: A } }
Type B { example: { e: E } }
Type Elem { example: { p: R } | { q: B } }
```
with `rv={a:av,b:bv,bad:'x'}`, `av={r:rv,e:ev}`, `ev={a:av}`, `bv={e:ev}`.

**Observed:**
- `B.check(bv)` is false, and so are `R.check(rv)`, `Elem.check({p:rv})` and `Elem.check({q:bv})`.
- `Elem.check({p:rv,q:bv})` is **true**.
- With the batch shape `Type U { example: { items: [R | K | B] } }` (`K={bad:''}`), `U.check({items:[rv,bv]})` is also **true**.

**Why it happens:** when A succeeds tentatively, its child E keeps `low` pointing at A's popped index 1. B is then pushed at that same index 1. B sees E in `tent`, decides it is a component root, and promotes itself to a permanent `yes`. R's later failure clears A and E but not B.

**Reach:** it needs cyclic in-process data, so JSON cannot reach it. It is still a wrong `true`, which the design's soundness claim rules out. The oracle missed it because it generates at most 3 types and 6 nodes and never puts object-shape unions at the top.

**Fix:** when a frame succeeds tentatively (`F.low < F.i`), re-lower to `F.low` every tl-range entry whose `low >= F.i`. Alternatively, key dependencies by frame identity or generation instead of by stack index. Then:
- pin both repros in `example-kinds-oracle.test.ts`;
- widen the generator (≥5 types, ≥10 nodes, top-level object-shape unions, a batch wrapper with 3-way unions);
- re-run at depth default, 2 and 1;
- demonstrate that the widened oracle finds this counterexample when the fix is reverted.

### B-2: A failed deferred pair re-runs the WHOLE outermost check. This is quadratic, and the 1e6 budget then rejects valid JSON (efficiency + correctness + security; three independent confirmed reports, merged)
`src/lang/emitters/js.ts:~2093–2148`.

**Mechanism:**
1. `__kFail` sets `S.redo`, and `__kVerify` returns after learning ONE failure.
2. `__match` kills the outer episode, which discards every `yes` memo, and re-walks from the root.
3. `S.work` counts only new `__kRef` frames. It does not count redo re-traversals or `dset` hits, and it accumulates across redos.

The result is k redos × O(n), which is quadratic. When the budget does trip, it rejects valid input.

**Reproductions (all plain JSON, no sharing, no cycles, so network-reachable):**
- **(a) Efficiency.** `Type T = { v: 0, kids: [T | { x: '' }] }` with a 128/129-node spine and k bad-via-first-alternative kids at the bottom. k=1000 takes 148ms and k=4000 takes 3.6s (4x input, about 24x time). One or two nodes off the boundary the same k runs in ≤4ms. k=8000 (about 250KB) takes about 11–15s and then returns a MonadicError for a **valid** value.
- **(b) Correctness.** `Type C { example: { next: C | null, k: 0 } }` and `Type Arr { example: { items: [C | { alt: 0 }] } }`, with m 200-deep chains that are valid via `alt`. m=100 takes 199ms. m=200 (about 609KB) is **rejected** ("A value too large to check against 'C' was REJECTED"). A control with only valid chains stays linear (2.4MB in 68ms).
- **(c) Security.** `Type T { example: A | B }` with `L = [T]`, K lists 129 or more deep that are valid as B. The time grows quadratically up to K=80 (292ms). K=160 (454KB) is **rejected** after about 0.37s of synchronous CPU, against a linear baseline of about 15ms. Depth 300 behaves the same (1.05MB rejected).

This contradicts the CHANGELOG's "time linear in the data" and reopens the M-1 class ("valid large payload rejected") that re-review 2 blocked on.

**Fix:**
- Don't restart the outermost check. Invalidate only the positives that depended on the failed deferral. For example, give each top-level array element or ref-frame root its own sub-episode, so a cascade stops at the nearest root. Or verify an element's deferreds before siblings reuse its success.
- At minimum, drain ALL pending deferrals per round, and charge redo re-traversal and `dset` hits against `__kBudget`.
- Add growth-ratio tests that assert both ACCEPT and a near-linear time or work ratio:
  - shape (a) at spine 127/128/129 with k=1000/4000;
  - shape (b) with m=50/200;
  - shape (c) with K=40/160;
  - stacked deferral boundaries (128 + 128 inside verification episodes).
- Add the "wrong alternative survives to deferral depth" shape to the oracle generator.

## Majors, to fix in the same remediation (not deferrable)

### M-1: A multi-line type expression is silently truncated at the first newline (correctness; confirmed)
`src/lang/parser-transforms.ts:~4244` (`readTypeExpression`), plus the `=` fallthrough at `~2911`.

**Observed:**
- `Type X {\n example: 'a'\n | 0\n}` gives `X.check(0) === false`.
- `example: { a: 0 }\n | { b: '' }` rejects `{b:'x'}`.
- `example: N\n | null` rejects `null`.
- `Type X = 'a' |\n 0` falls into the legacy regex, so **X is the number 0**. The same bitwise-OR defect appears with Prettier-style `Type X = 'a'\n | 'b'`.
- A leading `|` is a hard error.
- `Type X = { a: 0 } |\n { b: '' }` gives the misdirecting "declares no example…".
- `Generic { example: }` shares the reader, so it has the same exposure.

Nothing is recorded in any of these cases. This breaks the commit's own contract that "unreadable is an ERROR", and it is the B-1 defect class (silent truncation). fromTS emits single-line unions, so converted code is unaffected. Hand-written and Prettier-formatted `.tjs` is affected.

**Fix:** at a top-level newline, end the extent only if the text so far is one expression AND the next non-whitespace character is not a continuation (`| ? : . &`). After the example, require the start of another member or the end of the block, and raise a named error otherwise. When the `=` form cannot be read, throw the named error instead of falling through to the legacy regex or the block path. Add rows for a multi-line union (block, `=` and Generic), a trailing `|`, and a leading `|`.

### M-2: The test-only `globalThis.__TJS_KIND_DEPTH__` hook ships in every emitted module; a value ≤0 hangs every recursive check forever (security + blast-radius; confirmed; merged)
`src/lang/emitters/js.ts:2147`.

**Observed:** the hook is read with no lower bound and through the prototype chain. With depth ≤0:
- `__kRef` defers from an empty stack before it charges `S.work`;
- `__kVerify` re-enters and defers again, forever, and `__kBudget` never runs.

A 5-node `Node` list hangs (killed at 5–8s) with `globalThis.__TJS_KIND_DEPTH__ = 0` or `-1`, **or with only `Object.prototype.__TJS_KIND_DEPTH__ = 0`**. So a host prototype-pollution gadget turns every validated recursive call into a synchronous infinite loop.

**Severity:** the verifier graded this minor, because it needs a host-side trigger. It is triaged here as must-fix-now because it sits in the same checker being reworked, the fix is trivial, and it proves the budget does not bound every loop.

**Fix:** either inject the depth as a test-only transpile option, so production output carries a literal 128, or read it with `Object.hasOwn` and clamp it to an integer ≥1. Separately, charge `S.work` on the defer path. Add a test that 0, -1 and Object.prototype pollution all terminate and fail closed.

- **Bounds of `readTypeExpression` are unmeasured.** It runs `maskLiterals` over the WHOLE file for every `Type X =`, plus an acorn parse at each top-level `{`. That is potentially O(declarations × file size) on fromTS output. compat-scan skips files over 400KB. Measure transpile time on a many-alias file before re-review.

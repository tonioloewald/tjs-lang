## Blockers

### B1. The heap root model is incomplete: loop source arrays are unrooted and uncharged, and result growth is uncharged (CONFIRMED)
*`src/vm/runtime.ts` map ~3861, filter ~3920, reduce ~3965, find ~4040; alias rule in `setStateVar` (~2533). Merges the correctness and security blockers.*

- **Source array.** `resolvedItems = resolveValue(items, ctx)` is held in a JS local across nested guest execution. When an expression produces it, it is neither rooted (`holdRoot`) nor charged. Each item is bound `{ alias: true }` on the premise that the array is "already on the ledger or a program literal", which is false for a computed array.
- **Results.** `results` is a root now, but `results.push(...)` is never charged. The estimate never crosses the cap, so `reconcileHeap` never runs during the loop. A primitive `result` bind now estimates 0 bytes, because SLOT_BYTES moved the cost onto containers.
- **Reproductions** (`maxHeapBytes: 1_000_000`):
  - Recursive `['x'.repeat(4000000)+n].map(x => { h(n-1); return 0 })` with h(50) completes. At depth it holds +204MB RSS after GC, for about 40k fuel.
  - `[ 'x'.repeat(40000000) ].map(...)` holds about 41MB with no error.
  - Rebinding the parameter inside the callback leaves `resolvedItems` as the sole holder, about 83MB, which no reconcile can see.
  - `'x'.repeat(1e7).split('').filter(c => true)`, result discarded, completes {n:1} at 111k fuel and 884MB peak RSS. The bound variant is rejected only after the whole loop has run, at the same peak.
- This predates c6183d0 (it is identical at ef687cb), but it is exactly the audit rereview-4's B1 asked for. The REVIEWED ratchet wrongly certifies map/reduce as holding only results/acc.

**Fix direction:**
- `holdRoot(ctx, resolvedItems)` for the duration of map, filter, reduce and find.
- Charge `resolvedItems` once on entry, unless a ledger entry already references it (the O(1) bound-name case). Otherwise drop `alias` for its items.
- Charge each insertion into `results` (SLOT_BYTES plus a walk of the inserted value), as `accountMutation` does.
- Add transpile()-level rows under a 1MB cap that must FAIL inside the loop:
  - a recursive map over a fresh array, with and without rebinding the parameter;
  - a discarded filter/map over an expression-produced array.
- **Re-review scope:** security + correctness over the root/charge model (map, filter, find, reduce, alias rule), plus re-runs of cost-invariant, heap-scope and state-writes.

### B2. Allocation is not fuel-charged before it happens (CONFIRMED; latent, not a c6183d0 regression)
*`src/vm/runtime.ts` builtin `Array.from` ~1655; methodCall ALLOCATING_METHODS ~2878-2905.*

- `Array.from({ length: N })` has no per-element charge. `'from'` is not in ALLOCATING_METHODS.
  - Repro: length 3e8 under fuel 10 completes at 0.36 fuel, with 4.5s of synchronous CPU (the timeout cannot preempt it) and 7.6GB RSS.
  - Any length up to 2^32-1 is a host OOM.
- `.fill(v)` charges only the argument, not the array length: 1e8 elements cost 0.38 fuel and use 837MB.
- `repeat`, `padStart`, `padEnd`, `join` and `split` are charged after `fn.apply`, so the allocation already exists when Out of Fuel fires. `'x'.repeat(5e8)` reaches 531MB first.
- No capability is needed. This breaks the cost-invariant promise ("every step charges fuel ≥ c×work"), and the heap ceiling never sees an unbound intermediate.

**Fix direction:**
- Compute the size from the arguments before the call: the length/size for Array.from/of, the result length for repeat/pad/join/fill/split.
- Charge `ARRAY_FUEL_PER_ELEMENT × n` up front, and refuse if n exceeds the remaining fuel or heap headroom.
- Add cost-invariant rows for each of these with a tiny fuel budget; each must fail before allocating.
- **Re-review scope:** security + efficiency over builtin/methodCall charging, plus cost-invariant.

## Majors (must be fixed before the tag; both confirmed)

### M1. A `var` inside an arrow callback overwrites, or is refused by, the enclosing binding. REGRESSION in c6183d0
*`src/lang/emitters/ast.ts:518`, `hoistedVars` ~492. Merges the correctness and security findings.*

`hoistedVars` deliberately skips arrow/function-expression bodies, but `transformVariableDeclaration` sends every `var` to `transformVarAsAssignment`, which emits varAssign. That assignment walks out to the caller's scope.

| Case | HEAD | base ef687cb | JS |
|---|---|---|---|
| `let y=10; [1].map(x=>{var y=x;return y})` | y:1 | y:10 | y:10 |
| `const y=10; …map(x=>{var y=x})` | ERR "Cannot reassign const variable 'y'" | ok | ok |
| `var y=10; reduce((a,x)=>{var y=a+x;return y},0)` | y:3 | y:10 | y:10 |
| `map(x=>{if(x>1){var k=x} return k})` | [null,null] | [null,null] | [undefined,2] |
| `for (var x of [1,2,3]) {} return {x}` | {x:null} | {} | 3 |

These are silent wrong values on legal JS, which breaks AJS ⊆ JS (PRINCIPLES.md). The M2 table in `rc2-rereview-4.test.ts` covers only function and helper bodies.

**Fix direction:**
- Hoist per function boundary, including callback bodies (params excluded), so a callback's `var` is declared in the callback scope.
- Lower a `for (var x of …)` head as an assignment to the hoisted binding.
- If that is not tractable now, refuse `var` in callbacks and for-of heads with a TranspileError, which fails closed.
- Add all five rows to the M2 table / subset-invariant.
- **Re-review scope:** correctness + subset-invariant over emitter var lowering.

### M2. `callLocal` swallows a heap-limit or fuel failure from binding a helper parameter
*`src/vm/runtime.ts` ~3775-3790.*

- **Cause.** When `setStateVar(scopedCtx, param, …)` fails, callLocal does `return undefined`. That skips the `ctx.error = scopedCtx.error` propagation, which runs only after seq.exec. The run continues and reports success.
- **Reproductions** (under 1MB):
  - `h(Array.from({length:200000}))` returns `{after:'ran on'}` with `t` silently undefined. The inline control is correctly rejected. SLOT_BYTES (new in c6183d0) is what makes this reachable.
  - `let s='x'.repeat(400000); let t=h(s)` returns `{}`. The string is accepted alone, rejected only when it is also bound as a parameter (the unfixed per-name string over-count from rereview-4 M1), and that rejection is swallowed.
  - Recursive helpers return NaN.

**Fix direction:**
- Propagate on failure (`if (scopedCtx.error) ctx.error = scopedCtx.error`), or move the propagation into `finally`.
- Add rows where a parameter bind exceeds the cap; the run must fail with "Heap limit exceeded" and no later statement may run.
- Separately, decide on the string-per-name over-count: either count strings by value, or qualify the "no false rejection" claim in CHANGELOG/CLAUDE.md.

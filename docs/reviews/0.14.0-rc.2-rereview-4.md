## Blockers

### B1. The `map` atom's `results` array is not a heap root, so reconcile resets the estimate below live memory (security + correctness, verified)
`src/vm/runtime.ts:~3830`. `results` is a JS local inside the map atom, and it is never added to `ctx.heapRoots`. The callback scopes are released in `finally`. When a callback's bind crosses the cap, `reconcileHeap` walks only the registered roots plus the pending value, then sets `account.bytes = live`. That is a downward reset that forgets everything already accumulated in `results`.

The repro runs through `transpile()` plus `AgentVM.run` with `{maxHeapBytes: 1_000_000}`: `items.map(x => 'x'.repeat(100000) + x)` over 2000 items.
- **If the result is discarded**, the run returns `{n:1}`, with the host heap about 94 to 196MB higher.
- **If the result is bound**, the run is rejected, but only after all 2000 callbacks have run (about 161 to 168MB peak), and the error message reports "~1MB".

The exposure rate is about 10KB held per unit of fuel. The same shape exists in `filter`'s results. `reduce`'s accumulator was argued safe by one lens and flagged by the other, so audit it. The bug existed at e9c640b (86MB peak). cc7ccd1's reconcile now *actively* lowers the estimate below memory it cannot see, which contradicts the commit's claim that nothing refunds. The correctness lens found the same thing independently (deduped here).

**Fix:** register the in-progress `results` (map/filter) and the carried `acc` (reduce) as roots owned by the atom for the length of the loop, removing them in `finally`. Audit every atom that holds guest values in a JS local across a nested `seq.exec`, and consider a structural check for that in `heap-roots.test.ts`. Add transpile()-level rows under a 1MB cap, both of which must FAIL *inside* the map: the unbound `items.map(...)` statement and a block-bodied callback.

### B2. estimateBytes charges 0 bytes for null/undefined slots and for repeat references (security, verified; existed at base)
`src/vm/runtime.ts:~2176`. These two checks skip a slot without charging it, and array elements carry no per-slot cost:
- `if (v === null || v === undefined) continue`
- `if (seen.has(v)) continue`

Repro: `keep.push(Array.from({length: 4000000}))` ×10 under a 1MB cap returns `{n:10}`, with a host heap about 256MB higher, for about 40k fuel. `.fill(sharedObj)` gives the same result (about 242MB). The control, `.fill(0)`, is rejected after about 252 fuel. cc7ccd1 made reconcile the ceiling's actual measurement, so this undercount is now the ceiling's own blind spot. It is the same class as the rc.2 third re-review's B1.

**Fix:** charge a slot cost (about 8 bytes) for every array element and property value *before* the null/undefined/seen short-circuits. The node count is unchanged, so the walk's fuel is unchanged. Add a row with `Array.from({length: N})` under a small cap that must fail. Confirm that the cost-invariant tests still hold for the heap-walk fuel per node.

## Majors (fix in the same remediation, before re-review)

- **M1. Reconcile over-counts, so "no false rejection" is false (correctness, verified; new regression for rebinds).** `trackHeapWrite` calls `chargeHeap(..., [value])` *before* the write. The walk therefore counts the old binding, still in its root, plus the pending new value.
  - Measured under a 1MB cap: `s = s.slice(1) + 'a'` at 270k chars, `s = s + 'a'` at 300k chars, and `a = a.concat([...])` are all **rejected at HEAD and pass at e9c640b**. Only about 540 to 600KB is live. Immutable-update loops now run under about half the cap.
  - Strings are counted again for every name that reaches them, because `seen` is a WeakSet. `const big = 'x'.repeat(300000); const y = big` is rejected with "~1MB" when about 600KB is live. This existed at base, but the message now presents the inflated figure as the true measurement.
  - **Fix:** measure with the slot being written excluded (write, reconcile, roll back on failure; or skip the replaced value). Add a no-false-rejection row for the program above. Qualify the claim of a "true live" figure, or count large strings by value, but only after checking that doing so does not open an escape.
- **M2. `var` inside a v2 if/else/try/catch is now silently block-scoped (correctness + security subset invariant, verified; new in cc7ccd1).** At `src/vm/runtime.ts:3255`, `runBlock` gives every v2 block a child scope, and the emitter lowers `var` the same way as `let`. Examples:
  - `if (true) { var q = 5 } return {q}` now gives `{}`.
  - `var v = 1; if (true) { var v = 2 } return {v}` gives `{v:1}`, where JS gives `{v:2}`.
  - `try { var z = 1 } catch(e){}` drops `z`.

  There is no error, so the wrong value is silent, and this breaks AJS ⊆ JS (PRINCIPLES.md). The `while`-body variant predates this commit and has the same root cause. Two lenses reported this; the findings are merged here. **Fix:** refuse `var` in `transformVariableDeclaration` with a TranspileError that points to `let`/`const`, which matches `guides/ajs-llm-prompt.md`, or hoist it with `varAssign`. Add var-in-if/try/while rows to subset-invariant or transpiler-integration.

## Follow-ups

### → this repo (`TODO.md` / Virta cards): correctness, efficiency, blast-radius
- [ ] **(efficiency, verified, minor)** A v2 if/else/try body now always calls `createChildScope` + `releaseScope`. Over 20k iterations, wall-clock goes from 36ms to 73ms for if/else and from 37ms to 66ms for try/catch, with identical fuel, so this is uncharged host work. Create the scope only when the block declares something: a catch `bind`, varSet/constSet/varsLet/varsImport, or a step with a `result`. Decide that statically and cache it in a WeakMap keyed by the steps array. Add an if-in-loop benchmark row. Re-run the M2 shadowing tests (rereview-2 B1) after the change.
- [ ] **(efficiency, unverified, minor)** Near the cap, almost every bind triggers an O(live) reconcile walk. In the reported measurement this gives about 175 fuel/ms against about 900 fuel/ms for ordinary execution, roughly 5x the host CPU per unit of fuel. It is bounded and fails by fuel. Options: make the reconcile threshold geometric, or recalibrate the per-node walk price. Add a near-cap rebind loop to the cost-invariant or benchmark set so the CPU/fuel ratio is printed.
- [ ] **(efficiency, unverified, minor)** The build still prints absolute bundle sizes with no delta. `vm-ast` grew by 400 B raw / 151 B gzipped this round, and the growth is unreported. This repeats the open rc.2 item at `docs/reviews/0.14.0-rc.2-pre-release-review.md:81`. Add a delta column to `scripts/build.ts` and one size line to the rc.2 CHANGELOG entry.
- [ ] **(blast-radius, unverified, nit)** `DOCS-AJS.md:~996` documents `createChildScope` for embedders but not `releaseScope`. A scope that is never released now stays a heap root for the rest of the run. That fails closed, by false rejection. Add one sentence about releasing it.

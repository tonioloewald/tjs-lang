## Fixed before the tag

- **Major (verified): AJS accepted `x: '' || null` as a parameter annotation while TJS refused it**, breaking TJS ⊇ AJS (and rejecting null at run time, the #3148 bug). Fixed in the AJS emitter (`emitters/ast.ts`, the transpiler, not the VM). Rows: `subset-invariant.test.ts` "what TJS refuses, AJS refuses" (parameter and destructured).
- **Minor (verified): `x?: '' || null` was not refused** (`?:` is rewritten without a marker). Checked on the raw text where `?:` is rewritten (`parser-params.ts`), for TJS and AJS. Row: `type-or.test.ts`.
- **Minor: the error was located by the first textual match**, so an earlier string containing the same text took the location. Now located by the node's position (parameters) and the annotation's start (returns). The AJS message quoted the wrong characters (its node offsets are into the rewritten source); it now prints the annotation from the node. Rows: `type-or.test.ts`.
- **CHANGELOG wording**: a `||` default is still JavaScript, but its type is read from the left side, so `x = '' || null` rejects its own default; the entry now says so and names `x = '' | null`.
- **Red test**: the stale-`dist/` freshness check cleared after `bun run make`; `test:fast` 0 fail.

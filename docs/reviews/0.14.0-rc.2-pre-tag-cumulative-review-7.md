## Blocker

### B-1. The IO input-schema regex refusal fails open on a RegExp-object `pattern` (CONFIRMED, security, major)

`src/vm/runtime.ts:4867-4900` (`admitIoInputSchema`, the check at ~4887).

- **What happens:** the walk refuses a node only when `typeof n.pattern === 'string'`. A RegExp value has no own enumerable entries, so the walk sees nothing to refuse. tosijs-schema's `validate` does `if (o.pattern) new RegExp(o.pattern, …).test(value)`, which accepts a RegExp object.
- **Reproduced on HEAD with transpile() output:**
  - `defineAtom('probe', {type:'object', properties:{x:{type:'string', pattern:/^(a+)+$/}}}, …, {effects:'io'})` is admitted with no error.
  - `probe({x:'aaaa'})` passes validation; `probe({x:'aaaab'})` is refused "does not have the shape the atom declares".
  - An instrumented `RegExp.prototype.exec` counted one host exec per guest call.
- **Impact:** with a catastrophic pattern and a long guest string, validation hangs synchronously and neither fuel nor the timeout can stop it. That is the exact door the rule is documented to close.
- **Mitigations:** the regex is written by the host, not the guest. The builder forms (`s.pattern(/re/)`, `.pattern(re)`) convert to `.source` and are caught. Only a hand-written plain-JSON schema gets through.
- **Fix:**
  - Refuse when the keyword is present at all: `n.pattern !== undefined || n.patternProperties !== undefined`.
  - Add rows to `io-atom-schema.test.ts` for `pattern: /re/`, `pattern: { toString(){…} }` and a nested builder value.
  - Mutation-check the walk at nested positions: `items`, `anyOf`, `$defs`, `additionalProperties`.
  - The apparatus row already runs every core and battery schema, so confirm none is caught by the wider check.
- **Re-review scope:** correctness + blast-radius + security over the remediation diff only.

### Same remediation pass, must ship with B-1: double billing of a heap-refused egress (CONFIRMED, correctness, minor)

`src/vm/runtime.ts:4767-4804` (`egressValue` `refused()`) together with `allocate` (4076-4097).

- **What happens:**
  - `allocate`'s reconcile branch first charges `bytes * FUEL_PER_ALLOCATED_BYTE`, then runs `reconcileHeap` (also charged), then throws `heapLimitError`.
  - `egressValue` then bills the whole pre-walk `budget = min(cap, payable)` again, and that budget was sized from fuel the run no longer has.
  - The comment at 4798 ("refuses ... before charging anything") is true only for the `bytes > ceiling` branch.
- **Reproduced at both commits:** a `try { storeSet(...) } catch` over 20,000 objects with maxHeapBytes 1.2 MB.

  | Fuel granted | Base `aa908aa` | HEAD |
  |---|---|---|
  | about 200 above the real cost | `{refused:1}` | "Out of Fuel" (op `catch`), `fuelUsed` greater than the fuel granted, real cause hidden |
  | more than that | `{refused:1}` | `{refused:1}`, about 210 more fuel charged |

- **More generally:** whenever `payable < cap`, any refused egress (depth, function, class instance, heap) drains the run to zero and reports "Out of Fuel" instead of its reason.
- **Why it ships with B-1:** overcharging is the safe direction, so this does not break a safety bound. But "fuel used never exceeds fuel granted" is an invariant, and the round-32 plan said "Out of Fuel" only when the walk actually stopped at a fuel-bound budget.
- **Fix:**
  - Bill only the bytes walked that have not already been charged. The walk reports `bytes`, and `allocate` already charged its part.
  - Or bill from `ctx.fuel.current` at throw time and floor fuel at 0.
  - Raise "Out of Fuel" only when the walk stopped at a fuel-bound budget.
  - Add a transpile() row: a heap-refused copy caught in `try`, with fuel just above (real walk + base), must return the catch result, and `fuelUsed <= fuel` must hold.

## Round 33 — plan (written before any code, per the cycle STOP)

**The underlying problems:**
1. **We screened a live host object, then used it.** `admitIoInputSchema` inspected the
   host's schema in place, recognised `pattern` by its type (a string), and the call path then
   validated against `atom.inputSchema`, the same live, mutable object. It is the "admitted is
   not forwarded" class again, this time for a schema. The fix is the one that held for URLs and
   messages: **own a canonical copy**. At admission the IO input schema becomes plain JSON. Any
   non-JSON value (a RegExp, a function, a class instance, a getter) is refused, not converted.
   A `pattern`/`patternProperties` keyword is refused if it is PRESENT, whatever its type. The
   frozen copy is what every call validates against, held where the atom object cannot reach it
   (a WeakMap). An IO atom with no admitted copy at call time is admitted then: this covers
   retagging after construction. If admission fails, the call is refused.
2. **The bill was an estimate kept apart from what was already charged.** Round 32 charged the
   whole budget on top of `allocate`'s own charge, so fuel used could exceed fuel granted, and any
   refusal under low fuel read "Out of Fuel". The bill should be **the work done, reported on
   every exit, enforced by the type**. A failed `MembraneResult` REQUIRES `walked: number`, so a
   return site that omits it does not compile. `egressValue` charges `walked` minus what
   `allocate` already charged for this crossing. It never charges more than the fuel present at
   entry, and says `Out of Fuel` only when fuel actually reaches zero.

**Steps:**
1. `MembraneResult` failures carry `walked`, and `membraneValue`, `readArrayData`, `readOwnData`
   and `overBudget` report it. Over budget, `walked` is the budget, since the walk stops there.
   `egressValue` tracks `charged` in the admit hook and bills `max(0, walked − charged)`.
   - Rows: a heap-refused copy in try/catch with fuel just above the real cost returns the catch
     result, with `fuelUsed ≤ fuel`; each refusal kind under low fuel keeps its own message.
   - The weak transpile row gets a threshold that removing the billing fails (mutation-checked).
2. `admitIoInputSchema` returns a frozen canonical JSON copy: builders unwrapped at any depth,
   non-JSON values refused by name, regex keywords refused when present.
   - `ioSchemaOf(atom)` (a WeakMap, admitting lazily) is the one place `egressInput` reads a
     schema.
   - Rows: `pattern: /re/`, `pattern: { toString }`, a nested builder, a RegExp under `items`,
     `anyOf`, `$defs` and `additionalProperties`; the host mutating `atom.inputSchema` after
     definition changes nothing; an atom retagged to io later is admitted (or refused) at its
     first call.
3. **Formats were checked:** tosijs-schema's built-in `format` validators are linear (fixed anchored
   regexes; `email` is a hand-written scan, `uri` uses the URL parser) over input already paid
   for, so they stay allowed. The reason is recorded in the code. A `$predicate` in an IO schema
   is a trusted-only path that fails closed.
4. **Docs:**
   - vm-budgets.md and the CHANGELOG describe the billing as built;
   - review-lenses.md lens 10 gains "a refusal's bill never depends on its reason or outcome";
   - the CHANGELOG gets a migration snippet (`undefined` becomes `s.object({})`) and a note that
     persisted ASTs with key-less `memoize`/`cache` now fail.
5. **Upstream, held for Tonio's go (it posts to another repo):** a tosijs-schema issue for an
   injectable pattern engine (`setPatternEngine`), which would let the ban lift. Its card names the
   ban as the workaround.
6. **Cards:** check embedders (snowfox-app, lukko, service-compris, tosijs-ui `site/entry.ts`) for
   schema-less or `pattern` atoms before tagging, and a build-time size delta (joins #2848).

## Round 33 — implemented (2026-10-04)

- **Billing is the work done, enforced by the type.** A failed `MembraneResult` REQUIRES
  `walked`, and every refusal path in `membraneValue`, `readArrayData`, `readOwnData` and
  `overBudget` reports it (a path that does not cannot compile).
  - `egressValue` bills `walked` less what the crossing has already spent since entry. It never
    charges more than the fuel present (floored at 0), and says `Out of Fuel` only when fuel
    reaches zero.
  - Rows:
    - per refusal kind, billed what it walked and not the budget, and keeping its own reason
      under low fuel;
    - a heap-refused copy caught with 5 fuel to spare returns the catch result, with
      `fuelUsed ≤ fuel`;
    - refusing costs +40 fuel over accepting the same copy (the reconcile walk), where the
      double bill cost +74.
  - Mutants caught: no billing, the round-32 whole budget, the double bill, walked not reported.
  - Not caught: the floor at zero. That is an equivalent mutant, because the walk budget is
    capped by entry fuel so the bill cannot exceed what is left; the floor is a backstop.
- **The IO input schema is an owned copy.** `admitIoInputSchema` returns a frozen plain-JSON copy:
  - builders are unwrapped at any depth;
  - a RegExp, function, class instance, accessor or cycle is refused by name;
  - `pattern`/`patternProperties` are refused if PRESENT, at schema positions only (map names and
    data keywords are not keywords);
  - writes go through `setGuestKey`.
  - `ioSchemaOf(atom)` (a WeakMap) is the only schema `egressInput` validates against. An atom
    tagged io after definition is admitted at its first call, and refused if it cannot be.
  - Rows: `pattern: /re/`, a toString object, a RegExp under items/anyOf/$defs/
    additionalProperties, a nested builder, non-JSON values, a cycle, swapping
    `atom.inputSchema` after definition (no effect), and late retagging.
  - Mutants caught: string-only check, validate live schema, no lazy admission, non-JSON
    converted, builders not unwrapped, no cycle check. The cycle row first passed falsely,
    because the atom was NAMED `cyclic`, so `/cyclic/` matched the name. Renamed, and now caught.

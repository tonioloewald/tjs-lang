## Blockers

### B1. Schemas inside the guest AST run `pattern` (and `$predicate`) on the host engine, before or outside budgets (confirmed; correctness and security, deduped)

- **`return` step**: `src/vm/runtime.ts:4599` calls `schemaFilter(res, step.schema)` on the guest's schema.
  - Repro: a v1 AST `varSet x = 'a'×n+'!'` followed by `return {schema:{properties:{x:{type:'string',pattern:'^(a+)+$'}}}}`, run at `fuel:10, timeoutMs:50`.
  - Measured 6 / 61 / 246 ms at n = 20 / 24 / 26 (exponential). Neither fuel nor the timeout fires.
- **`ast.inputSchema`**: `src/vm/vm.ts:396-397` calls `validate(args, ast.inputSchema)` before any fuel, timeout or abort controller exists.
  - Measured 5 / 18 / 67 / 133 ms at n = 20 / 22 / 24 / 25, with fuelUsed 0. With `^(\w+\s?)*$` it hangs on benign host arguments too.
  - `tjs-lang/vm-ast`, the recommended VM, has this door as well.
  - If a global evaluator is registered, a `$predicate` key reaches it, and through it the bypasses in B2. That `$predicate` sub-path was not exercised separately.
- `assertNoGuestPatterns` (runtime.ts:2832) guards only the Schema.* method and argument paths (2781/2803). `regex-doors.test.ts` cannot see either site, because the compile happens inside tosijs-schema.
- **Fix:** add a shared `admitSchema` and apply it to every schema that comes from the AST (`inputSchema` at admission, `return`'s `step.schema`, any other step schema). It must refuse guest `pattern`, and also refuse `$predicate` unless that is metered and charged to the run. Enumerate every `validate(`/`schemaFilter(`/`filter(` call in `src/vm/**` as a listed door in the doors test. Add rows for both repros, on both `tjs-lang/vm` and `tjs-lang/vm-ast`.

### B2. The predicate verifier certifies host `RegExp` and String pattern methods used as values, and tagged templates (confirmed; correctness and security, deduped)

Each of these returns `verifyPredicate` safe: true and compiles `'(a+)+$'` with the host engine at fuel 1000:
- `['(a+)+$',''].reduce(RegExp).test(s)`: 8 / 127 / 384 ms at n = 20 / 24 / 26.
- `['(a+)+$'].map(String.prototype.match, s)[0] != null`: 13.5 / 53 / 211 ms at n = 20 / 22 / 24.
- `['(a+)+$'].some(s.match, s)`
- `Array.from(['(a+)+$'], s.search, s)`
- ``s.match`(a+)+$` ``: a TaggedTemplateExpression, which the CallExpression visitor never sees.

`emitVerifiedPredicate` certifies all of these too. They are reachable from untrusted data:
- `tjs-lang/schema` `validate(v, {type:'string', $predicate})`: 56 / 202 / 606 ms at n = 22 / 24 / 26.
- An AJS `Schema.isValid` call with `timeoutMs:5`: 122 ms at n = 24.

This is rereview-11 B1 reached through different syntax. The redos-lint promise that a verified predicate fails closed on ReDoS and halts within fuel is still broken.

**Fix:** close the surface on references, not calls.
- Refuse any free identifier that is not a local, another predicate, or in PURE_GLOBALS/PURE_NAMESPACES. That refuses `RegExp`, `Function`, `Reflect` and `Symbol` as values.
- Refuse `.prototype` reads.
- Refuse any member naming a String/RegExp pattern method (match, matchAll, search, replace, replaceAll, split, exec, test) except as a callee whose first argument passes `isRegexValue`.
- Refuse TaggedTemplateExpression.
- Defense in depth: shadow `RegExp` in `compileVerified`'s parameters.
- Add one redos-lint row per form, plus rows through `createPredicateEvaluator` and `emitVerifiedPredicate`.

### B3. The "regex const declared exactly once" rule ignores class names and does not resolve scope (confirmed; correctness, with security form 6 deduped)

- `const r = /a/` followed by `function p(s) { class r { static toString() { return '(a+)+$' } } return s.match(r) != null }` is safe: true. It ran 13 / 53 / 215 / 428 ms at n = 20 / 22 / 24 / 25 at fuel 1000.
- The `declarations` counter (around predicate.ts:347-375) omits ClassDeclaration and ClassExpression ids.
- The rule counts names across the whole source. So a const local to one function "validates" `r` in another function, where at runtime `r` resolves to a global.
- **Fix:** resolve the identifier through the existing scope machinery (`declared`/`isLocal`). Its binding must be a `const` declarator with a regex-literal init, found in an enclosing scope. At minimum, count class ids and refuse an identifier that has no binding in scope. Better still, refuse classes in predicates outright: `new` is already banned, so a class can only be used for shadowing. Add rows for the class-shadow case and the out-of-scope case.

## Majors (do not block alone; must land in this cycle)

### M1. HostRegex's meter and program can be overwritten by the predicate (confirmed; correctness and security, deduped)

`src/lang/predicate-regex.ts:38` declares `private readonly re, m`, which is TypeScript-only. At runtime they are writable own properties.
- `r.m = { steps: Math.abs, alloc: Math.abs }` verifies as safe. At fuel 1000 it ran 313 ms on 1e6 characters and 2.9 s on 1e7 characters. The control without the override throws PredicateFuelExhausted in about 1 ms.
- `r.re` can be swapped the same way (not exercised).
- **Fix:** use `#re`/`#m` private fields or closure capture, and seal the instance apart from `lastIndex`. Optionally also have the verifier reject writes to a regex-literal binding. Add a redos-lint row asserting that the override has no effect.
- Separately, consider charging native amplifiers (`repeat`, `padStart`, `padEnd`, `join`, `split`) in predicates.

### M2. `regex-doors.test.ts` cannot see the doors that are open, so "closed set" is not enforced (confirmed; correctness and security, deduped)

- It matches only bare `compileRegex(` / `RegExp(` / `new RegExp` in `src/vm/**` and `lang/predicate*`. It passes green (4/4) while B1, B2 and B3 are all open.
- It is blind to:
  - tosijs-schema's internal `new RegExp`
  - `globalThis.RegExp`, `Reflect.construct`, an aliased constructor, or `re.constructor`
  - `.match`/`.search`/`.matchAll` called with a non-literal argument
  - `compileRegex` reached through an alias or namespace import
  - guest-source forms
- `COMPILE_SITES` verifies meters by argument count only, so a no-op meter passes.
- **Fix:**
  - Add a behavioural apparatus. Replace `globalThis.RegExp` with a counting Proxy, spy on `String.prototype.{match,search,matchAll}` for non-RegExp arguments, and fail on any host compile attributable to guest input. Run it over the B1/B2/B3 corpus.
  - Widen the static scan to flag `RegExp` references and listed tosijs-schema `validate`/`filter` imports.
  - Mutation-check: reintroduce each door and confirm the test goes red.
  - Narrow the header claim until all of this holds.

### M3. The global `$predicate` evaluator holds unbounded host memory across runs, and compile work is not charged (confirmed; security)

- `createPredicateEvaluator` (predicate.ts around 1098-1135) caches every distinct source forever, in both `cache` and `warned`.
- With `tjs-lang/schema` imported, an AJS run looping `Schema.isValid('x', {type:'string', $predicate: src_i})` over 200 distinct sources used about 160 fuel per run. Heap grew about 13 MB per run after GC with no ceiling (RSS went from 70 MB to 272 MB over 12 runs; the reviewer measured 317 MB per run with a heavier shape).
- Predicate verify/compile work (a 250k-unit floor) and predicate fuel (1M per call) are never charged to the run's fuel, heap or timeout.
- **Fix:** make the cache an LRU bounded by `Compiled.bytes` and entry count, and bound `warned` too. Refuse `$predicate` in guest schemas in `assertNoGuestPatterns`/`admitSchema` (ties into B1), or compile it under the run's meters. Add an RSS row that runs the repro twice.

## Minors

- **m1. The compile budget amplifies memory: about 1–2.6 KB of RSS per source byte, up to 12.8 KB/byte charged** (confirmed; correctness and security, deduped). `RegexCompiler` derives memory from work (`BYTES_PER_WORK = 64`, regex.ts:228/946).
  - A 104 KB AJS source took about 200 ms and grew RSS by about 262 MB before refusal.
  - A 405 KB `$predicate` verify grew RSS by 279–486 MB.
  - `$predicate` sources have no size cap. The VM run path is unaffected.
  - **Fix:** document the derived bound in docs/vm-budgets.md, or add a separate byte budget proportional to the source, and/or a source-size cap on `createPredicateEvaluator`/`compilePredicateSchema`.
- **m2. (unverified) The build prints no per-bundle size delta against the base** (efficiency). `scripts/build.ts:250`.
  - Measured this round: vm-ast +315 B (+146 gzip), vm +292 B (+134 gzip), css +1,234 B (+435 gzip). The growth is justified.
  - The README's 10% tolerance can absorb many rounds of growth before anything fails.
- **m3. (unverified) A string-literal pattern to `match`/`search`/`matchAll` in a predicate is now refused** (blast-radius). `predicate.ts:486`.
  - A persisted `$predicate` such as `s.search('@')` will throw on upgrade. It fails closed and the CHANGELOG mentions it.
  - **Fix:** lower a string literal through the same metered `__rx` path as a regex literal, and refuse only non-literal arguments. If you keep the refusal, add a migration line to the CHANGELOG.

## Remediation plan (round 8), written before acting

**Root cause, two parts.**

1. *VM:* schemas carried by the guest AST (`inputSchema`, a `return` step's schema) reach
   tosijs-schema, which compiles their `pattern` on the host's engine. The VM's own doors were
   closed; a library's were not listed.
2. *Predicates:* verified predicates compile to native JavaScript, and the verifier is a
   syntactic screen over full JavaScript. JavaScript has unbounded routes to its own regex engine
   (values, prototypes, tagged templates, classes, scope, writable fields). A denylist over it
   does not converge: four rounds each found more syntax.

**Decision (Tonio, 2026-10-02): separate predicates by who wrote them.** Untrusted predicate
source (`$predicate` arriving as data) is REFUSED, failing closed, unless the host explicitly
opts in. Running untrusted predicates on the AJS VM, whose surface is a closed, enforced table, is
the follow-up that lifts the restriction safely. Trusted source (an author's own `Type`
predicates, `tjs-lang/css`) stays native: an attacker cannot choose its patterns, and input ReDoS
is covered by lowering literals onto the linear engine. Verification is a guarantee an author
gets about their own code, not a sandbox for hostile code.

**Changes:**

- **A. VM schema admission.** One `admitGuestSchema` for every schema from the AST — admission
  (`inputSchema`), the `return` step, and every other step schema — refusing `pattern`,
  `patternProperties` and `$predicate` at any depth. The schema doors are listed in the doors
  test.
- **B. Trusted predicate sources only.** `createPredicateEvaluator` and the `$predicate` schema
  paths refuse a source unless it is trusted: registered with `trustPredicate(source)` (the
  library's own builders, e.g. `tjs-lang/css`, register theirs) or the host passes
  `trustAllPredicates: true`. Fails closed, through `onUnsafe`.
- **C. Doors test, behavioural.** A corpus of guest attacks run with `globalThis.RegExp` and the
  String pattern methods instrumented: no guest-chosen string may reach the host engine. Header
  claim narrowed to what is enforced.
- **D. Hardening that stays useful on the trusted path:** `HostRegex` fields become `#private`;
  the evaluator cache is a bounded LRU; string-literal patterns are lowered onto the engine
  instead of refused (fixes the blast-radius minor).
- **E. Docs:** what "verified" promises; the compile-memory bound; CHANGELOG migration lines.

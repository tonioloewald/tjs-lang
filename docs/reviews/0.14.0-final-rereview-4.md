## Blockers

### B-1: `vm.run(sourceString)` transpiles unbounded source before option validation and before any budget *(verified; correctness + security, merged)*
`src/vm/vm.ts` ~L192–215. The string branch calls `transpileImpl(astOrToken)` with no size check. That runs before the new option-validation loop, the 4MB argument cap, fuel and the timer. `tjs-lang/vm` is documented as accepting SOURCE, so this is a supported entry path with **no** bound, unlike Eval/SafeFunction (`checkSourceSize`) and runCode/transpileCode (`admitSource`).
- Measured with `fuel: 'abc'`, which should be refused cheaply: 64KB took 240–508ms, 250KB 2.5s, 500KB 8.3s, 600KB 14.4s. Blank-line shapes: 20KB took about 10s. Only after that came "Invalid run option fuel".
- `tjs-lang/vm-ast` (AstVM) is not affected.
- **Fix:** validate options *above* source resolution. Apply the shared length-first byte cap (`checkSourceSize`/`DEFAULT_MAX_SOURCE_BYTES`, overridable by a `maxSourceBytes` run option) before `transpileImpl`. Add a test that oversized source is refused in under 100ms with the transpiler never reached. The cap only bounds cost once B-2 is fixed.

### B-2: The 64KB source cap does not bound pre-fuel transpile work, because `transformParenExpressions` is quadratic *(verified; security)*
`src/lang/parser-params.ts:205`. Doubling the input quadruples the time: 4KB 299ms, 8KB 1.18s, 16KB 5.0s. At the cap, 64KB of line comments took 54.5s and 64KB of nested parens 44.5s.
- `Eval({ code: '1 +\n' + '// pad\n'.repeat(4571) + '1', fuel: 10, timeoutMs: 1 })`, which is 32KB and under the cap, took 21.7s and reported **fuelUsed 0.33, no error**.
- Any signed-in account can reach this through the `agentRun` callable and the `run` REST endpoint, which pin a Cloud Functions instance for about a minute. SafeFunction, RBAC rule code and runCode/transpileCode via `admitSource` are affected too.
- The `eval.ts` comment that 64KB "transpiles in well under a tenth of a second" is false for hostile shapes. The M-1 test only checks that 140KB is refused. Nothing tests the worst shape *at* the cap.
- **Fix:** profile with `bun --cpu-prof` and remove the super-linear step, probably a rescan of the whitespace/comment run or a growing `result +=`. Add hostile-shape tests at the cap through Eval and runCode (64KB blank lines, `//` lines, nested parens) with a small wall-clock bound, and correct the `eval.ts` comment. If the parser can't be made linear before release, lower the caps until the measured worst shape is under about 100ms, and record that measurement. Keep `literal-blindness` and `param-markers` differential suites green.

## Majors (non-blocking but should land before the tag)

### M-1: The argsMaxBytes default dropped from 64MB to 4MB, but Eval/SafeFunction cannot raise it *(verified; blast-radius)*
`src/lang/eval.ts:279` and `:363` call `vm.run` without `argsMaxBytes`, and neither options type exposes it. The CHANGELOG's advice, "raise `argsMaxBytes`", cannot be followed from the public safe-eval API. Released 0.13.x had no argument cap at all, so this is a regression on upgrade. Strings count 2 bytes per character, so the real ceiling is about 2M characters (a 3MB string is refused).
- **Fix:** add `argsMaxBytes?` to EvalOptions and SafeFunction options and pass it through, keeping the 4MB default. Add a CHANGELOG line, and document the 2-bytes-per-character accounting.

### M-2: verify-shipped is untested, and a stale attestation fails with a message that blames the build *(verified; correctness; blast-radius duplicate merged)*
`../tosijs-coding-practices/tools/attest.ts:78`. `verifyShipped` never checks `att.version` or `att.tree`. Once one attested release is committed, the recommended pre-tag `dry_run` on main (publishing-via-oidc.md step 0) fails with "this build does not reproduce the attested one … differs: package.json, dist/…". That points at nondeterminism when the real cause is "attestation is for 0.14.0, package.json is 0.14.1". Nothing tests `shippedManifest` or `verifyShipped`. This fails closed, so it cannot let a bad build ship.
- **Fix (shared repo, see routing):** check version and tree first, reusing verifyAttestation's check, and name staleness explicitly. Add a scratch-repo test covering identical, differs, extra, missing, stale version, and no `shipped` field.

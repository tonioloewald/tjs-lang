## Blockers

### B1. A host's own `fetch` capability now receives the guest's raw Host, Cookie, X-Forwarded-* and method (security, CONFIRMED; filed as major and treated as blocking)
- **Where:** `src/vm/runtime.ts` around lines 6387-6416. At `bfa16a4`, `admitHeaders` and the method check ran before `if (ctx.capabilities.fetch)`. At HEAD, only `refuseDepthHeader` runs before that branch.
- **Why it matters:** the canonical host shapes forward `init` unchanged:
  - `guides/safe-eval.md` around lines 70-90: `safeFetch = (url, init) => { check host; return fetch(url, init)… }`
  - the `SafeCapabilities.fetch` JSDoc in `src/lang/eval.ts` around lines 71-75
  - README line 92
  - `createSecureFetch` in `guides/patterns.md`

  On top of that, `patterns.md:147` tells production users to *always* provide a custom fetch, which steers them off the hardened built-in client and onto the least-guarded path.
- **Reproduced:** a scratch Bun probe called `Eval` with the documented `safeFetch` against a local `Bun.serve`. The server received `PROPFIND`, `host=internal-admin.local`, `cookie=sid=1` and `xff=10.0.0.1`. Behind a Host-routing proxy, a guest allowed only one domain can reach virtual hosts outside the allowlist. Fetch's defaults (`redirect: 'follow'`, same-origin credentials) also apply to this shape. That part predates the diff and is not documented.
- **Why it is not just the chosen option:** rereview-4 chose option 1 (allowlist on the built-in path only), but with "possibly a framing-header guard on both paths". No such guard was added. The carried item "document what a custom fetch does not get" is still unchecked. The only new test row pins the open behaviour with a stub that never reaches a wire.
- **Fix: pick one and record the decision in the review doc.**
  - **(a)** Keep a small wire-level guard on BOTH paths, next to `refuseDepthHeader`, covering Host, Content-Length, Transfer-Encoding, Connection, Upgrade, TE, Trailer, Proxy-*, Forwarded and X-Forwarded-*. Also refuse CONNECT, TRACE and TRACK on both paths. Hosts that really need these can use `defineAtom`.
  - **(b)** Rewrite every host-fetch example so it never forwards `init` blindly. Build method and headers from an allowlist, pass `redirect: 'manual'` and `credentials: 'omit'`, and say in each place that `init.method` and `init.headers` are guest-controlled. Fix `patterns.md:147`.
  - **Either way:** add a row that runs the *documented* `safeFetch` against a real `Bun.serve` and asserts that a guest `Host` does not arrive. Fold in the method-case finding below by computing `verb` before the branch.
- **Re-review scope:** security plus docs/dx over the remediation diff, plus `src/doc-snippets.test.ts`. Per the STOP, that is a cumulative httpFetch pass against `v0.14.0-rc.1`, not another one-commit delta.

## Diagnosis (filed before acting; HELD for Tonio)

Round 24 applied the header and method allowlists to the BUILT-IN client only, treating admission
as a property of the TRANSPORT. It is a property of the agent's REQUEST. What an agent may ask
for does not depend on who sends it, and the documented host `fetch` patterns forward the agent's
`init` unchanged. Proposed: one admission of the agent's request (method, headers) on EVERY path,
and a host that needs more DECLARES it (`allowedRequestHeaders`, and likewise
`allowedFetchMethods`) instead of getting a raw pass-through. Separately, the domain allowlist
ignores the port (it predates this work).

## Round 25 — implemented (2026-10-03; Tonio: "one admission, every path", "default port unless named", and "fetch is a demonstration capability … highly constrained being the default")

- **One admission of the agent's request on EVERY path.** The headers (closed list) and the method
  are admitted before the custom-fetch branch, so a host's own `fetch` receives only admitted
  requests (the method upper-cased). A host DECLARES more for a run with
  `context.allowedRequestHeaders` and `context.allowedFetchMethods`. CONNECT, TRACE and TRACK are
  never admitted, even if declared.
- **Highly constrained by default.** Methods are GET and HEAD unless the host enables more. The
  built-in `httpFetch` is documented as a demonstration capability; real deployments supply their
  own `fetch`.
- **Ports.** An `allowedFetchDomains` entry admits the scheme's default port only, unless it names
  one. A named default port (`:443`) is normalised. Wildcards follow the same rule.
- **Rows:**
  - the rewritten host-fetch row (refused until declared, then passed upper-cased);
  - default methods, CONNECT/TRACE refused even when declared;
  - case-insensitive host header names;
  - a port matrix;
  - redirect pins: a 301 without `Location` and a 300 with one are both ordinary responses.

  The recursive-fetch and integration fixtures now declare their ports and methods.
- **Docs.** The DOCS-AJS "SSRF Protection" section, which described request signing and
  configurable private ranges that do not exist, is rewritten from the code. `guides/patterns.md`,
  the docblock and the CHANGELOG are updated.
- **Mutation:** 7 of 7 caught.
- **Lanes:** format, lint, make, test:fast (7125), dogfood, and the full suite without the live
  LLM (7144, 0 fail).
- **Stopping rule (Tonio):** a finding about the built-in client's HTTP completeness is a
  follow-up, not a blocker, unless it breaks the constrained default.

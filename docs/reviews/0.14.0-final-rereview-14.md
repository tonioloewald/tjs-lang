## Blockers

### B-1: A quota can be switched off by a table shape that passes admission (correctness + security, both confirmed; the two findings are merged)

- **Where:** `src/vm/admission.ts` ~133–156 (validation of the counterTable and budgetTable options); `src/vm/runtime.ts` ~2674–2688 (the quota read in the atom exec wrapper).
- **Defect:** `validateRunOptions` checks `quotas` and `quotaUsed` with `Object.entries(v)`, which sees own enumerable keys only. The exec wrapper reads `ctx.quotas?.[op]` and `ctx.quotaUsed[op] ?? 0` as ordinary property reads, which follow the prototype chain and also see non-enumerable keys. Nothing re-checks the value where it is used. Cost and timeout are re-checked at use by `checkedCost` and `timerMs`; quotas have no equivalent.
- **Reproduced through public `vm.run`:** 5 calls to a `ping` atom. The baseline `quotas: {ping: 2}` stops after 2 calls with "Quota exceeded". Each of these makes all 5 calls with no error:
  - `quotas: new Map([['ping', 2]])`
  - `quotas: Object.create({ping: NaN})` (`used >= NaN` is never true)
  - `quotas` with a non-enumerable own `ping: NaN`
  - `quotaUsed: Object.create({ping: -100})`, or a non-enumerable `-100`
  - a getter on a table: validation reads a valid value, the later read gets `-100` (time-of-check vs time-of-use)
  - `quotaUsed` is a shared, mutable object by design, so a value written after admission (by a capability, or by a sibling run) is never checked.
- **Impact:** the failure re-review 13 blocked on. A cap such as `llmPredict: 3` becomes unlimited model spend without any error. Only the host can supply these values, not the guest. But a Map is a very plausible mistake, and so is the `Object.create(baseQuotas)` defaults idiom. The CHANGELOG's promise that the counter "must be an object of finite, non-negative counts" is not delivered.
- **Fix, both halves required:**
  1. **At the point of use** (the underlying fix, the same shape as `checkedCost`): read `Object.hasOwn(table, op) ? table[op] : undefined`. Refuse a quota that fails `isBudget`. Refuse a `used` count that is not a finite, non-negative number. Fail the step with an AgentError.
  2. **At admission** (the early refusal): refuse any table whose prototype is not `Object.prototype` or `null`. Check `Reflect.ownKeys`, not `Object.entries`. Refuse accessor properties, as the membrane does. Optionally snapshot the static `quotas` table into a null-prototype object.
  - Add hostile-input rows for Map, inherited, non-enumerable, getter-backed and mid-run-mutated tables to `src/admission.test.ts` and the re-review-13 test block.
  - Rule 5 of `budget-funnel.test.ts` currently trusts `ctx.quotas` and `ctx.quotaUsed` as already validated. Revisit it after the fix.
- **Before patching (see the STOP flag):** four rounds have found "admission sees a different set than the read". The general pattern to plan is to validate every host-supplied table at the point of use, or to snapshot it once into a frozen, null-prototype plain value that is the only thing the runtime reads. Adding one more admission check is not enough. The plan should also cover `costOverrides` and `timeoutOverrides` for consistency, even though those are already re-checked at use.
- **Re-review scope:** security + correctness over the remediation diff (admission table validation and the quota read in the exec wrapper).

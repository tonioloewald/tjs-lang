## Blockers

### B1: image URLs are admitted as one string and forwarded as another (security, confirmed)
`src/vm/atoms/batteries.ts:253`. `admitImageUrls` calls `admitFetchUrl(img, allowedFetchDomains, true)` and **discards the returned href**. Two places then forward the raw guest string:
- `llmVision` forwards the raw `resolvedImages`.
- `llmPredictBattery` forwards the original `resolvedUser` unchanged.

Reproduced at HEAD `e232a62` with allowlist `['a.test']`:
- `http://a.test\\@169.254.169.254/latest/meta-data` is admitted. WHATWG `new URL` parses the host as `a.test`.
- The raw string goes to `llmBattery.predict`.
- Python's `urlsplit` reads the hostname of that string as `169.254.169.254`. Python sits under vLLM and mlx-vlm, the backends the CHANGELOG names as fetching `image_url` server-side.

Result: an SSRF to the metadata endpoint through the backend, despite the allowlist. The round-28 commit message says "both paths send it", but that is true only for httpFetch.

**Fix.**
- `admitImageUrls` returns the admitted strings: the normalised `href` for http(s), and a data URL unchanged.
- `llmVision` forwards that returned array.
- `llmPredictBattery` rebuilds the message array so each image part carries the admitted href.

**Tests.** Add hostile rows that assert what the mock battery **received**, not only that the call was admitted:
- backslash-userinfo
- leading space or tab
- mixed-case scheme or host

Run every row against both atoms, and mutation-check them by restoring the raw forward.

**Re-review scope:** security plus correctness over **every** site that forwards a guest-chosen URL to a capability (httpFetch host and built-in paths, llmVision, llmPredictBattery), reviewed as a whole and not as a delta.

### Major M1: message parts are admitted by a denylist that fails open (security + correctness, confirmed; two findings merged)
`src/vm/atoms/batteries.ts:274-289`. `admitLlmUser` skips every part where `type !== 'image_url'`. Reproduced: `video_url` and `audio_url` parts carrying `http://169.254.169.254/...` are **admitted** with or without an allowlist, and so is the case variant `IMAGE_URL`. vLLM fetches `video_url` and `audio_url` server-side, so this is the M1/M2 SSRF through a part type nobody listed. It is the same shape as the rc.2 header re-review 4 finding ("denylist inside the allowlist").

The shipped battery is not exposed, because `buildUserMessage` ignores arrays. A host `llmBattery` that forwards message arrays is the documented multi-turn integration, and that host is exposed.

**Fix:** a closed allowlist.
- Each message is a plain object with a string `role`.
- `content` is a string, or an array of parts whose `type` is exactly `text` (with a string `text`) or `image_url` (admitted, then forwarded as the admitted href per B1).
- Refuse every other part type, any extra URL-bearing key, and any other content shape.

**Tests.** Add rows for `video_url`, `audio_url`, `input_audio`, `file`, a case-variant type, and an `image_url` part with an extra URL sibling. Each row asserts 0 backend calls.

This should land with B1. It is the same remediation.

## Plan (round 29, filed before acting)

**Root cause:** round 28 established "the URL you forward is the URL you admitted" for `httpFetch`
only. The image paths still admitted a value and forwarded a different one, and the message-part
check was a denylist (`image_url` checked; every other type passed).

**Fix: the VM BUILDS what it forwards, from what it admitted.**
- `admitImageUrls` returns the admitted strings (the normalised `href`, or the data URL unchanged),
  and `llmVision` forwards THOSE.
- `llmPredictBattery` rebuilds the message array from a CLOSED shape: each message is
  `{ role: string, content }`, where content is a string or an array of parts typed exactly
  `text` (string `text`) or `image_url` (admitted, then rebuilt with the admitted href). Anything
  else is refused. The rebuilt array is what is forwarded, never the guest's.
- **Network-path references** (`//host/x`, `\\host/x`, `/\\host/x`, after WHATWG whitespace
  stripping) name a host but take the page's scheme. They are refused on EVERY path ("shape
  always").
- **Policy lists** (`allowedFetchDomains`, `allowedFetchMethods`, `allowedRequestHeaders`) must be
  arrays of strings; anything else is refused.
- **Rows** assert what the mock backend RECEIVED: backslash-userinfo, leading whitespace, a
  mixed-case scheme or host, and the `video_url`, `audio_url`, `input_audio`, `file`,
  case-variant and extra-key parts. Each is mutation-checked by restoring the raw forward.

## Round 29 — implemented (2026-10-03)

- **B1.** `admitImageUrls` RETURNS the admitted strings: the normalised `href`, or a data URL as
  given. `llmVision` forwards those. `llmPredictBattery` forwards a message array REBUILT by
  `admitLlmUser`, never the guest's value. The invariant is now the same at every site: what is
  forwarded is built from what was admitted.
- **M1.** The message shape is CLOSED: `{ role: string, content }`, with content a string or
  parts typed exactly `text` or `image_url`. Unknown part types, a case-variant type, extra keys on
  parts or messages, and an `image_url` with keys other than `url` are all refused.
- **Network-path references** (`//host`, backslash forms, after leading controls and spaces) are
  refused on every path. This is a character loop, not a regex: the regex tripped
  `no-control-regex`.
- **Policy lists** are validated up front on every request as arrays of strings.
- **The shipped battery** sends a message-array `user` as the conversation itself (it used to
  become one message with undefined text). `llm-transport` has a row for it. The DOCS-AJS
  parameter table and battery notes are updated.
- **Rows assert what the backend RECEIVED:** the normalised href; no backslash form forwarded; the
  rebuilt message array; 7 hostile part shapes and an extra message key refused with 0 backend
  calls; network-path refusals; policy-list refusals.
- **Mutation:** 6 of 6 caught (raw forwarding, both atoms; unknown parts; extra part keys; the
  network-path check).
- **Lanes:** format, lint, make, test:fast (7191), dogfood, and the full suite without the live
  LLM (7210, 0 fail).

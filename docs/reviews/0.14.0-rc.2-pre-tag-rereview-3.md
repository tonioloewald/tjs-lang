## Blockers (must fix before tag)

### B1: httpFetch leaks the guest's body cross-origin on a 301/302 redirect of PUT/PATCH/DELETE (major, confirmed; correctness and security, deduplicated)

**Where:** `src/vm/runtime.ts` around line 6452, in the redirect loop. The comment at around line 6402 is affected too.

**What happens:**
- The body is dropped only in two cases: a 303, or a 301/302 when the method is POST.
- The new cross-origin refusal fires only for 307/308.
- So `httpFetch({ url: A/301, method: 'PUT', body: { secret } })` gets a 301 whose Location points at origin B, and B receives `PUT {"secret":…}`. The run reports success.
- PATCH with 302 and DELETE with 301 behave the same way.
- The guest's headers are stripped on that hop, but the body is not.

**Why it matters:**
- The code comment says the request carries "never the guest's body", which is false for these cases.
- The CHANGELOG is literally accurate, because it only names 307/308. But it reads as if the body-leak class were closed.
- Reach is limited to origins that are also allowlisted, since every hop goes through `admitFetchUrl`. That is exactly the threat model round 22 decided to close.

**Fix:** make the rule depend on the body, not the status code. Apply it *after* the 303 and POST-301/302 rewrite: refuse any hop where `currentBody !== undefined` and the next origin differs from the current one. Add cross-origin rows to `fetch-admission.test.ts` for PUT+301, PATCH+302 and DELETE+301, each asserting that B sees nothing. Correct the comment.

**Re-review scope:** correctness plus security over the remediation diff. Per the STOP above, also re-read the whole of the redirect, header and credentials code against v0.14.0-rc.1 (see gap 1).

## Diagnosis (filed before acting; HELD for Tonio)

The redirect loop is where three of the four blocks came from: credentials re-sent, the body
re-sent on 307/308, and now on 301/302 for other methods. Following redirects safely means
re-implementing the platform `fetch`'s redirect rules (method rewriting, header and body
stripping, credential handling) and then auditing that copy. Each review finds one more rule.
The routing-header denylist has the same shape: it is open-ended.

**Proposal: the built-in `httpFetch` follows NO redirects.** A 3xx is returned to the guest as
data (`{ status, location }`) or refused, and a host that wants redirects supplies a `fetch`
capability. That removes the redirect class rather than patching its next member. Similarly,
guest headers could be an ALLOWLIST (Accept, Accept-Language, Content-Type, Authorization,
If-None-Match, If-Modified-Since, Cache-Control, User-Agent, plus `X-` names that are not on the
routing denylist?) instead of an open denylist.

## Round 23 — implemented (2026-10-03; Tonio chose "follow none, 3xx as data" and "header allowlist")

- **B1, by removal.** The built-in `httpFetch` follows no redirects (`redirect: 'manual'`). A 3xx,
  or a browser's opaque redirect, returns `{ redirect: true, status, location }` (location null in
  a browser) with the body released. Fetching `location` is a new request, admitted like any
  other.
  - The redirect loop, the hop cap, the cross-origin header and body rules and `refuse()` are all
    deleted.
  - Rows: the metadata, outside-host and `file:` redirects come back as data and are not
    followed; a cross-origin PUT redirect with a body and `Authorization` never reaches the
    second origin; an agent can follow a 303 itself as a new request; a loop costs one request.
- **Headers are an allowlist:** Accept, Accept-Language, Authorization, Cache-Control,
  Content-Language, Content-Type, If-Match/-Modified-Since/-None-Match/-Unmodified-Since, Range and
  User-Agent, plus `X-…` names that do not match the routing/identity pattern or `x-agent-depth`.
  Everything else is refused by name. Rows add `X-Original-Host`, `X-Host`, `X-Real-IP`,
  `True-Client-IP`, `X-Forwarded`, `Cookie` and `Origin` as refused, and a positive row for
  `X-API-Key`.
- **M1:** the `storeOf(ctx)` migration is documented (CHANGELOG, DOCS-AJS custom atoms, CLAUDE.md
  "Custom Atoms Must", `docs/universal-endpoint.md`).
- **m2:** `atom-effects-scan` has a `storeOf(` marker plus an apparatus row asserting the store
  atoms are SEEN as effectful. The mutant (marker removed) is caught.
- **Mutation:** 4 of 4 caught.
- **Lanes:** format, lint, make, test:fast (7086), dogfood, and the full suite without the live
  LLM (7105, 0 fail).

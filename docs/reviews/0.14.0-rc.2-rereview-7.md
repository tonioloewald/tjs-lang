The common cause: **an allocation or work bound is computed from a view of the input that differs from what the host native then does.** Examples: `int()` vs ToIntegerOrInfinity; a per-method exemption where coercion happens per position; a truncated `slots` count; 1 output character per input character where the real figure is up to 6; one `$` vs k tokens; regex screening at some doors but not others. Before patching row by row, the remediator should design this as one rule: every native call receives operands of the exact primitive type it reads, and every bound is derived from those same operands. Then add a probe matrix that runs at a finite cap.

## Blockers (all confirmed)

**B1. `flat`'s bound uses the truncated `treeBytes().slots` (I1 broken).** `src/vm/runtime.ts:2465` / `treeBytes` ~3214. The walk aborts at the cap, but `slots` stays at about 15k, so the bound comes out near 120KB. `a.flat(7)` on a 10×7 DAG under a 1MB cap returned `{n:10000000}` with about +89MB RSS for about 45 fuel. The probe runs with `maxHeapBytes = MAX_SAFE_INTEGER`, so it can never reach the abort branch. *Fix:* make `treeBytes` report `truncated`, and treat a truncated walk as over the cap for every derived figure. Add a probe row that runs at a finite cap.

**B2. Count arguments are bounded with `int()`, which reads a numeric string or an array as 0.** `runtime.ts:2102–2105`, plus bounds at ~2401–2403 and 2424. Under a 1MB cap: `'x'.repeat('1e8')` gave about 191MB; `padStart('5e7')` about +50MB; `Array.from({length:'1e7'})` / `{length:[1e7]}` +80–93MB (up to about 800MB with a larger literal). Each cost 0.24 fuel and was refused only at the bind. Quoting the number reopens I1's headline amplifier. *Fix:* bound with the same ToNumber → ToIntegerOrInfinity/ToLength the native uses, or refuse non-number counts and non-number `length`. Add numeric strings, booleans and `{length:'n'}` to the probe ARGS.

**B3. `STRUCTURAL_ARGS` exempts a whole method rather than argument positions, and the Date wrapper coerces internally.** `runtime.ts:735/2679`, `methodGate` ~2715, Date wrapper ~1951–2003. These calls build a DAG's full string form for about 5 fuel, taking 0.8–8.8s and up to about 5GB RSS against a 50ms timeout and a 1MB cap: `indexOf/includes/lastIndexOf(v, DAG)`, `with(DAG, v)`, `fill(0, DAG)`, `splice/toSpliced(DAG, …)`, `Object.hasOwn({}, DAG)`, `Object.fromEntries([[DAG,1]])`, and `Date(...).diff/isBefore/isAfter(DAG)` / `.isBefore({timestamp: DAG})` / `.add({days|years: DAG})`. `.add({years: DAG})` also rejected `vm.run` with a host `RangeError`, which breaks the monadic contract. `isBefore([2020])` silently coerces an array to a date. *Fix:* declare structural arguments **per position**. The Date wrapper should accept only a Date wrapper or a primitive, `add` fields must be numbers, and host exceptions inside wrapper methods must be caught. Add sweep rows covering every non-zero position of every `STRUCTURAL_ARGS` entry, plus the Date receiver with arrays and DAGs.

**B4. Printers and atoms still expand guest values before any tree-sized charge.** Merges the correctness tree-expanding-paths finding with the security atoms finding.
- `hash` (`runtime.ts:6183–6205`): `JSON.stringify` runs before `chargeForSize`, about +400–500MB.
- `filter(data, schema)` bounds only `a[0]`. `convertExampleToSchema(schema)` mirrors every path (+411MB, 4.8 fuel).
- `Schema.isValid` is in the NONE group with `ns:Schema` set to `'*'`.
- `storeProcedure` stringifies before its size check (about 503MB).
- `regexMatch`'s `pattern` goes through `String(source)` before `regexGate`.
- `httpFetch`'s `url` goes through `new URL()` in `isBlockedUrl` (522MB).
- v1 `consoleWarn`/`consoleError` push unbounded JSON into `warnings` / `error.message`.
- v1 `template` calls `String(tmpl)` before computing its bound.

*Fix:* run `primitiveOperand` (or the inputSchema check) on every string-typed resolved atom input, and charge `allocate(treeBytes/stringifyBound)` before every stringify. Give `isValid` and `filter`'s schema argument treeBytes bounds. Add atom-ratchet rows that pass a DAG to each string input.

**B5. The Set rewrite desynchronizes on NaN (heap-ceiling bypass).** `runtime.ts:53/1838`. `remove(NaN)` deletes the host `index` entry (SameValueZero), then runs `data.splice(data.indexOf(NaN) /* -1 */, 1)`, which deletes the last element. The heap walk only sees `data`. A loop of add-big / remove(NaN) / add(NaN) kept about 100MB under a 4MB cap (RSS +139MB) and completed successfully. *Fix:* find the element with SameValueZero (`findIndex(x => x === item || (x !== x && item !== item))`) and splice only when it is found. Better still, use one structure, or have the heap walk count the index. Add regression rows for NaN, -0 and object identity at a small cap.

**B6. The replace/replaceAll bound counts one subject length per match regardless of `$` token count.** `runtime.ts:~2441–2465`. `'a'.repeat(3000).replaceAll('a', "$'".repeat(50))` was bounded at about 36MB under a 40MB cap and built about 429MB (RSS +544–625MB) before the bind refused it. *Fix:* charge per token. `` $` ``/`$'` cost n per occurrence per match; `$&`/`$n` cost (k+1)·n in total; the literal part is charged per match. This **must be fixed together with M1** (the same function over-charges `$1`).

**B7. Schema validation runs unscreened guest regexes and walks DAG paths for free.** Merges the correctness major and the security blocker. `runtime.ts:1789/1815`, pattern bound ~2378. `Schema.isValid('a'.repeat(26)+'!', Schema.pattern('^(a+)+$'))` took 251–386ms against a 50ms timeout for 0.9 fuel and grows exponentially. `filter(s, sch)` behaves the same. `isValid(DAG8, nested)` took 1065ms for 2.3 fuel, about 10× per level. The `regexGate` docstring's claim of covering "EVERY place" is false. *Fix:* run `regexGate` on `Schema.pattern`'s argument, and on any `pattern` key reaching `isValid`/`filter`/`fromExample`, and apply the input cap during validation (or refuse `pattern` in AJS). Give `isValid` a treeBytes bound plus a fuel charge. Add malicious-actor rows.

**B8. Polynomial ReDoS passes `regexGate`, and the 100k input cap does not bound it** (severity-uncertain, confirmed). `runtime.ts:5109`, `src/redos.ts`. `s.replace(/a*a*c/,'x')` on 3000 characters took 1.67s (12.9s on 6000) for about 2.7 fuel. `s.search('\\d+\\d+\\d+x')` on 1000 digits took 16.7s. At the allowed 100k input this is hours. The surface grew this round because regex literals are now usable in replace/split/match/search. `redos.ts` lists polynomial backtracking as out of scope, but B4 of the last round set the bar ("guaranteed to halt"), and this misses it. *Fix (choose and record):* fail closed on two or more unbounded overlapping quantifiers without a disjoint mandatory separator; or cap input by quantifier count (n^k ≤ 1e8); or use the linear engine (`l` flag) or a killable worker. The related overlapping-alternation gap (m2) should be fixed in the same pass.

## Majors (confirmed; fix in the same remediation, they touch the same code)

- **M1. Regression: `$1`/`$&` replacements with a RegExp are bounded as O(n²).** `runtime.ts:2454`. `s.replace(/(\d+)/g,'<$1>')` under defaults: 2000 characters cost 802 fuel (base 1.7); 5000 characters run Out of Fuel (base 3.3 fuel, success). This false rejection makes ordinary code fail. Fix it together with B6 using per-token charging, and add a no-false-rejection row (20k characters, `$1`, defaults).
- **M2. `treeBytes` walks up to `maxHeapBytes` worth of paths before charging any fuel** (efficiency, severity-uncertain). `runtime.ts:3214`. A doubling DAG (25 levels, about 12 fuel) costs about 327ms of synchronous host CPU per printer call (stringify/join/flat/Schema/filter), with the same result at fuel 50 and fuel 1000. The cost scales with the host's configured cap. *Fix:* meter fuel inside the loop, and stop at the remaining heap headroom rather than the full cap. Add a regression test for fuelUsed and wall-clock.
- **M3. `treeBytes` charges 1 output character per string character, but JSON escapes control characters to 6.** `runtime.ts:3240`. `JSON.stringify([s,s,s,s])` with `s = '\x01'.repeat(2e6)` was bounded at about 16MB and built a 48M-character string (about 92MB) under a 40MB cap. `return {n: …length}` **completed with no refusal at all**. *Fix:* in JSON mode (stringifyBound, toJSON, hash), charge 12 bytes per character or pre-scan for characters that need escaping. Add control-character and quote-heavy receivers to the probe.

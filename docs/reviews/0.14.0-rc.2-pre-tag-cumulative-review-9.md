## Blocking

### M1 (security, major, **confirmed**): a refused capability RETURN is catchable and bills nothing
`src/vm/runtime.ts` ~5257–5270. The `exec` wrapper's inbound membrane (`membraneValue(result, ctx.membraneMaxBytes)`) handles a refusal with `ctx.error = new AgentError("Capability boundary rejected the return of '<op>' …")` and returns. It does not call `haltRun` and charges no fuel for the walk. Round 34's halt covers only `egressValue` and `egressInput`.

- **Reproduced:** a store capability returns a prebuilt 600k-element array, and the guest runs `while (true) { try { const x = storeGet({ key: 'k' }) } catch (e) { n = n + 1 } }`. Measured times: 2.0–2.4 s at fuel 100, 7.5 s at fuel 300, and about 26 s at fuel 1000 with an explicit timeout. That is about 20–26 ms of walk per unit of fuel, against a time box of 10 ms per unit. So "wall time tracks fuel" and "fuel ≥ c×work" are both broken by about 2–2.6×, and the factor grows linearly with the host's `membraneMaxBytes`.
- **Reachable:** any capability that can return oversized data. That includes `httpFetch` of a 2 MB JSON body like `[0,0,…]`, which passes `readBounded` and then grows to about 16 MB of estimate after parsing.
- **Why it blocks now, though review 8 carded it as a gap:** round 34 chose halting as *the* fix for exactly this class of loopable refusal, and CLAUDE.md now says "A capability-boundary refusal ENDS THE RUN". The one refusal whose message literally reads "Capability boundary rejected…" does not end the run. That is a documented guarantee the gate does not keep, so the gate fails open. The CHANGELOG and the DOCS-AJS body ("on its way out") are accurate. The CLAUDE.md headline and the DOCS-AJS heading are not.
- **Fix:** route the inbound refusal through `haltRun(ctx, new AgentError(...))`, the same pattern as `egressInput`, with the same reasoning: plain data is a host contract, so a refusal here is not a failure of the world. Decide the output-schema failure on the inbound path the same way and in the same commit. Add `membrane-halt.test.ts` rows that use `transpile()` output:
  1. An over-budget capability return inside `try`: the catch does not run and no later step runs.
  2. The loop above: the run ends after one walk.
  3. A capability returning a function: halts the same way.

  If inbound is instead *deliberately* kept catchable, then (a) bill the walk exactly as egress does, and (b) narrow the CLAUDE.md line and the DOCS-AJS heading to "an outbound refusal". Either way, write one rule for both directions; do not add a third per-direction patch.
- **Re-review scope:** correctness and security over the remediation diff only.

## On the user's request: "exempt some atoms from timers by the same token"

Yes, and the reasoning carries over. Round 34 removed a per-step cost (a billing mistake that could be caught and repeated) by making the boundary structural. The per-atom timer is the same kind of cost: per-step machinery that does no protective work for a synchronous atom. Its callback cannot run before the atom's body has already resolved.

Measured on a 200k-iteration `while` loop, the timer accounts for about 20–35% of wall time. The protection it appears to give is already provided elsewhere:
- **Fuel and `allocate()`** bound how much work and memory a step can use.
- **The abort and halt checks at every step entry** enforce the run deadline.

**The exemption rule:** an atom that neither awaits nor runs nested steps gets no armed timer unless the host passes a `timeoutOverrides` entry. IO atoms keep the 1000 ms default. The control-flow atoms already use `timeoutMs: 0` for this reason.

It is filed above as a non-blocking card with a `setTimeout`-instrumented test row. It is independent of M1 and should not be bundled into the blocking remediation.


## Round 35 — plan (written before any code, per the cycle STOP)

**The underlying problem.** Round 34 stated a rule about the BOUNDARY ("a refusal at the
capability boundary ends the run") and implemented it at SITES (the outbound copy and the
outbound schema check). The inbound refusal (a capability's return that cannot cross) kept its
own handling: a catchable `ctx.error`, unbilled. This is the site-by-site shape again, at the
level of a rule. The fix is to make the boundary a small CLOSED set of crossing functions, each
of which halts on refusal, and to enforce by parsing that nothing else crosses.

1. **One function per direction, both halting:**
   - `egressValue` (outbound, as now);
   - a new `ingressValue(ctx, op, result)` for capability returns: the walk and the copy, then
     the output-schema check for an IO atom. Any refusal goes through `haltRun`.
   - Pure atoms' output checks are unchanged: their values never crossed a boundary.
   - **Ratchet** (`membrane-doors.test.ts`, parsed): `membraneValue`/`membraneValueFrom` are
     called only from `egressValue`, `ingressValue` and `vm.run`'s argument admission (which
     refuses before the run exists). A new crossing fails the test until it is listed with how it
     halts.
2. **Rows (transpiled):**
   - an over-budget capability return inside `try`: the catch does not run, and nothing after it
     runs;
   - the review's loop (`while (true) { try { storeGet } catch … }` over a 600k return): the run
     ends after one walk, in bounded time;
   - a capability returning a function halts the same way;
   - an IO atom's output-schema mismatch halts.
   - Mutation-checked: ingress not halting, and a schema mismatch not halting.
3. **Constructs that loop without entering an atom** (review gap 4): a refusal inside a `while`
   body, a `map` callback, and a `callLocal` helper called in a loop must end the run promptly
   (bounded fuel). Pinned by rows. If any construct keeps looping, it gets the halt check in its
   own loop.
4. **`halt` is required in the reads too:** drop the `?.` in `exec`, so a context without the
   record fails loudly rather than making refusals catchable. Direct `egressValue` callers
   without a run keep throwing the refusal.
5. **Map/Set false refusal (confirmed minor):** a repeated reference costs one slot (8 bytes)
   when popped, consistent with the heap model ("every slot costs a pointer, repeat references
   included"). That makes the per-entry and per-element "at least 8" bound true, so the early
   bails are truthful. Rows: shared-value Maps, Sets and arrays that fit by their real cost
   cross.
6. **Top-level string** reports `overBudget(maxBytes, length*2)`, the same message and bill as
   a nested string.
7. **Docs:**
   - the DOCS-AJS heading and the CLAUDE.md line now say "both directions";
   - lens 10 gains "can the guest catch the refusal and retry it?";
   - the CHANGELOG names `cache` entries and persisted ASTs wrapping `cache`/`agentRun` in `try`;
   - the `agentRun` capability route (a NEW `vm.run` with its own halt) is documented as the
     host's re-entrancy, like `quotaUsed`.
8. **Not in this round:** the timer exemption Tonio asked for (#2849 carries the measurements
   and the rule: no armed timer for an atom that neither awaits nor runs nested steps, unless
   the host overrides). It is independent of the blocker and gets its own small reviewed diff
   next, as the review recommends.

Re-review scope: correctness + security over the round-35 diff.

## Blockers

### B-1: The block form `Type X { example: A | B }` or `{ example: A }` drops or truncates the example, and fromTS emits this form for every TS union or alias *(verified; security blocker merged with a correctness major)*

`src/lang/parser-transforms.ts:~2614`. The block path still reads `example:` with `extractJSValue`, which takes a single literal only: no `|` chain and no bare name. e4a85a8 moved only the `=` sibling onto `extractTypeDefault`. Measured at HEAD with fromTS and `/* @tjs TjsStrict */`:

| TS source | Emitted | Behaviour |
|---|---|---|
| `type Id = string\|number` | `Type('Id', undefined, '')` | Rejects `a(1)`: **valid input is refused.** |
| `type U = string\|undefined` | example `''` | Rejects `undefined`, which contradicts CHANGELOG line 33. |
| `type MaybeNode = Node\|null` or `P\|null` | `Type('MaybeNode')` | Accepts `5`, `true`, `{}` and `'a'`: **fails open.** |
| `type Alias = Node` | `Type('Alias')` | Accepts `5`: fails open. |
| `type Expr = Add\|Mul\|Num` | `Type('Expr')` | `evaluate(5)` runs the function body on garbage. |

Nothing is recorded when this happens, unlike the ref TDZ degrade. The parse defect predates 0.14, but this release turns on TjsStrict validation for converted TS and says that "references to other types are checked". So the release advertises a gate that silently passes garbage and rejects valid input on the most common converted shapes.

**Fix:**
- Make the block `example:` and the `=` default share one reader (`extractTypeDefault` plus `markExampleKinds`).
- Make an example that cannot be read a transpile **error**, not a silent `Type('X')`.
- Add rows to `tjsstrict-safety.test.ts` through fromTS for a union of interfaces, `T|null`, a plain alias, `string|number` and `string|undefined`, each with one accept and one reject case.
- Add native block rows to `example-kinds.test.ts`, covering `{ example: A|B }`, `'' | 0` and `{ example: N }`.
- Re-run compat-scan and dogfood, because Types that were previously empty will now validate.

**Re-review scope:** correctness + security over the block-example extraction and the fromTS alias emission, plus blast-radius.

## Majors (verified; must land before publish)

### M-1: The ref-check rollback is still quadratic, and the per-top-frame 1e6 budget then REJECTS valid data *(verified; correctness major merged with the security major)*

`src/lang/emitters/js.ts:2123-2124`. Two rollbacks throw away more than they should:
- A failed ref frame's `__kRoll(L)` rolls back every pair logged since L, including descendant proofs that never consulted the refuted pair.
- The union-level `__kRoll` does the same after a failed alternative, although a failed alternative refutes nothing.

When an alternative proves the recursive tail and then fails on a later key, such as a discriminant declared last, the next alternative re-proves the whole tail. The cost is T(d) = T(d−1) + O(d).

Measured at HEAD:

| Case | Size | Result | Time |
|---|---|---|---|
| Text\|Num list, valid | 400 nodes | accepted | 70 ms |
| Text\|Num list, valid | 800 nodes | **MonadicError "Expected Num"**, recorded as "too large to check" (~20KB) | 247 ms |
| Add\|Mul\|Num left-deep tree, `kind` declared last, valid | 600 levels (32KB) | **rejected** | 198 ms |
| Same tree, `kind` declared first | 600 levels | accepted | ~2 ms |

The budget resets per top frame. With `Type Batch { items: [Expr] }`, a 713KB valid body took about 1.9 s of synchronous CPU, and about 7 s at 912KB. The budget scope is also inconsistent: an array checked directly returns `true`, while the same array wrapped in `Type W { r: Root }` returns `false` (not re-measured). The code comment "each pair's cost paid once" is false for this shape. The verdict stays **sound**: no wrong `true` was found. It is incomplete.

**Fix:**
- Track dependencies per frame, Tarjan-lowlink style (the lowest open-assumption index each frame consulted).
- Keep any success that did not depend on the refuted pair, and promote a closed success to a permanent true-memo.
- Remove the union-level rollback.
- Scope the work budget to the outermost validation.
- Correct the code comment.
- Add time-bounded tests that must **accept**:
  - valid Text\|Num lists of 1000 and 5000 nodes;
  - a valid discriminated-union AST of 2000 or more nodes with the tag declared last;
  - an X\|Y chain at depth 5000;
  - a ~1MB `[T]` payload, with a total-time bound.
- Add a check that an array gets the same verdict with and without an enclosing ref frame.

### M-2: The memo and failure scope opens at the first `ref` frame, not at the top-level `Type.check` or parameter check, so B-1 is only partly closed *(verified; efficiency)*

`src/lang/emitters/js.ts:2121` sets `const top = !__kA`. `Type.check` and validated parameters enter through `__match` and open no scope. Every array element therefore becomes its own top frame and re-walks the shared graph.

Star-shaped parent-pointer tree (`TN`):

| Children | Time |
|---|---|
| 400 | 27 ms |
| 2000 | 578 ms |
| 4000 | 2.4 s |
| 8000 | 10.4 s |

That is quadratic, and it was no better at base. The fromTS `TreeNode` shape that B-1 named takes 2.2 s for 4000 children under TjsStrict. JSON input cannot build shared or cyclic graphs, so this is not a network DoS. In-process ASTs, DOM-like trees and ORM graphs pay O(children × graph) on every validated call. The pinned test (400 nodes, 200 ms bound) cannot fail on this.

**Fix:**
- Open `__kA`, `__kF`, `__kLog` and `__kWork` in the outermost check (the inline `Type` stub's `check` and the parameter entry), or through a shared `__kScope(fn)` helper. Tear the state down in that scope's `finally`. This is the same scope change M-1's budget needs, so land both together.
- Add a growth test: a star of 8000 children must finish in under 1 s, and time(8000)/time(2000) should be about 4, not about 16.
- Add a `TreeNode[]` sibling-array row.

**Re-review scope for M-1 and M-2:** correctness + efficiency + security over the `__k`/ref diff, including soundness of the widened assumption set (the rollback must still cover every failing alternative).

### M-3: For a predicate Type, whether the example is enforced standalone depends on whether the example carries a marker, so `0` versus `0.0` decides fail-open *(verified; correctness, security-relevant)*

`src/lang/parser-transforms.ts:~2718-2728`. The gate is `__match(x, __ex)` only when `markExampleKinds(example) !== example`. Otherwise the gate is the old `schemaGate`, which is `true` when no runtime is installed.

Results with no runtime:

| Type | `{a:'x'}` | `5` |
|---|---|---|
| `{ example: { a: 0 } predicate(x){return true} }` | accepted | accepted |
| `{ a: 0.0 }` with the same predicate | rejected | rejected |
| `{ a: 0 }` with no predicate | rejected | – |

So a predicate that narrows nothing widens the type, which is still the M-2 invariant break, on the default (standalone) emission path. The commit's own comment says that `__match` "needs no runtime" but applies it to only one branch.

**Fix:**
- Gate every non-empty example on `__match`, and keep the schema gate only as an extra check when a runtime is installed.
- Extend the M-2 differential test with an unmarked-example-plus-predicate row in standalone mode.
- Add a CHANGELOG "may newly REJECT" line: a predicate Type now enforces its example without a runtime, including when the predicate was deliberately wider than the example (completeness gap 7).

**Re-review scope:** correctness + security over the predicate route.

## Completeness gaps (still scheduled; none waived)

1. **Gate lanes not run on what ships.** No typecheck, `lint --max-warnings 0`, `format:check`, `make` plus `git diff --exit-code` on generated artifacts (demo/docs.json and CHANGELOG changed again), dependency audit, dogfood in CI, or full pre-tag `bun test` (LLM + benchmarks) has run on the 7-commit batch. Run all of them before publish.
2. **Cross-module ref soundness and termination.** The `__kA`, `__kF`, `__kLog`, `__kWork` and `__kDeep` state is per-file and not fused. Open questions: whether the budget and failure memo reset on every cross-module entry, and whether an assumption proven in module A survives a failure detected in module B. Needs a two-module test with a hostile DAG and a cycle.
3. **Monotonicity.** A `pred` marker or user predicate that calls another Type's `.check` and **negates** the result re-enters the live `__kA`/`__kF`, and memoized state could flip its answer. This is untested.
4. **Throwing predicate mid-ref-check.** A non-RangeError skips `__kRoll` and the `__kF` record. State does not leak between checks, but the caller now sees a throw where the non-ref path may return false. Compare against 0.13.x.
5. **fromTS `Array<T>`** now propagates `position` instead of `nested`, which changes output for every `Array<…>`. Compat lanes run without TjsStrict and cannot see the change. Check the generated `.d.ts` and JSON Schema for `Array<{a?:…}>` and `Array<object>`.
6. **Schema surface change.** With `__kSchema` and `__kv` removed, `toJSONSchema` and `functionMetaToJSONSchema` for a Type with a predicate and a marked example come from a different path. Diff them against 0f4e6e5 and 0.13.x, and check the bigint-set mapping through `JSON.stringify`.
7. **A predicate deliberately wider than its example** now newly rejects in runtime-less standalone JS. Name this in the CHANGELOG "may newly REJECT" block (folded into M-3).
8. **Downstream `.tjs` not re-run** under the new semantics: `tjs-src/runtime.tjs`, the guides/examples `declarations.md` and `tjs-grammar-demo.md`, and `functions/src/*.tjs`, which is deployed and only affected after publish, with nothing gating that.

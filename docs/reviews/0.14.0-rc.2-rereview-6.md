## Blockers (all verified)

### B1. The I1 bounds deduplicate shared references, so string forms and `flat` of a DAG allocate exponentially past the bound
`src/vm/runtime.ts:2063` (deepBytes), `~2646` (estimateBytes), `~2898` (stringFormBound). Correctness and security found this independently; the two reports are merged here.

- **Cause:** estimateBytes counts each object once (its `seen` WeakSet). Printing or flattening a value visits every path to it, so the output is far larger than the estimate.
- **Measured** (8 levels × 10 wide, maxHeapBytes 1MB, fuel 1000):
  - `h.join(',')` built 410M chars for 2.5 fuel.
  - `JSON.stringify(h)` built 432M chars.
  - `h.flat(10)` built 1e8 slots.
  - At `a58b91a` the same calls failed with Out of Fuel, so this is a regression.
- **Bind-time catch comes too late:** `'x' + q`, template literals and `concat` are stopped at the bind only after the ~114MB string already exists.
- **Impact:** one synchronous native call can exhaust host memory, and both the space and time budgets are bypassed.
- **Fix:** bound string-form and flatten results by tree size. Walk without a global `seen`, use an ancestor stack for cycles, abort once past the cap, and charge the walk as fuel. Use it in stringFormBound, DEEP/PRINT/join/stringify/flat and DEEP_ARGS. Add DAG receivers and arguments to the RECEIVERS/ARGS pools in `vm-budgets.test.ts`, plus an I1 row through `transpile()`.
- Also correct `docs/vm-budgets.md`'s "fails closed" wording where it implies string forms over-count.

### B2. Implicit coercion doors outside `allocate()`
`src/vm/runtime.ts:3209` (member), and the binary operators from `~3216`. Correctness rated this major; security folded it into its blocker. It is a blocker because it is the same I1 claim.

- **Ungated sites:**
  - computed member keys: `String(prop)` and `obj[prop]`
  - relational and arithmetic operators on objects: `< > <= >= - * / % **`
  - every NONE/CONST table entry that converts its argument with ToString or ToNumber: `includes`, `indexOf`, `startsWith`, `localeCompare`, `charAt`, `at`, `toFixed`, `Math.*`
  - the NONE GLOBAL_TABLE entries: `parseInt`, `parseFloat`, `isNaN`, `isFinite`
  - the default comparator of `sort`/`toSorted`
  - `String(resolvedValue)` in regexMatch, which runs before its `MAX_REGEX_INPUT_LENGTH` check
- **Measured:** these ran to completion while building strings of tens to hundreds of MB, for about 1–1.5 fuel each. Even a flat array (no DAG) gets the full string form for free while the `+` operator is gated.
- **Fix:** refuse non-primitive operands and keys where JS coercion has no AJS purpose (simplest, and fails closed), or charge the tree-size string-form bound from B1 at each site. List these doors in `docs/vm-budgets.md`'s door table, and add a sweep over the coercion sites to `vm-budgets.test.ts`.

### B3. `callLocal` binding a parameter clears the caller's frame, so unbound extra arguments escape the heap
`src/vm/runtime.ts:4260`, with setStateVar `~3113`. The severity was marked uncertain; it is confirmed as a blocker under the 0.14.0 trust model (the VM admits ASTs from any front end).

- **Mechanism:** `scopedCtx` is built by spreading `ctx`, so it shares the caller step's `allocFrame`. The first `setStateVar` zeroes that frame. Arguments with no matching parameter are then neither charged nor rooted, but `resolvedArgs` keeps them alive for the whole call.
- **Measured:** setting `paramNames=['n']` on `h(n, pad)` completes at 250 × 400KB live under a 1MB cap. With `['n','pad']` it is correctly refused.
- **Bound:** about 256 × maxHeapBytes, since `MAX_CALL_DEPTH` is 256.
- **Fix:**
  - Refuse an arity mismatch, at admission or in callLocal.
  - More generally, a bind may reset only a frame that its context owns.
  - Add a hand-built-AST row to `rc2-rereview-4` / `vm-budgets`.

### B4. `String.prototype.match` and `.search` bypass the ReDoS guard
`src/vm/runtime.ts:2161` (search, NONE) and `:2323` (match, SHALLOW(4)). Security rated this a blocker; correctness rated it major. The blocker stands because it breaks the VM's "guaranteed to halt" guarantee.

- **Measured:** `('a'.repeat(27)+'!').match('^(a+)+$')` takes 634ms for 0.5–0.7 fuel and returns SUCCESS with `timeoutMs: 50`. Time doubles with each extra character, so about 36 chars blocks the host for minutes.
- **Context:** the problem predates this diff, but P2 re-admitted both methods under the principle that admission requires a declared bound, and that bound counts bytes only.
- **Fix:** factor out a shared regex gate (pattern length, `isSuspiciousRegex`, input length) used by both regexMatch and these methods. Alternatively remove both from METHOD_TABLE and GUEST_METHODS and point users to regexMatch. Add hostile-pattern rows to `malicious-actor.test.ts`.

## Majors (verified), required in the same remediation because they are the same class

- **M1. The method table is keyed by name, not by receiver kind** (`runtime.ts:2333`).
  - The later Schema spread `union: DEEP_ARGS` overrides the Set wrapper's `union: SHALLOW(2)+WRAPPER`, so the first entry is dead code. `diff` is CONST(4096) because it was written for Date, but Set `diff` copies the receiver.
  - Measured on a 100k-element Set: bound 4.6KB / 4KB against a 100k-slot result.
  - The Date `format` is also CONST(4096), but it runs six `.replace` calls over a guest-length format string (merged from security's minor).
  - The probe cannot see any of this: `createdBytes` never walks `HEAP_CONTENTS`, and no pool argument is larger than WRAPPER_BYTES.
  - **Fix:** dispatch bounds by receiver kind, refuse duplicate keys when METHOD_ENTRIES is built, make the probe follow `HEAP_CONTENTS`, and add a pool argument larger than WRAPPER_BYTES.
- **M2. Set `intersection`/`diff` do O(n×m) work for a byte-linear fuel charge** (`runtime.ts:1851`). At 60k elements this took 2.6s for 523 fuel, which breaks cost-invariant. Implement them with a host Set (O(n+m)) and add a cost-invariant row. The Set's `has`/`add`/`remove` are linear per call for constant fuel, which is milder.
- **M3. Bounds for `slice`/`substring`/`substr`/`split` use the receiver's size, not the result's** (`runtime.ts:2080`, `2305–2307`). This is a false-rejection and fuel regression:
  - A char-scan loop costs 12× the fuel.
  - `s.slice(0,10)` on a 300k-char string is refused.
  - `split(',')` on 100k chars is refused.
  - **Fix:** compute bounds from the clamped arguments, and add no-false-rejection rows so the probe checks both directions.
- **M4. A partial result of a `+` chain stays charged in flight until the step ends** (`runtime.ts:3220`).
  - Templates now compile to a left-nested `+` chain, so `${s}a${1}…` with a 2MB `s` is refused at an 8MB cap, while the same template with `s` last fits. Whether a program fits depends on where the interpolation sits.
  - **The guards were weakened:** `heap-reconcile.test.ts` (200000 to 120000) and `rc2-rereview-4.test.ts` (290000 to 140000) were edited down to fit. Those are no-false-rejection guardrails, and CLAUDE.md says not to make them pass by editing the expectation. Restore the original sizes.
  - **Fix:** release a consumed operand's transient once the consumer is charged, or compile templates to one n-ary concat charged once. Document in the CHANGELOG how much in-flight memory counts against maxHeapBytes.

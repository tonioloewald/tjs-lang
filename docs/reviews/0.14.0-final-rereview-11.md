## Blockers

### B-1 — `transpile(source, { maxSourceBytes: NaN })` admits source of any size (confirmed ×3)
- **File:** `src/lang/core.ts:45` → `src/vm/admission.ts:97-103` (`sourceBytesOver`)
- **Defect:** core.ts only checks `maxSourceBytes !== undefined`, then calls `sourceBytesOver`, where `code.length > NaN` and `bytes > NaN` are both false. Result: null, and the source is admitted.
- **Reproduced:** 16.8KB, 21KB, 36KB and 108KB AJS sources were all admitted with `NaN`, while `8192` refused them.
- **Related inconsistencies:**
  - `-1` and `null` refuse everything, with nonsense messages ("over the -1-byte limit", "over the null-byte limit").
  - `'8192'` works only through coercion.
  - `0` silently disables the cap, and `TranspileOptions` does not document that.
- **Why it blocks:**
  - This is the entry the deprecation notice, the CHANGELOG and CLAUDE.md send untrusted-source hosts to. `Number(process.env.X)` with the variable unset gives a silent no-cap.
  - `vm.run` refuses NaN (`validateRunOptions`/`isBudget`), and Eval/SafeFunction refuse it (`checkSourceSize`, fixed in this same diff). The newest gate is the only one that fails open.
  - The fix was applied at one call site, not in the shared funnel, so the copies drifted inside a single commit.
- **Fix:**
  - Validate in the funnel. Either make `sourceBytesOver` refuse any non-number, NaN or negative value (as `timerMs` already does), or add one `admitSourceCap`/`assertSourceCap` in `src/vm/admission.ts` built on `isBudget` and call it from core `transpile`, eval `checkSourceSize` and runtime `admitSource`.
  - Delete eval.ts's local copy.
  - Document that `0`/`Infinity` disable the cap, or refuse them on this opt-in API.
- **Test:** add `transpile (in-process, capped)` to the NaN/negative rows in `src/admission.test.ts`. Also cover `null` and the string case, and pick a disposition for each.
- **Re-review scope:** correctness + security + blast-radius over the remediation diff only.

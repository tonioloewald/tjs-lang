# 0.14.0-rc.2 pre-release review: triage (base v0.14.0-rc.1, HEAD 4508601)

**Verdict: BLOCK.** 1 confirmed blocker and 3 confirmed majors (deduped to 2). All are in the round-30 outbound membrane (`egressInput`, `src/vm/runtime.ts` ~4755, called at ~4897).

## The user's question: "Checking stuff at the membrane is negative blast radius, no?"

**Yes, in design.** It is one choke point at the `exec` door, it fails closed, and it is on by default for `defineAtom`. So every embedder's custom IO atom gets a checked deep copy just by upgrading. That is the right shape, and it beats fixing call sites one at a time, which is what the earlier rounds kept doing.

**Not yet, as implemented.** There are two reasons, and both are confirmed:
1. **The choke point is not metered.** The crossing costs work proportional to its size, but it charges no fuel or heap, and it runs before the fuel check. That opens a new guest-controlled amplifier at exactly the point meant to shrink risk.
2. **Not all traffic goes through it.** IO atoms that resolve their own inputs (`agentRun`, `cache`; also `memoize`/`runCode` and any embedder atom with `resolveInputs: false`) go around it. The docstring's "covers every IO atom, including ones not yet written" is false.

So the design should stay. Make it the **only** door (enforced by a ratchet), and make it **charge before it copies**, the way run arguments already do in `vm.ts` (`ARG_BYTES_PER_FUEL`).

## Blockers

### B-1. The outbound membrane copy is guest-sized work that charges no fuel and no heap, and runs before fuel (verified; correctness + efficiency + security)
`src/vm/runtime.ts:4755` (`egressInput`), call site `:4896-4911`.
- `egressInput` runs `membraneValueFrom` (walk plus `structuredClone`, up to `membraneMaxBytes` = 4MB) and then `validate()`. It does this **before** `ctx.fuel.current -= currentCost`. It never calls `allocate()` and never charges fuel in proportion to bytes.
- **A refused input is never charged.** Validation throws before the base cost is deducted, and the guest can catch the refusal and loop.
- Measurements (three independent probes on `transpile()` output):
  - `storeSet` loop on 100k objects: 10.8 s at HEAD vs 105 ms at HEAD~1, with **identical fuel** (3300).
  - `consoleLog({message: arr})` x200: 11.8 s for 1.8 fuel.
  - Refused `storeGet({key: big})` in try/catch: about 250 ms of host CPU per ~0.8 fuel.
- That is roughly 12 to 600 ms per unit of fuel, against the 10 ms per fuel the default timeout assumes. Each copy is synchronous and blocks the event loop. The timeout cannot preempt a copy in progress.
- Invariants broken: `cost-invariant.test.ts` ("fuel that doesn't track work isn't a budget") and `docs/vm-budgets.md` ("nothing allocates before it is charged"). The door is not listed in the vm-budgets allocation-door table.
- It is new in round 30: `atom.resolveInputs = LEAF_IO_OPS.has(op)` replaced `= false`.
- **Fix:** charge the atom's base cost and quota first. Then size the input with a budgeted pre-walk capped at `min(membraneMaxBytes, remaining fuel x bytes-per-fuel)` (mirror `vm.ts` run-argument admission), and charge fuel for the bytes that cross through `allocate()` *before* the `structuredClone` and validate. Add a cost-invariant row: N IO calls on an N-node value, **including refused calls**, must cost at least c x N fuel. Add a mutant that removes the charge and confirm the row goes red. Add the door to `docs/vm-budgets.md`.
- **Re-review scope:** correctness + efficiency + security over the remediation diff.

## Majors (must be fixed with B-1; same subsystem, same re-review)

### M-1. The "one choke point" is not total: agentRun and cache still give host capabilities live guest objects (verified; security + blast-radius)
`src/vm/runtime.ts:6974` (agentRun), `:7378` (cache), LEAF_IO_OPS at `:7780`.
- `agentRun`: `ctx.capabilities.agent.run(resolvedId, resolvedInput)`. `resolvedInput` is only a *shallow* null-prototype copy, so nested objects stay live, and `resolvedId` is passed through unchecked. **Reproduced:** when the host mutated `inp.a.x`, the guest's `o.x` read back `'MUTATED_BY_HOST'`. Nothing bounds the size against `membraneMaxBytes`.
- `cache`: `store.set(cacheKey, { val: result, _exp })` receives the live callback result. Its `key` (`s.string.optional`) is never validated, and host ToString runs on whatever the guest resolved.
- This is the same "values forwarded live" class that round 30 says it closed. The `egressInput` docstring overclaims, while the CHANGELOG is correctly narrower.
- **Fix:** send both call sites through the same egress helper (copy plus budget plus charge from B-1, and validate the cache key as a string). Then add a **parse-based ratchet**, in the style of `regex-doors` / `guest-key-writes`. It should fail on any `ctx.capabilities.*(...)` or `storeOf(ctx).*(...)` call whose arguments did not come through egress, and on any `effects: 'io'` atom not on the egress path, unless that atom is allowlisted with a written reason. Stale entries must also fail. Reword the docstring to name the `resolveInputs: false` exemption, or remove the exemption.

## Round 31 — plan (written before any code, per the cycle STOP)

**The underlying problem.** Round 30 added a door: a crossing that does work proportional to guest
data. It added that door the way the earlier rounds added checks, at one place, without asking what
it costs. The VM already has a rule for this, and run arguments already follow it: *size it against
what the run can pay, charge it, then copy it* (`vm.ts`, `ARG_BYTES_PER_FUEL`). The egress copy has
to follow the same rule, through the same gate (`allocate()`), so there is one way to cross and one
way to pay. The second problem is the same as before: "one choke point" was claimed, not
enforced. Enforce it with a list that a parse checks.

1. **One metered crossing, `egressValue(ctx, op, value)`.**
   - The walk's budget is `min(membraneMaxBytes, the bytes remaining fuel can pay, the heap
     headroom)`.
   - `membraneValue` gets an optional `admit(bytes)` hook that runs between the walk and the
     `structuredClone`. Egress passes `allocate()`, so the copy is charged as fuel and held as
     transient heap, and both happen before it exists. The transient heap is released when the
     step ends.
   - A walk refused over budget is charged for what it walked. When fuel was the binding limit,
     the refusal reads `Out of Fuel`, as run arguments do.
2. **Egress moves after the base cost.** The order becomes quota, abort, resolve (already metered
   per node), cost function, base fuel, egress (charged), validate, body. So a refused call has
   paid its base cost and its bytes.
   - Validation runs over a copy whose size has been paid for. The schema is the host's and is a
     constant factor.
   - Host-authored `pattern` regexes running on guest strings are the host's own regex. That is
     the same exposure the return-path `outputSchema` validation has today. It gets a written
     allowlist reason and a card.
3. **Every IO atom is on the egress path.**
   - `agentRun`'s capability route: the agent id must be a string or an AST (checked as today),
     and `input` goes through `egressValue`.
   - `cache`: the key must be a string, and the stored `{ val }` goes through `egressValue`.
   - `runCode` sends only an admitted string. `random`, `uuid` and `clearExpiredProcedures` send
     nothing guest-shaped. Each gets a written reason.
   - **Ratchet:** a parse over the core and battery atom definitions. Every `effects: 'io'` atom
     is VM-resolved, or calls `egressValue`, or is listed with a reason. Stale entries fail. A
     behavioural row per capability route checks that a host mutation of what it received is not
     visible to the guest.
   - The docstring is reworded so it names the rule rather than claiming it.
4. **Rows that can fail, each mutation-checked.**
   - N IO calls on a large value, accepted and refused, cost at least c×N fuel. Removing the
     charge must fail this row.
   - An egress walk bounded by remaining fuel ends as `Out of Fuel`, not as a 4MB copy.
   - agentRun and cache aliasing rows.
   - A v1 AST `storeGet` whose key is a bare variable name resolves the same through egress.
   - **Reconcile re-seed:** a value about 0.6×`maxHeapBytes` rebound N times must cost fuel
     linear in N. If no row can tell the two apart, the re-seed is reverted rather than shipped
     unpinned. Remove the stale comment.
5. **Docs.**
   - `membraneMaxBytes` caps both directions: RunOptions, CLAUDE.md and vm-budgets.md, plus a
     CHANGELOG break note.
   - vm-budgets.md lists egress as a door.
   - `docs/review-lenses.md` gets the lens this review asked for: a new choke point states its
     cost and is metered before it does work.
6. **Cards, not this round:** m-3 (io atom with no schema), n-1 (name the failing field), m-4
   (bundle deltas and stale size claims), m-5 (VM throughput row), m-6 (test:fast time),
   completeness-3 (a real embedder check, snowfox #2814), completeness-8 (tosijs-ui ecosystem
   check), and the host `pattern`-on-guest-string note.

Re-review scope: correctness + efficiency + security over the round-31 diff.

## Findings (deduplicated)

### Minor

1. **The intrinsic-capture docstring claims "used ONLY", but the membrane still calls live intrinsics** *(unverified; correctness + security, merged from 2 findings)*. Location: `src/vm/runtime.ts:~1003`. Round 45 captured only `Array.prototype`, `Object.prototype`, `Array.isArray` and `Object.defineProperty`. Several decision paths still call the live intrinsics:
   - `admitKind` (~l.946) uses `Object.getPrototypeOf` and `Reflect.ownKeys` (Date check).
   - `readArrayData` (~l.1069, ~l.1094) uses `Object.getOwnPropertyDescriptor`, plus `Object.setPrototypeOf` and `Object.keys`.
   - `readOwnData` uses `Object.create`.
   - The refusal message (~l.996) uses `Array.isArray`.

   A host that replaces `Object.getPrototypeOf` could make `admitKind` treat an Array subclass as an exact array, which is the M-2 thinning class. The S1 test hijacks only the two captured functions. The risk is low, because whoever rewrites host globals already owns the host. The defect is that the comment promises more than the code does, and review 19 S1 already called this policy "half applied". **Fix:** either capture the remaining intrinsics, switch l.996 to `IS_ARRAY` and extend the hijack row, or narrow the comment to the captured set and state that hostile global replacement is out of the threat model.

2. **The build prints absolute bundle sizes, never a delta** *(unverified; efficiency)*. Location: `scripts/build.ts:250`. `bundle-size.test.ts` fails only on drift over 10% and over 1 KB against the README table. Measured values:

   | Bundle | Measured (raw / gz) | README table |
   |---|---|---|
   | `tjs-vm-ast.js` | 136,930 B / 42,919 B | 129 KB / 41 KB |
   | `tjs-vm.js` | 317,379 B / 95,893 B | 305 KB / 93 KB |

   Both are about 4% over and still green. `dist/` predates HEAD, so these numbers are not exactly HEAD's. This was not introduced by the diff and does not block.

### Nit

3. **`admitKind` docstring still states round 44's array rule** *(unverified; correctness)*. Location: `src/vm/runtime.ts:929`. Change it to: "an array by brand whose prototype is Array.prototype, Object.prototype or null (copied with Array.prototype); never admitted as plain".
4. **The per-atom deadline now starts after the atom's first microtask** *(unverified; correctness)*. Location: `src/vm/runtime.ts:5564`. An atom that runs `await null` followed by 200 ms of synchronous work, with a 50 ms timeout, now times out at about 250 ms instead of about 200 ms. The run-level deadline is unaffected. **Fix:** take the start time before calling `fn` and arm the timer for `armedTimeout - elapsed`, or change the CHANGELOG wording to "timed as before, from its first await".
5. **The alias pass in `guest-key-writes` recognises only the exact `const X = Object.defineProperty` form** *(unverified; security + blast-radius, merged from 2 findings)*. Location: `src/vm/guest-key-writes.test.ts:134`. Destructured captures (`const { defineProperty: DEF } = Object`, `const { set } = Reflect`) and `.bind(...)` aliases are invisible to it. `SETTING_CALLS` is a shared module-level Set, so the result depends on file order. There is no apparatus row for the alias pass. No such form exists in `src/vm` today. **Fix:** handle ObjectBindingPattern on `Object`/`Reflect` and `.bind`, keep alias sets per file, and add an apparatus row for each alias shape.
6. **`defineAtom` has two atom-call sites** *(unverified; blast-radius)*. Location: `src/vm/runtime.ts:5547`. Atoms with no timeout go through the `execute` wrapper; atoms with a timeout call `fn` directly. That is the sibling-site risk. **Fix:** use one `running` promise built with `try { Promise.resolve(fn(...)) } catch { Promise.reject }`, then race against the timer only when a timeout is armed, and delete `execute`.
7. **One extra `Promise.race` and microtask hop for calls that are really pending** *(unverified; efficiency)*. Location: `runtime.ts:5564`. The cost is O(1) per step, and synchronous calls are a net win. No action needed. If profiles show it, skip the probe for nested-step control atoms.

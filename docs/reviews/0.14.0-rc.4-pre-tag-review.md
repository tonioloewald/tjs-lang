## Major (confirmed; fix before tagging, not a block)

**M1. Indented sources lose test and signature-test enforcement silently** (`src/lang/tests.ts:286`, correctness, **verified**).
`extractTests` now blanks test blocks in place and no longer `.trim()`s. The trim used to dedent the first statement. `stripModuleSyntax` (`src/lang/emitters/js-tests.ts:372`) strips `/^export\s+/gm`, which only matches at column 0, so an indented first `export` survives. `new Function` then fails, and every test comes back `inconclusive: true` with nothing thrown.

Reproduced against a git-archive of rc.3:
- `\n  export function inc(count: 0)…` with a failing test: rc.3 **threw**; HEAD returns inconclusive.
- The guardrail canary `\n  export function add(a: 2, b: 3): 0`: rc.3 threw "signature example is inconsistent"; HEAD is silently inconclusive.
- A passing indented test: rc.3 returned `passed: true`; HEAD returns inconclusive.

This is a regression from rc.3 and worse than issue #50. Indented template-literal fixtures are the common case (b8r-tjs, the docs fixtures).

**Fix:** build the test module with the parsed `stripExports` (`src/lang/strip-exports.ts`) plus import removal, not the column-0 regexes. That also covers the arrow `export default` case from #50 and closes m4. Add rows for the indented failing test and the indented canary, in `diagnostic-lines.test.ts` or a #50 test.

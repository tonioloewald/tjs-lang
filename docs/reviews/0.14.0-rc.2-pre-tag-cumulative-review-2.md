## Blockers

### B1. Round-27 relative-URL fix is incomplete: admission and forwarding use different strings (security, CONFIRMED)

**Where:** `src/vm/runtime.ts` ~6337–6350 (`admitFetchUrl`) and ~6491 (host fetch forward).

**What happens:** When an allowlist is set and `new URL(url)` throws, the code resolves the URL against `https://relative.invalid/`. If the result has a different host, it recurses on `resolved.href` and checks the allowlist against that. It then forwards the RAW `url` to `ctx.capabilities.fetch`.

**Reproduced at HEAD** with allowlist `['api.example.com']`. All of these are ADMITTED:
- `/\api.example.com/x`
- `\\api.example.com/x`
- `\/api.example.com/x`
- `//api.example.com/x`

A single leading `\` is correctly refused.

**How a host resolves the raw strings:**
- Under `capacitor://`, `tauri://` or `chrome-extension://`, `/\api.example.com/x` becomes `<origin>/\api.example.com/x`. That is a same-origin read that skips the allowlist, the same class as cumulative-review B1.
- Under the same origins, `//api.example.com/x` becomes `capacitor://api.example.com/x`, a scheme that is not http/https.
- Under `file:` (Electron), every admitted variant becomes `file://api.example.com/x`, which is UNC/SMB on Windows. That breaks the "http:/https: only, every path, always" promise.

**Root cause:** Admission decides on one parse, and the host acts on a different string. This is the same pattern that re-reviews 3–7 kept hitting.

**Fix (structural):** Make admission and forwarding use one string.
- **Option 1:** When `allowedDomains` is set, refuse every URL for which a base-less `new URL(url)` throws, and drop the recursive branch.
- **Option 2:** Forward only the admitted `resolved.href`, never the raw input.

**Tests:** Add rows to `fetch-admission.test.ts` for `\\a.test/x`, `/\a.test/x`, `//a.test/x`, `\/a.test/x` and `/\/a.test`. Run them against allowlist `['a.test']` under vm.run, Eval and SafeFunction. Each row asserts either 0 host calls or that the forwarded URL is absolute http(s). Mutation-check the rows.

**Re-review scope:** security + correctness over `admitFetchUrl` and both fetch branches, cumulative over all httpFetch admission since rc.1.

## Major (must fix before tag)

### M1. llmPredictBattery bypasses the llmVision image-URL admission (security, CONFIRMED)

**Where:** `src/vm/atoms/batteries.ts` ~186.

**What happens:** The `user` value is resolved and passed to `llmCap.predict` unchecked. The input schema says `user` is string | array, but `resolveInputs: false` means the resolved value is never checked against it. `buildUserMessage` (`src/batteries/llm.ts:32-50`) turns `{text, images}` into `image_url` blocks.

**Reproduced** with no allowlist: `let u = {text:'hi', images:['http://169.254.169.254/y']}; llmPredictBattery({ user: u })` reaches `predict` with the metadata URL. vLLM and mlx-vlm backends fetch that URL server-side, which is the SSRF the CHANGELOG (~188) says is closed.

**Fix:**
1. Move image admission into one shared helper, and call it from llmVision and from llmPredictBattery whenever `user` is not a string.
2. Better: make llmPredictBattery refuse an object-shaped `user` outright, by enforcing string | message-array on the resolved value.
3. Admit any `image_url` parts inside a message array the same way.
4. Add hostile rows to `battery-output-shape.test.ts` that mirror the llmVision M2 rows.

**Re-review scope:** security sibling-site sweep. Cover every atom whose capability forwards guest-chosen URLs to a backend.

## Plan (round 28, filed before acting)

**B1, root cause:** admission decided on one string (the URL resolved against a made-up base) and
the host acted on another (the raw input). **Fix: one string.** With an allowlist set, a URL that
does not parse as ABSOLUTE on its own is refused (the protocol-relative recursion goes too), and
the host fetch receives the admitted `href` whenever the URL parsed, never the raw input. Without
an allowlist, a relative URL passes as before (the host owns the destination). Rows: `\\a.test/x`,
`/\a.test/x`, `//a.test/x`, `\/a.test/x` and `/\/a.test` under `vm.run`, `Eval` and `SafeFunction`
with allowlist `['a.test']`, each refused with 0 host calls; plus a row asserting the forwarded URL
is the admitted, normalised `href`.

**M1 (llmPredictBattery bypasses image admission):** one shared `admitImageUrls` helper, used by
`llmVision` and by `llmPredictBattery`. `user` must be a string or a message array (an object
`{text, images}` is refused); `image_url` parts inside a message array are admitted the same way.
Hostile rows mirroring `llmVision`.

**Correcting my round-27 claim:** the reconcile reset was NOT equivalent. The reviewer built the
in-flight sequence (`arr.pop()` leaves every root, a `repeat` forces a reconcile, then a rebind),
under which the mutant holds about 600k over the cap. A row pins it.

**Data URLs:** accept `data:<type>[;params];base64,` for image types and octet-stream, with their
own error message, so `httpFetch`'s `dataUrl` output feeds `llmVision`.

## Round 28 — implemented (2026-10-03)

- **B1, one string.** `admitFetchUrl` returns the URL it admitted (the normalised `href` for an
  absolute URL), and both fetch paths send THAT. With an allowlist set, a URL that does not parse
  as absolute on its own is refused (the protocol-relative recursion and `RELATIVE_BASE` are
  deleted). Without one, a relative URL passes raw to a host fetch.
  - Rows: the five backslash and protocol-relative forms under `vm.run`, plus `Eval` and
    `SafeFunction` `fetchPolicy.domains`, each with 0 host calls; the host receives
    `https://a.test/y` for `HTTPS://A.TEST\x/../y`.
  - Two mutants caught (raw forward; relative passing the allowlist).
  - The caching-proxy fixture now expects the normalised URL it receives.
- **M1.** One `admitImageUrls` helper for `llmVision` and `llmPredictBattery`. A `{ text, images }`
  user is refused (use `llmVision`). `image_url` parts in message arrays are admitted. Two
  mutants caught.
- **Data URLs:** `data:image/…` or `data:application/octet-stream`, parameters allowed, base64.

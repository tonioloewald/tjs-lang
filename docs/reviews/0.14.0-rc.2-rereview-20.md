## Blockers

### M1. A zero-argument call to a POSITIONAL embedder atom arrives with `args` undefined and crashes (correctness, confirmed; lens severity major, uncertain; treated as release-blocking)

- **Where:** `src/lang/emitters/ast.ts:~2311`. `extractCallArguments` now returns `{}` when `expr.arguments.length === 0`. Before bccbecb, that case fell through to the positional branch and emitted `args: []`.
- **Who is hit:** embedder atoms whose inputSchema declares `args`, for example `defineAtom('countArgs', s.object({ args: s.array(s.any) }), s.number, async ({ args }) => args.length)`. `defineAtom`'s positional refusal (runtime.ts ~4766) deliberately exempts these atoms, so they remain a supported shape. The required `args` is not enforced when the atom is called.
- **Repro (verified):**
  - `countArgs(1, 2)` returns `{ n: 2 }`.
  - `countArgs()` returns the monadic error `"undefined is not an object (evaluating 'args.length')"`.
- **Not affected:** core atoms, `callLocal` helpers, and `Error` (its `args` is optional and read with `?.`).
- **Why it escaped:** the round-15 test rows only use named-input atoms such as `random()`. This is the empty-case pattern that lesson 9 was just added to `docs/review-lenses.md` to catch.
- **Fix:** make the empty case right at the VM layer, for both kinds of atom. In `defineAtom`'s exec, when the atom's declared inputs include `args` and `inputData.args` is absent, supply `[]`. The emitter cannot know an embedder atom's schema, so it cannot be the only place that guarantees this. Then add a row to `src/vm/guest-values.test.ts`: a positional custom atom called as `foo()` receives `[]`. Run it on both `vm` and `vm-ast`.
- **Re-review scope:** correctness and blast-radius over the remediation diff only.
- **The plan before patching:** per the STOP flag, write down the single rule for how a call's arguments reach an atom: named vs positional, empty vs non-empty, emitter vs VM. Pin all four combinations in one table test. Do not patch the one cell that broke.

## Remediation plan (round 16, filed before acting; HELD for Tonio)

**Third block in a row from remediation code.** Rounds 14 and 15 each fixed one cell of "how a
call's arguments reach an atom", and each broke a neighbouring cell. I stopped here instead of
patching a fourth time.

**Underlying mistake:** in round 15 I moved part of the rule into the EMITTER (dropping `args` for
`foo()`). The emitter cannot see an atom's schema, so it is the wrong place for any part of the
decision, and moving it there also changed the persisted AST format.

**Proposed rule (one place: the VM's `exec`):**
- Revert the emitter to base, so `foo(...)` with non-object arguments always emits
  `args: [...]`, including `[]`. That means no AST format change, and the fixtures stay as they
  are.
- In `exec`, one normalisation over the four cells:

  | atom declares | `args` is empty | `args` is non-empty |
  |---|---|---|
  | `args` (positional embedder atom) | passes `[]` | passes the values |
  | named inputs only | runs with no inputs (as `foo({})`) | refused, naming `foo({ … })` |

  `args` absent behaves the same as empty, which covers ASTs written by bccbecb's emitter.
- Pin all four cells in one table test, built from `transpile()` output, on `vm` and `vm-ast`.
- Fold in the small follow-ups:
  - `timestampOf` finite and in-range;
  - `Date.parse` rows;
  - DOCS-AJS Date forms;
  - a zero-arg row in the v2 fixture.

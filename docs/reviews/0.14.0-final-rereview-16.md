## Findings by severity

### Minor

1. **[correctness, VERIFIED] The budget-funnel guard can't see a raw run-option table re-read after admission; its header cites the deleted `snapshotTable`.** `src/budget-funnel.test.ts:37`
   - Reproduced by running `scan()` against mutated in-memory copies of `src/vm/vm.ts`. `const startFuel = options.fuel` was caught (1 → 2 violations). `quotas: options.quotas,` and `costOverrides: options.costOverrides,` in the RuntimeContext literal (vm.ts ~461) were **not** caught (1 → 1). `options.signal` was also not caught.
   - Cause: rule 2 treats a read forwarded into a budget-named key as a forward, and rule 5 trusts every RuntimeContext. The two rules vouch for each other, so the exact re-review 14/15 defect class (re-reading the caller's table after `admitRunOptions`) passes the guard.
   - Line ~43 of the header still says tables are "snapshotted at admission (`snapshotTable`)". That function was removed in 4faa343. The blind spot is also missing from the header's KNOWN BLIND SPOTS list.
   - Why this is not a blocker: there are runtime backstops (`checkedQuota`, `checkedCost`, `timerMs` at the read), and the header states that run options do not rely on this test.

2. **[security + correctness, unverified; two findings merged] `admitRunOptions` silently turns a non-plain-object options bag into `{}`.** `src/vm/admission.ts:162-163`
   - `const f = () => 0; f.quotas = { ping: 'x' }; f.fuel = NaN; admitRunOptions(f)` returns `{}`, with no refusal. `vm.run(ast, args, f)` then runs with default fuel and **no quotas**.
   - Before this diff, `validateRunOptions` read `options[name]` directly, so it refused `fuel: NaN`, and `vm.run` enforced `options.quotas`. A caller-set quota is now dropped silently, contradicting the file's own rule of "refused rather than defaulted". Only host code that ignores the `RunOptions` type can reach this. A guest cannot.
   - The completeness pass says non-object options became `{}` "same as before". That conflicts with the security lens's claim, which is one reason this stays unverified. Check it before acting.

### Nit

3. **[correctness, unverified] A cyclic prototype hangs `readOnce`.** `src/vm/admission.ts`, the `readOnce` prototype walk. An options Proxy whose `getPrototypeOf` returns itself loops forever, before any timeout is armed. Confirmed in scratch by both the lens and the completeness pass. Only a host can trigger it.
4. **[docs/correctness, unverified] CLAUDE.md overstates the quotaUsed check.** CLAUDE.md:474 says it is "checked at every read (own, writable, finite, non-negative)". `quotaCount` (admission.ts ~287) does not check `writable`; writability is checked once, at admission. An entry made read-only mid-run surfaces as a strict-mode TypeError on write-back, which becomes an AgentError. The run fails closed, but not through the check the doc describes. The CHANGELOG wording is accurate.
5. **[coverage, unverified] No test fails if `checkedQuota` is removed.** `src/vm/admission.ts:270`. There are no hits for `checkedQuota` or "Invalid quota for" in any test. It can't be reached through `vm.run`, because the admitted table is frozen, null-prototype and pre-validated. Only a hand-built ctx reaches it.

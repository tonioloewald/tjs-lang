## Blockers

### B-1: The recursive `ref` check is exponential. The coinductive set tracks the current path only and memoizes nothing *(verified; correctness blocker, merged with the security major and the efficiency minor)*
`src/lang/emitters/js.ts:~2121-2122`, in the inline `__k('ref', …)` stub, which is what emitted code runs.

The in-progress `Set` is keyed by marker instance and cleared in `finally`. Nothing records a (value, marker) pair that has already been checked. The cost therefore grows with the number of simple paths, not with nodes × types, which is what B-2 prescribed. Measured at HEAD:
- **Parent-pointer tree** (`Type TN { example: { parent: TN|null, children: [TN] } }`, the fromTS `TreeNode` shape B-2 itself cited): 121 nodes took about 1.2 s. At 364 nodes the check did not finish within 3 minutes.
- **Doubly-linked list** checked from its midpoint: about n³. 1000 nodes took about 31 s.
- **Hostile JSON, with no cycle and no shared nodes**: two recursive union alternatives that overlap (`A.next: A|B|null`, `B.next: B|A|null`) plus a bad leaf. The time doubles per level. Depth 20 is 333 bytes and takes about 200 ms. Depth 30 is about 500 bytes and takes about 3 minutes. Any `function f(a: A)` that receives untrusted input can be pinned on the CPU this way.
- **Diamond DAG / shared substructure** (`{l:d,r:d}`, `kids:[n,n]`): 2^depth. Depth 24 takes about 4.8 s.
- **Complete cyclic graph**: factorial growth. n=9 takes about 240 ms, and n=12 takes minutes.

The new test only covers a root with two leaf children, so it cannot fail on any of these shapes. The code comment's claim that each node is "checked once per path" describes the defect, not a fix. The other half of B-2, fail-closed on overflow, is confirmed fixed. No wrong `true` results appeared across 3,010 re-checks.

**Fix:** Keep a memo scoped to each top-level check, keyed by (value, marker).
- Caching `false` is always sound.
- Cache `true` only when no open in-progress assumption was consulted to reach it. Alternatively, use one assumption set per top-level check (Amadio–Cardelli) and roll it back only when a union alternative fails.
- Clear the memo in the outermost `finally`.
- As a backstop, add a budget on the number of `ref` checks per top-level check. When it runs out, fail CLOSED and record through `__kWarn`.

Add time-bounded tests for: a parent-pointer tree of at least 300 nodes (native, and via fromTS+TjsStrict), a 1000-node doubly-linked list, the overlapping-alternatives JSON chain at depth 30, a diamond DAG at depth 30, and a complete graph at n=12.

**Re-review scope:** correctness, efficiency and security over the `__k`/ref diff, plus the type-identity and differential tests.

### B-2: A recursive Type with a predicate skips its `ref` members when the runtime is installed *(verified; security major, blocking because it is an unresolved security fail-open)*
`src/lang/emitters/js.ts:~2123` and the predicate gate in `src/lang/parser-transforms.ts:~2721`.

Take `Type Node { example: { v: 0, next: Node | null } predicate(x) { return true } }`. With `createRuntime()` installed (the bun-plugin configuration), the check gates on `validate(x, __kSchema(...))`. In that schema, `next` degrades to `{}`. As a result:
- `{v:1, next:{v:'bad'}}` returns `true`.
- `{v:1, next:5}` also returns `true`, so the `next` member itself goes unchecked, not just the levels below it.

The same Type without a predicate rejects all three. So a predicate that narrows nothing widens the type, which the M-2 invariant says must never happen. The M-2 differential test only iterates over non-recursive `Type T` rows, so it cannot catch this.

**Fix:**
- On the predicate route, compose `__match(x, ex)` (coinductive) before `__g(x)`, **or** have `__kjs` emit a `$predicate`/`$ref` that calls `m.check` for a `ref`.
- Otherwise fail closed with `{not:{}}` plus a record, and never emit `{}`.
- Add recursive rows (self-ref, mutual ref, ref inside an array) to the differential test, each with and without a predicate, with the runtime installed.

**Re-review scope:** correctness and security over the schema/predicate path.

## Majors (must land before publish, not blocking re-review on their own)

- **M-1: The CHANGELOG omits the TjsStrict error short-circuit** *(verified; blast-radius, docs only)*. At `CHANGELOG.md:40`, the 0.14.0 notes invite users to put converted TypeScript under TjsStrict. Under TjsStrict, every parameter, including those declared `Error`, `any` or `unknown`, gets `if (p instanceof Error) return p`. Reproduced: `describe(new Error('boom'))` returns the Error object and never runs the body. That behaviour is documented only in TODO.md, which is not shipped in the package. **Fix:** add a line to the "What may newly REJECT" block, or a sibling "may newly short-circuit" block, that names the `safety none` workaround and says to leave TjsStrict off in files that handle errors. Re-review scope: Tier 0 (docs) only.

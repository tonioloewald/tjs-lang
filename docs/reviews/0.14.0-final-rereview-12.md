## Blockers

### B-1: predicate fuel is read outside the funnel, and `fuel: NaN` makes the runaway guard vanish (security/correctness; reproduced)
- **Where:** `src/lang/predicate.ts:726` (`compilePredicate`) and `:848` (the standalone IIFE compiler). Both do `const budget = opts.fuel ?? 1_000_000` with no validation. The schema `$predicate` path inherits this through `installPredicateSupport({ fuel })`.
- **Failure:** with `NaN`, `--__f < 0` is always false, so a verified predicate with exponential recursion runs unbounded. It pins the host thread (reproduced above; killed at 10s). At `:859`, `budget` is also interpolated raw into `new Function` source (`__f = ${budget};`), so a non-number `fuel` becomes code text. It is host-supplied, but it is still code built from an option value.
- **Why it blocks:** re-review 11 blocked on this exact shape (NaN on `transpile`'s cap), and admission.ts cites NaN-fuel as the precedent. Under "predates is not a reason", a sibling site in the same class cannot ship when its twin was blocking.
- **Fix:** validate `fuel` through the admission funnel's budget check (`isBudget`, or the same validator `validateRunOptions` uses) at both sites. Refuse NaN, negative, non-number and non-finite values, or map them explicitly. Interpolate only a validated number. Add rows for `NaN`, `-1`, `'1; x()'` and `Infinity` (decide Infinity explicitly) to a predicate test, and include the exponential-recursion shape as a positive "stops" case.
- **The cycle this belongs to:** this is the third consecutive re-review blocked on "a budget read somewhere other than the funnel". The structural fix is a single exported budget validator plus a scan-style guardrail test that fails when any `opts.fuel` / `maxSourceBytes` / `*Bytes` / `timeoutMs` option is read without passing through it. Plan that before patching the site.

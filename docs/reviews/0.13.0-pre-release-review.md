## BLOCKERS (5)

### B1 — `typeNameOptionals` is keyed by parameter NAME, so one function's `n?: T` deletes another function's genuine default
`src/lang/emitters/js.ts:993` · correctness · **new regression in this diff** (e120602)

```
const fallback = 42
function a(n?: number) { return n }
function b(n = fallback) { return n }
```
emits `function a(n)` (correct) **and** `function b(n)` — the default is deleted, `b()` returns `undefined` instead of `42`. No warning, no error, no recorder entry; `b.__tjs` also degrades to `{"kind":"any"}`. `preprocessed.typeNameOptionals` is a module-wide `Set<string>` of bare names (`src/lang/parser-params.ts:1250`); the emitter tests only `typeNameOptionals.has(paramName)`. The comment at the site claims the set exists *precisely* so the emitter would not "test the name instead" — it does exactly that, across function boundaries. Blast radius is wider than filed: arrow functions are hit too (`const arrow = (value = LIMIT) => value` → `(value) =>`), and a class method both poisons the file and fails to get the fix (`class C { m(value?: string) {} }` emits `m(value = string)` → `ReferenceError` at call time). Legal JavaScript whose meaning silently changes — a `PRINCIPLES.md` TJS ⊇ JS violation.

**Fix:** key the side channel by source position (`Set<number>` of `right.start` offsets), not by name. Add a regression test with two functions sharing a param name.

### B2 — `maxHeapBytes` is bypassable by any guest program via child-scope shadowing
`src/vm/runtime.ts:1668` · security · **new regression in this diff** (70ab7fd)

`heapPerKey` is a run-wide `Map` keyed by variable NAME, shared by reference across `createChildScope`, while scopes are prototype-chained and independent. A child-scope bind of an existing name **replaces** the parent's accounted size while the parent value stays live. Measured with `maxHeapBytes: 6MB`: control (plain `varSet` loop) correctly aborts with `Heap limit exceeded`; the attack (each `varSet` followed by `{op:'map', items:[1], as:'k'+i, steps:[]}`) returns cleanly with RSS **+672MB — 112× the cap**. Reachable from ordinary transpiled AJS source (`one.map(k0 => k0)` where `k0` shadows an outer name), not just hand-built AST. Every child-scope binder is a vector: `map`/`filter`/`find`/`reduce` (`as`), `callLocal` params. This defeats the space budget documented in `DOCS-AJS.md:139` and advertised in `CHANGELOG.md:477`, in the same release that hardened three other heap-ceiling holes.

**Fix:** scope-qualify the ledger — per-`RuntimeContext` `heapPerKey` released on scope discard, or key by `${scopeId}:${key}`. Test: N distinct keys each shadowed once in a child scope must still trip the cap.

### B3 — `demo/docs.json` is stale and ships in the npm tarball
`demo/docs.json` · docs · **regenerable, uncommitted**

Regenerated from HEAD in a scratch tree: **12 documents differ** (ASSUMPTIONS, CHANGELOG, CLAUDE, CLAUDE-TJS-SYNTAX, CONTEXT, DOCS-TJS, TJS-FOR-JS, TJS-FOR-TS, TODO, UPSTREAM, guides/footguns, guides/patterns). The shipped copy of `CLAUDE-TJS-SYNTAX.md` still contains verbatim `const p2 = new Point(10, 20) // Still works, but linter warns` (a hard compile error in 0.13.0) and `const add = wasm (a: i32, b: i32): i32 {` (a form never implemented) — the two claims quoted in `src/doc-snippets.test.ts`'s own docstring as its reason for existing. Its CHANGELOG entry tops out at `0.13.0-beta.1`. `package.json` `files` now includes `demo`, and `npm pack --dry-run` confirms a **7.1MB** `demo/docs.json` in the tarball — so the release announcing *"The npm package now ships its own documentation"* ships a second, stale copy of every doc alongside the fresh one. ### B4 — `unsafe { … }` is taught in five shipped docs; the compiler rejects it — and this release annotated two of those blocks so the new harness looks away
`DOCS-TJS.md:317` · docs

`tjs("function f(x: 0) { return x }\nunsafe {\n f('a')\n}")` → `REJECTED — Unexpected token at <source>:2:7`, in every context tried (top level, inside a function, `dialect: 'js'`, both docs' verbatim blocks). `src/lang/parser.ts:384` confirms the removal is deliberate and permanent. `CLAUDE-TJS-SYNTAX.md:211` states the fact correctly — and the fix travelled to exactly one file. Still teaching it: `DOCS-TJS.md:317`, `TJS-FOR-JS.md:485`, `guides/tjs.md:368/393/542`, `guides/benchmarks.md:43,63` (which invents semantics *and quotes measured overhead* for a form that has never parsed), `PLAN.md:70,253,541` (marks it ✅ shipped). All ship in the tarball. Worse, `3cad86c` ("fix four stale claims") inserted `<!-- tjs-doc: fragment -->` immediately above the `unsafe {` fences in `DOCS-TJS.md:321` and `TJS-FOR-JS.md:489`; `src/doc-snippets.test.ts:101` is `if (s.mode === 'fragment') continue` — asserts nothing. `bun test src/doc-snippets.test.ts` → 159 pass, 0 fail, while the flagship reference teaches a construct that cannot compile. (`guides/tjs.md` and `guides/benchmarks.md` are not in the harness's document list at all.)

**Fix:** delete the `unsafe { }` sections (point at `unsafe <expr>` / `(!)`), correct the PLAN.md rows, and where a rejection is demonstrated deliberately use `<!-- tjs-doc: expect-error -->`, never `fragment`. Consider making `fragment` require a trailing reason so it cannot be used as a silencer.

### B5 — The published `tjs-playground` bin resolves a pid from a port with bare `lsof -ti:PORT` and `kill -9`s every match
`src/cli/playground.ts:74-82` (and byte-identical logic at `bin/dev.ts:28-37`) · blast-radius

No `-sTCP:LISTEN`, no identity check, no opt-out, and the kill block runs unconditionally (the `buildDocs()` result is discarded). `lsof -ti:PORT` matches local **or remote** port. Verified with a real browser: Chrome navigated to a local server → `lsof -ti:18702` returns `12963, 68383`, where 12963 is `Google Chrome Helper … NetworkService`, still present after 30s idle — and it is returned **first**, so it is SIGKILLed before the actual server. `port` comes straight from `--port` unvalidated, so `tjs-playground --port 3000` on a consumer machine `kill -9`s their Next/Vite dev server or API, announcing it as "Killing existing process on port 3000". Nothing in `--help`, README, or CHANGELOG says the command kills processes; there is no way to decline. Not introduced by this diff, but `package.json` declares the `tjs-playground` bin and `files` includes `src`, so 0.13.0 publishes it.

**Fix (one shared helper, not two copies):** add `-sTCP:LISTEN`; positively identify the victim (`ps -p PID -o comm=` must be bun/node) and refuse otherwise; SIGTERM with a grace period before SIGKILL; **default to complaining, not killing** (`port 8699 is in use by PID x (comm); pass --force to reclaim it, or --port N`); document it in `--help` and the CHANGELOG.

## MAJORS — confirmed, do not ship silently (fix now or file with a named owner)

**Correctness**

- **TDZ: the declared-type guard `typeof X !== 'undefined'` throws** — `src/lang/emitters/js.ts:2201`. `typeof` is safe only for *undeclared* identifiers; a declared type emits as `const Color = Enum(…)`, so a top-level call before the declaration throws `ReferenceError: Cannot access 'Color' before initialization` at module load. New in `9fe9e92` (before it, the case emitted no check at all, so the same source ran clean). The guard is not dead code — it correctly protects annotations naming a never-declared type — so the fix is additive: hoist declared-type bindings above function declarations, or use a TDZ-safe probe. The comment at the site claims to handle exactly the case it fails (comment-vs-code, lens 2).
- **Arrow/function-expression params are checked but not REQUIRED, and arrow return annotations are parsed and thrown away** — `src/lang/parser-params.ts:553` (`trackRequired=false`) and `:561` (`// we extracted it but don't emit it`). `const f = (n: 0) => n*2` → `f() === 0`; `function g(n: 0){…}` → `g()` is a MonadicError. The colon *example* silently becomes a JS default (`required:false, default:0`), contradicting the language's own `:` = required rule. Separately: no `returns` metadata, no signature test (the guardrail canary `(a: 2, b: 3): 0` **throws** as a declaration and transpiles clean as an arrow), and `:?` emits no return wrapper. `src/lang/arrow-validation.test.ts` says "the control and the subject must agree" but contains **no zero-argument call anywhere**, which is why this went unnoticed. *(Merged with the ecosystem finding on issue #4 — see F-UP-1.)*
- **ASI protection inserts a `;` inside a multi-line template literal** — `src/lang/parser-transforms.ts:1094`. `c64bcd3` made the *previous* line literal-aware and left the current line raw. `` const s = `line one\n(two) three` `` → `` `line one\n;(two) three` `` plus a warning telling the author the opposite of what happened; `` const b = `a\n` `` evaluates to `"a\n;"` at runtime. Trigger: second physical line of a multi-line template starting with `(`, `[`, or `` ` `` — i.e. markdown/prose templates and the common two-line closing-backtick shape. Fix: test `maskedLines[i]`, not `line`.
- **`new X` detection is implemented twice and already disagrees — `tjs convert` emits TJS that `tjs check` rejects** — `src/lang/emitters/from-ts.ts:3207` vs `src/lang/parser-transforms.ts:4442`. Both new this release; the rewriter requires a call paren, the validator does not. Verified through the real CLI: `tjs convert pt.ts --emit-tjs` leaves `const p = new Point;` verbatim, then `tjs check pt.tjs` exits 1 with ``​`new Point()` is not allowed in TJS``. Fix belongs in the rewriter (`new Point` → `Point()`, not `Point`) behind **one** shared `declaredClassNames`/`newExpressionRegex` helper. The diagnostic also misquotes the source.
- **`src/lang/tests.ts:268 findMatchingBrace` was left literal-blind while both siblings were migrated** — `docs.ts:findMatchingBrace` and `parser-transforms.ts:findFunctionBodyEnd` were converted to the masked scan this release ("Sixth instance of the same blind spot"); the one that delimits every inline `test { }` was not. `test 'x' { const re = /[}]/ … }` makes legal TJS uncompilable (`Unexpected token`), and via `extractTests` directly a `}` in a comment truncates the body so the generated runner reports `passed: true` **with no assertion executed** — live in `docs.ts:467` and `demo/src/module-store.ts:190` (the playground *runs* that runner).

**Efficiency** — one root cause, three distinct fixes; all newly introduced or newly amplified in this diff

- **`scanLiterals` is called 175× per transpile with 91% redundancy and no memo** — `src/strip-comments.ts:205`. Base: 13 calls / 296KB / 5.5ms (10% of transpile). HEAD: **175 calls / 745KB / 11.1ms (17%)**, 35 distinct strings. A within-one-transpile `Map` memo (cleared per transpile, no staleness surface) restores base timing exactly — 64.9ms → 54.8ms, and `bun test src/lang src/strip-comments.test.ts` stays 1828/0. The consolidation was the right correctness call; nothing memoized it.
- **`extractTests` / `generateDocs` call the scanner once per item** — `src/lang/tests.ts:190` (`isInsideComment` → `commentRanges` → full scan per `test` match) and `src/lang/docs.ts:313/345/548` (`findMatchingParen` re-masks per function; `findMatchingBrace`/`computeBraceDepths` per class). `generateDocs` on a 168KB file: **9.3ms at base → 185ms at HEAD**, quadratic (185/717/2805ms at 1×/2×/4×). `src/rbac/rules.tjs` (13KB, 35 tests): `extractTests` is 31% of total transpile; hoisting the ranges out of the loop gives **6.5ms → 0.59ms**, byte-identical output. `strip-comments.ts:296` documents the fix ("Prefer `commentRanges` when testing many positions") and neither call site took it. `extractTests` runs on every playground keystroke and every `.tjs` import.
- **`dropRedundantNew` re-masks the whole output once per class** — `src/lang/emitters/from-ts.ts:3220`. Quadratic in class count: 160 classes → 7.83MB scanned, 264ms of a 305ms `fromTS` (87%). Realistic 100-class / 147KB TS: 575ms of an 837ms call. A single deduped alternation pass runs in 6ms with byte-identical output (~95×). This is the migration on-ramp and it runs in the browser playground.
- **VM loop bindings now run a full `estimateBytes` walk per iteration** — `src/vm/runtime.ts:2692`. `map`/`filter`/`find`/`reduce`/`callLocal`/catch/`varsLet`/`varsImport` bind through `setStateVar` → `trackHeapWrite`; the identity fast path can never fire for a loop variable. `filter` over 5000 records: **202 → 442 fuel (+118%)** deep, +30% shallow, wall time roughly doubled; with `fuel: 260` the base run completes and HEAD dies `Out of Fuel`. `src/vm/cost-invariant.test.ts:351` still declares map/filter SIZE_INSENSITIVE — now false. Deployed agents with budgets tuned on 0.12/0.13-beta start failing on unchanged code, and **nothing in the CHANGELOG says budgets now buy less work.**

**DX**

- **Generated `.d.ts` emits type names that are never declared — the declarations no longer compile under `tsc`** — `src/lang/emitters/dts.ts:43`. Verified against `ts.createProgram` (strict, `skipLibCheck: false`): exported Type → **TS2749** ('Even' refers to a value, but is being used as a type); unexported → **TS2552**; `Box<int>` leaks the internal hoisted name → **TS2304: Cannot find name 'Box_int'**. Before this diff the same input gave `n: any` — lossy but valid. **`src/lang/dts-type-preservation.test.ts:88` asserts the broken string**, and no dts test ever feeds output to the compiler. Guard test must use `skipLibCheck: false` or it passes vacuously.
- **`Timestamp` / `isValidTimestamp` inverted in meaning while keeping their names** — `src/types/Type.ts:370`. `(v: string)` ISO-8601 → `(v: unknown)` epoch-ms; `Type<string>` → `Type<number>`. Both changes *widen*, and `RuntimeType<T>.check(value: unknown)` never references `T`, so `tsc --strict` reports **zero diagnostics** on `isValidTimestamp(isoString)` / `Timestamp.check(isoString)` — they simply return `false` where they returned `true`. Breaks against **0.12.0**, not just the beta. No warning, no recorder entry, no deprecated alias; the CHANGELOG table is the only signal a consumer will ever get. Cheapest mitigation: warn-once when the argument is a string satisfying `isValidISOTimestamp`, naming `isValidISOTimestamp` / `TimestampISO`.
- **`--max-warnings N`, the release's flagship CI ergonomic, exists in no help text and no doc but the CHANGELOG** — `src/cli/tjs.ts:39`. `--help` lists 12 options and omits it; grep across all `*.md` returns only `CHANGELOG.md:329`. It also silently applies only to `check` — `emit`/`convert`/`types`/`run` parse and discard it with exit 0. Same commit taught `check`/`emit` to print warnings to stderr (new CI-log noise; piped stdout is clean) and gave `tjs test <file.tjs>` a new inline-test capability while `HELP` still says "Run .test.tjs test files". *(Absorbs the duplicate dx-minor.)*

**Blast radius**

- **The battery output-schema fix is absent from the CHANGELOG while a floating `^1.4.0` breaks already-released versions** — `src/vm/atoms/batteries.ts:171,230`. tosijs-schema 1.5.0 (2026-08-07) began enforcing `additionalProperties: false`; 0.12.0 and 0.13.0-beta.1 both declare `^1.4.0`, which resolves to 1.5.1 today. Verified end-to-end: an OpenAI-shaped message with `refusal`/`annotations` → `Output validation failed for 'llmPredictBattery'` (a hard `AgentError` at `src/vm/runtime.ts:2172`) under the old schema, OK under the new. A consumer on the **previous release** doing a fresh `npm i` breaks with no change on their side, and grepping the 0.13.0 section for `tosijs|schema|batter|llm|vision` returns nothing. UPSTREAM.md/TODO.md document it but neither ships in `files` — while `CHANGELOG.md` was *added* to `files` this release.

**Practices** *(these compound; they are not holding the tag)*

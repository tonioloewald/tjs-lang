## 🚫 Blockers — must fix before tagging

### B1 · Any parenthesised concise arrow body emits JavaScript that does not parse
`src/lang/emitters/js.ts:1225-1246` (correctness · **confirmed**, reproduced again during triage)

The `__exprBody` branch anchors its two insertions at `func.body.start` / `func.body.end`, which is acorn's span for the concise-body *expression* and excludes any surrounding parentheses. `const point = (x: 0, y: 0) => ({ x, y })` emits a statement block spliced into object-literal position:

```js
const plain = (a, b) => ({
  __tjs.pushStack('<source>:2:plain');
  if (a instanceof Error) return a;
  return { a, b }
  __tjs.popStack();
})
// PARSE FAIL: Unexpected token '.'. Expected a ':' following the property name '__tjs'.
```

Three things make this worse than filed:

1. **It is not specific to object literals.** Any parenthesised concise body fails — `(n: 0) => (n + 1)` too. The paren is outside the body node's span regardless of what it wraps.
2. **It fires on unannotated plain JavaScript.** The snippet above has no `:` anywhere. Legal JS in a `.tjs` file emits unparseable output — a **PRINCIPLES.md "TJS ⊇ JS" subset violation**, the class `src/lang/subset-invariant.test.ts` exists to prevent. (`dialect: 'js'` / `fromTS` are unaffected.)
3. **`tjs check` reports the file clean** (`✓ … point(x: integer, y: integer) -> void`) while `tjs run` fails with `3 errors building …tjsrun.mjs`. Nothing warns before the module fails to load.

New in this release — `__exprBody` does not exist at `v0.13.0-beta.1`; introduced by `21f342d`. `src/lang/arrow-validation.test.ts` has zero cases with a parenthesised concise body, which is why the suite is green.

**Fix:** when `__exprBody` is true, *wrap* rather than splice — insert `{ <checks> return (` at body.start and `) }` at body.end so the parens nest. Add `(n: 0) => ({ a: n })`, `=> (n + 1)`, plus `async` and `export const` variants to `arrow-validation.test.ts`, asserting the emitted code **parses** and returns the right value.

**Adjacent, fix in the same pass:** `__tjs.popStack()` is inserted *after* the `return` in every concise-arrow body (visible above, and in the `=> [n]` case that parses fine). With `callStacks: true` the stack grows unboundedly for concise arrows.

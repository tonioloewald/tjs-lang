## Blockers (fix before tag)

### B1. In allowlist mode, `httpFetch` checks the hostname but not the scheme, so a guest can read host files (security, blocker, **confirmed**)
`src/vm/runtime.ts:6230` (`isDomainAllowed` at about line 6148).

When `allowedFetchDomains` is set, the code skips `isBlockedUrl` ("allowlist takes precedence"). That function is the only place http/https is enforced, and `isDomainAllowed` compares only `new URL(url).hostname`. Bun's `fetch` serves `file:` URLs and ignores the host part.

The verifier reproduced it on Bun 1.4.2. With `allowedFetchDomains: ['api.github.com']`, `httpFetch({ url: 'file://api.github.com/etc/hosts', responseType: 'text' })` returns /etc/hosts to the guest. A `*.github.com` wildcard is just as exposed. `file://<host>/dev/zero` reads without limit until the 30s timeout, because the 4MB membrane cap only applies after the read. This affects any Bun or Deno server that runs untrusted AJS behind an allowlist. Node and browsers refuse `file:`, so `functions/` and the doc site are not affected.

**Fix:** enforce the scheme in both modes, failing closed: only `http:` and `https:` pass, checked before the allowlist. Optionally restrict ports to the defaults unless an allowlist entry names a port. Add allowlist-mode rows to `malicious-actor.test.ts` for `file://<allowed-host>/…`, `data:`, `blob:` and `ftp:`, and show that they fail on the pre-fix code.
**Re-review scope:** security + correctness over the remediation diff.

### M1. `vm.run` writes the default store into the caller's capabilities object, so data crosses runs and tenants (security, major, **confirmed**). Must fix before tag.
`src/vm/vm.ts:330`.

`admitRunOptions` classifies `capabilities` as `opaque` and returns the host's own object. `capabilities.store = {…new Map…}` then writes into it. The verifier reproduced this: run A calls `storeSet({key:'secret'})`, and run B, sharing the same `caps`, reads it back with `storeGet`. After the runs, `Object.keys(caps)` is `['store']`, and later runs no longer print the "default in-memory store" warning. Passing `Object.freeze({})` makes `vm.run` throw instead of returning a monadic error.

**Fix:** never write to the caller's object. Copy it once (preferably in `admitRunOptions`) and attach the per-run default store to the copy. Add tests for: two runs sharing one capabilities object with no store passed (no data crosses, host object unchanged); frozen capabilities; and nested `agentRun` still seeing the same per-run store.
**Re-review scope:** security + blast-radius.

## Plan (round 20, filed before acting)

**Underlying problem (B1 and the redirect/body minor):** "may this URL be fetched, and how much
of it" is answered in PIECES. `isBlockedUrl` checks the scheme and private ranges, but only when no
allowlist is set; `isDomainAllowed` checks only the hostname; a redirect is followed by the host's
`fetch` with no check at all; and the body is read in full before any size cap. Each piece is right
about its slice, and the gaps between them are the holes.

**Fix: one admission function, applied at every hop, plus one bounded reader.**
- `admitFetchUrl(url, ctx)`:
  - the scheme must be `http:` or `https:`, in BOTH modes, checked first and failing closed;
  - then the allowlist (when set) or the private-range block (when not).
- Redirects: `redirect: 'manual'`, and every `Location` goes through `admitFetchUrl` again, with a
  hop cap.
- Body: read through a byte-counting stream reader that aborts past `membraneMaxBytes`, before
  any `text()`, `json()` or `dataUrl` build.
- Rows (in `malicious-actor.test.ts`, shown failing on the pre-fix code):
  - `file://<allowed-host>/…`, `data:`, `blob:` and `ftp:` in allowlist mode;
  - a local fixture server redirecting to a blocked address and to a disallowed host;
  - an over-cap body aborted early.

**M1 (the capabilities object is mutated):** the VM must never write to a host object.
`admitRunOptions` already copies every other option once; `capabilities` gets the same treatment,
with a shallow copy made once per run, and the default store attached to the copy. Rows:
- two runs sharing one capabilities object, with no data crossing;
- the host object unchanged afterwards;
- a frozen capabilities object returns normally;
- nested `agentRun` sees the same per-run store.

**Minors taken in the same round:**
- Reserved step keys (`op`, `result`, `resultConst`, `resultAssign`) are refused as atom inputs
  for EVERY atom, at the property, in the transpiler.
- The wall-clock test flakes move to work or fuel assertions where possible; the regex fuzz gets
  an explicit timeout.

The rest are carded.

## Round 20 — implemented (2026-10-03)

- **B1.** `admitFetchUrl` is the one rule, applied to the first request and to every redirect
  hop. The scheme must be `http:`/`https:` in both modes. Then the allowlist applies, or, without
  one, nothing is allowed.
  - The unreachable "localhost only" branch is gone and the docblock is corrected (#2819).
  - Redirects are followed by the VM (`redirect: 'manual'`, at most 5 hops). A browser's
    opaque redirect is refused.
  - The body is read through `readBounded` under `membraneMaxBytes` (`content-length`
    pre-check, then a streaming byte count).
  - Rows in `src/vm/fetch-admission.test.ts`, all failing on the pre-fix code:
    `file://<allowed-host>`, `ftp:`, `data:`, `blob:`; redirects to the metadata address, to an
    outside host and to `file:`; a 32MB body aborted near a 1MB cap.
- **M1.** Each run gets its own shallow, null-prototype copy of the capabilities object; the host's
  is never written. Rows cover: no store shared between runs, the host object left unchanged, a
  frozen object, and nested `agentRun` sharing the run's store.
- **Minor.** Reserved step keys (`op`, `result`, `resultConst`, `resultAssign`) are refused as atom
  inputs for every atom, at transpile time.
- **Minor (failing tests).** The three wall-clock flakes are fixed:
  - Set intersection now checks SCALING (n vs 4n, best of 3; a quadratic mutant is caught).
  - The B3 rate rows take the best of 3.
  - The regex fuzz has a 30s timeout.
- **Docs.** The stale positional `storeSet`/`storeGet` example in the `storeGet` docblock is fixed.
- **Mutation:** 5 of 5 caught (scheme check, redirect re-admission, body cap, capabilities copy,
  quadratic intersection).
- **Lanes:** format, lint, make, test:fast (7050), dogfood, full without the live LLM (7069, 0 fail).

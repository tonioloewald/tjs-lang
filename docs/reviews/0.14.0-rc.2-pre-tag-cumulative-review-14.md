## Findings (deduplicated)

### Minor
1. **The outbound membrane builds the full copy before the heap gate, breaking I1. VERIFIED.** This merges correctness #1, security #7 and a completeness gap. `src/vm/runtime.ts` ~824 (`admit?.(bytes)`) and ~4803 (`egressValue`).
   - Before this change, `allocate()` ran between the read-only walk and `structuredClone`. Now it runs only after `membraneValue` has built the whole copy.
   - The copy is budgeted by `min(membraneMaxBytes, fuel/FUEL_PER_ALLOCATED_BYTE)`. `maxHeapBytes` is never consulted before the copy exists.
   - Measured: a 500k-number array has a heap delta of ~71MB at the moment `admit` fires, against ~19MB at base. That is about 17x the budget, driven by the per-slot `Slot` objects, `put` closures and `entries` tuples.
   - It is bounded and reclaimed, and a refusal halts the run, so it happens at most once per run. It is not an escape.
   - `docs/vm-budgets.md` I1 ("a budget checked after the allocation has already lost") now contradicts the table row at ~182 ("copy BUILT … then charged").
   - **Fix:** either add heap headroom to the egress budget (`min(cap, payable, heapHeadroom)`) or call `admit` incrementally during the walk. Drop the per-slot closures: store `{v, depth, parent, key}` and use parallel key/value arrays. Then restore I1 for this door, or state the exception in I1 itself. Add a host-memory-ratio probe row to `vm-budgets.test.ts` / `egress-cost.test.ts`.
2. **Five consumer-facing sites still describe the removed `structuredClone` contract. VERIFIED.** This merges blast-radius, correctness #2, security nit #10 and a completeness gap.
   - `src/lang/eval.ts:69`: public JSDoc, which reaches the `.d.ts` hover.
   - `guides/safe-eval.md:120`
   - `llms.txt:121`
   - `docs/ajs-native-vm.md:115`
   - `src/vm/runtime.ts`: the module docstring (~590-610) still describes "pre-walk then structuredClone … defense in depth" and the "structured-clone builtins" value model.
   - `src/vm/runtime.ts:380, 443, 8122`, the `egressValue` docstring (~4754, "BEFORE structuredClone runs") and `src/vm/regex.ts:916` say the same.
   - Consequence: consumers are told that structured-cloneable values are fine, but a Map, Uint8Array or Error is now refused and ends the run. Reviewers are told a second defensive layer exists, and it does not.
   - **Fix:** reword every site to "JSON data plus Date; the membrane builds its own copy; Map/Set/typed arrays/ArrayBuffer/RegExp/Error are refused". Run `bun run docs`. Optionally add the phrase to the `docs-tombstones` guard.
3. **A Date subclass, or a Date carrying own fields, is silently thinned to a bare Date (unverified).** `runtime.ts` ~767, `dateTime()` brand check.
   - Previously this was refused as "a Date subclass". Now prototype getters and own fields read as `undefined` in the guest, which is the M-2 fail-open class: a negated rule can flip deny to allow.
   - A test now pins the thinning as intended.
   - **Fix:** accept only `getPrototypeOf(v) === Date.prototype` with no own keys and refuse anything else as shape. If thinning is deliberate, document it in CLAUDE.md and DOCS-AJS as a reviewed decision.
4. **The hand-built copy is 1.4-1.9x slower on large payloads and uses about 65% more transient heap (unverified).** `runtime.ts` ~700.
   - 400k floats: 127→180ms. RAG-shaped return: 3.5→6.8ms. Small payloads are unchanged.
   - Causes: a closure per slot, a double `defineProperty` per object key, and `defineProperty(String(i))` per array element.
   - **Fix:** assign array elements directly (`copy[i] = c`), define each property once (keep `defineProperty` only for `__proto__` or null-prototype copies), and record the cost in the CHANGELOG or a budget row. This shares its fix with #1.

### Nit
5. **Non-index own properties on arrays come out in reverse order in the copy (unverified).** `runtime.ts` ~907, `readArrayData`. Each `put` is LIFO. **Fix:** pre-define the keys in source order, as the object branch does, and add an array row to the key-order test.
6. **The refusal for Map/Set/typed arrays/RegExp/Error gives the class-instance reason (unverified).** `runtime.ts` ~786. "Convert it to a plain object" is the wrong advice for a typed array. **Fix:** give the newly refused built-ins their own message ("JSON cannot express it; use Array.from / an object / an array of pairs").
7. **The build prints no per-target size delta (unverified).** `scripts/build.ts` ~250. This diff shrank tjs-vm-ast by 1.3KB raw / 290B gzip, measured by hand. **Fix:** record the last release's sizes and print a delta column.

### M1. An untyped `args` input is no longer positional, so positional calls that worked in rc.1 and 0.13 are refused (blast-radius, confirmed; lens severity major, uncertain; treated as release-blocking)
- **Where:** `src/vm/runtime.ts:4733` (`callShape`), `isPositionalAtom` ~4753.
- **What:** `defineAtom('sumAll', s.object({ args: s.any }), …)` called as `sumAll(1,2,3)` now returns `{ $error, message: "'sumAll' takes named arguments: sumAll({ args })" }`. At base the exemption `!named.includes('args')` let it run with `args: [1,2,3]`. `isPositionalAtom` recognises only `type === 'array'` or a type list containing `'array'`. `s.any`/`{}`, an untyped `args` and `anyOf` unions that include an array all fall through to "named".
- **Why it blocks:** the same reasoning as the 20th re-review's M1. This diff introduced the regression, against behaviour already published. It surfaces only at guest run time, and the error message points the author at the wrong fix. The review history and `feedback_correct_over_fast` both say known regressions get fixed before an rc ships.
- **Fix (decide the cell, then pin it):** either (a) treat any declared `args` whose schema does not rule out arrays (no `type`, `{}`/any, or an `anyOf`/union that includes an array) as positional, which keeps the rc.1 behaviour, or (b) keep the refusal, document it in the CHANGELOG's positional-call paragraph ("an `args` input must be declared as an array to take positional arguments") and say so in the error message. In either case, add the `args: s.any`, `args: {}` and union-with-array cells to `CELLS` in `src/vm/call-shape.test.ts` on both `vm` and `vm-ast`. Fix M1 and m1 together, because both are cells of the same table (see the cycle flag).

## Diagnosis and proposed spec (filed before acting; HELD for Tonio)

**Why four rounds:** every round classified atoms by READING THEIR SCHEMAS, and schemas are an
open domain: `s.any`, unions, records, optional arrays, mixed named plus `args`. Each new
classification rule changed the behaviour of some shape that already worked, and each round
found one more such shape. I also invented new behaviour along the way: defaulting `args` to `[]`
and stripping an empty `args`. That added cells the table never needed.

**Proposed spec: refuse only what cannot have worked, and pass everything else through as
written.** A positional call (non-empty `args`) is refused only when the atom declares named
inputs and declares NO input called `args`. An atom like that never reads `args`, so the call
already ran with every input undefined. Every other step runs exactly as it did in rc.1:
- no `args` default;
- no stripping;
- no reading of `args`'s type.

So the rule is a strict narrowing to calls that were already broken, and it cannot regress a call
that worked. This is base behaviour plus one refusal. The emitter stays at base. The table test
keeps every cell, and each cell's expected value is rc.1's behaviour, except the refused one.

**Follow-ups:**
- m2: a bad date string is refused at `dateLike` (one definition: `timestampOf` is not NaN).
- m1 (an atom with `args` plus other named inputs called positionally) gets a card. It predates
  this work, and refusing it needs the same care.
- m3: `test:grok` before tagging.

and chose **named-only atom calls**. That is the #2789 rule, triggered as it says: blockers
cascading from an inherited JavaScript-ism.

## Follow-ups

### → this repo's `TODO.md` (correctness / security / efficiency)

Correctness and security:

- [ ] **Make the M-1 "every non-literal AST execution is gated" sweep complete** *(unverified; merged from the correctness and security lenses, both minor)*. The sweep's regex is `\b(?:seq|seqAtom)\.exec\(`. It misses `vm.ts:327`, `this.resolve('seq')?.exec(ast, ctx)`, so vm.ts contributes **zero** sites and removing `AgentVM.run`'s gate would not be caught. It also cannot see `?.exec` or `!.exec` receivers, aliased resolvers (`const r = ctx.resolver('seq'); r.exec(x)`), or anything under `src/vm/atoms/*` and the batteries. The search back for a gate stops only at exported atoms, so an exec inside a non-exported helper can count the previous function's `checkAstVersion` as its own gate. The apparatus check `sites >= 3` is met by runtime.ts alone. Fix: walk the enclosing function with acorn or the TS parser rather than a regex (see the guard-both-directions lesson). Match on receivers that resolve to `seq`. Make the site count exact (4). Add a negative fixture with an ungated `runner.exec(x)` so the test is shown to go red. Also pin that the `{op:'seq', steps}` wrappers only take `steps` from the already-gated parent. Until this is done, soften the CHANGELOG from "sweeps every such site" to "every `seq.exec` site".
- [ ] **Test the toJSON non-enumerability fix at the `brandPredicate` site** *(unverified, minor)*. `src/types/predicate-brand.ts:169`: putting `enumerable: true` back leaves `bun test src` green. The existing test covers only Type, Enum and Union, which get toJSON earlier from `Type.ts asPredicate`. Add a value produced by `brandPredicate` (`brandPredicate(v => v === 1, 'one')`, or `isColor` from `src/css`). Assert that `Object.keys(p)` contains no `toJSON` and that `{...p, description:'X'}` has no toJSON. In the same change, fix the stale comment `toJSON — likewise`.
- [ ] **Make the release tooling's clean-tree checks fail closed** *(unverified; merged from a correctness minor, a security nit and a completeness gap)*. `writeStamp`, `releaseStampProblem` (`scripts/release-stamp.ts`), `treeClean()` (`scripts/release-gate.ts`) and `prepublish-check.ts:92` all compare only stdout to `''`. A failing `git status`, for example on a corrupt index, therefore reads as a clean tree. All four also inherit `status.showUntrackedFiles`. Today the publish is saved only because `git ls-files` happens to fail the same way. Fix: one exported `treeDirtyReason(root)` helper that runs `git status --porcelain --untracked-files=all`, treats a non-zero exit as a refusal, and is used at all four sites. Add a test that corrupts `.git/index` in a scratch repo and expects `writeStamp` to refuse. Also add a test of `release-gate.ts` as a script, since today only the stamp module is tested.
- [ ] **Stop the release gate inheriting `SKIP_*` variables** *(completeness gap; this predates the diff)*. `scripts/release-gate.ts` and the pre-push worktree run `bun test` with the caller's environment. If `SKIP_LLM_TESTS`, `SKIP_BENCHMARKS` or `SKIP_AUDIT` are exported in the shell, the "FULL suite" skips those lanes and still stamps HEAD. This is the one remaining way a stamp can certify a lane that never ran. Either scrub these variables or refuse to run when they are set.
- [ ] **TODO.md:4253 is stale** *(unverified, nit)*: it still says "HEAD is `0.14.0-rc.0`". When this review closes, tick it and move it to Completed, citing this review.

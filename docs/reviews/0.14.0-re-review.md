## Blockers

### B-1: release-gate stamps a dirty tree, so a later publish skips the gate and ships untested dist/ (confirmed)
**File:** `scripts/release-gate.ts` (~84–171) · lenses: security + correctness (merged; the security wording is kept)

The clean-tree refusal only runs under `--prepare`. That covers both the check before `make` at ~110 and the one after it at ~134. The plain `prepublishOnly` path runs `make` and `bun test` on whatever is on disk. It then writes `.release-gate` (HEAD plus a hash of that dist/) and appends HEAD to `.release-gate-verified` without checking anything. `prepublish-check.ts` runs *after* this and refuses because the tree is dirty.

The failing sequence:
1. The author runs `npm publish` with uncommitted edits.
2. The gate stamps HEAD, and prepublish-check refuses the publish.
3. The author runs `git checkout .` or `git stash`, which is the obvious response to that refusal.
4. The author runs `npm publish` again. The stamp matches HEAD, the tree is clean, and the dist/ hash is unchanged. The gate prints "Not re-running", and npm packs HEAD's src/ with a dist/ built from code that is in no commit.

The ledger then also lets `.githooks/pre-push` pass a tag on that SHA without running the suite. This is the 0.13.7 src/dist divergence shape, on the one step that cannot be undone. The docstring claim that "skipping release:ready costs time, never safety" is false on this path. prepublish-check.ts:~48 is also stale: it still says `make` always runs first.

**Fix:** run the `treeClean()` refusal before `make` in *both* modes. Write the stamp and the ledger only if the tree is still clean after the suite. Add a test for the writer: factor out the should-stamp decision and assert it refuses on a dirty tree. Correct both docstrings.

## Majors (must fix before publish: unresolved correctness/security)

### M-1: M3 is marked RESOLVED, but the agentRun inline-AST branch bypasses `checkAstVersion` (confirmed, two lenses)
**File:** `src/vm/runtime.ts` ~3992–4010

`if (resolvedId && typeof resolvedId === 'object' && 'op' in resolvedId)` goes to `seqAtom.exec(resolvedId, childCtx)` without a version check. It needs no capability. I reproduced it on HEAD:
- `vm.run({$ajs:99,…})` is refused, and so is `$ajs:'2'`.
- The same ASTs passed as `agentId`, either inline or through `args.sub`, run and return `{ran:'yes'}` / `{hi:'from-future'}`.

This is the original review's own repro, and the fix it prescribed covered "both agentRun branches". `ast-version-boundaries.test.ts` cannot see the gap: its sweep only enumerates `procedureStore.get(` readers. Nothing is exploitable today, because `AST_VERSION` is 1. It becomes wrong-semantics execution of untrusted code on the day v2 ships, and ASTs are already persisted.

**Fix:**
- Call `checkAstVersion(resolvedId, 'agentRun')` before the inline `seqAtom.exec`.
- Add behavioural cases for inline `$ajs:99` and inline `$ajs:'2'`.
- Widen the structural sweep to every `seqAtom.exec` / `resolver('seq')` call site that gets a non-literal AST.
- Decide about `runCode` (~4145), which also runs a capability-returned AST with no gate. See gaps.
- Correct the M3 STATUS block in `docs/reviews/0.14.0-pre-release-review.md`.

### M-2: Emitted Generic instances are plain objects, while library Generic instances are callable Predicates (confirmed)
**File:** `src/lang/emitters/js.ts` ~2085; `src/lang/predicate-callable.test.ts` FORMS (~109–128)

The emitted stub returns `const t={…check…};return t` with no `__pred` wrap. With the library, `typeof Box(Type('n',0)) === 'function'`. In emitted code `typeof Box(0) === 'object'`, and `Box(0)(v)` throws "is not a function". Emitted code always uses the stub, so this is B1's divergence again on a sixth form. FORMS covers Type, Enum, Union, Exactly and FunctionPredicate, but not Generic, so the B1 STATUS line "all five forms" is accurate but incomplete. The generic FunctionPredicate factory has the same shape: its instances are wrapped, the factory is not.

**Fix:** return `__pred(t, t.description)`, and add a Generic-instance row to FORMS so the callable, check-identity, naming and serialisation cases run on both sides. If leaving instances non-callable is deliberate, document it in `docs/type-identity.md` and pin it with a test instead.

**Re-review scope after the fixes:** correctness + security over `release-gate.ts` and its tests, `runtime.ts` agentRun/runCode, `ast-version-boundaries.test.ts`, the emitted Generic stub and FORMS, plus Tier 0. Also look at the version-bump commit (rc.1 or 0.14.0 plus CHANGELOG), which is not in this diff.

## Completeness gaps (from triage; each is scheduled, none dropped)
1. **Diff basis.** The diff is sound and clean (13 commits, not the 14 the brief says). src/ has not changed since 9bd4519, so the rc.0 that tosijs-ui verified has the same shipped code as HEAD. **But** HEAD is `0.14.0-rc.0`, which is already published. The commit that will actually ship (version bump, CHANGELOG, regenerated artifacts) has not been reviewed and must be covered by the re-review.
2. **`runCode` (~4145)** runs whatever AST `ctx.capabilities.code.transpile()` returns, without `checkAstVersion`. The host supplies that capability, so this is less severe than M-1, but it is still a door missing from the "enumerable" list. Decide as part of the M-1 fix: gate it, or exempt it with a written reason.
3. **`astVersionProblem`**: `JSON.stringify(ast.$ajs) ?? String(…)` throws a TypeError on a BigInt or cyclic value (`??` does not catch a throw). It still fails closed, but with the wrong error, and a very large `$ajs` string is copied whole into the message. Wrap the call in try/catch and truncate the output.
4. **Global brand slot** `globalThis.__tjs_Predicate_1 ??= PredicateBrand`: a script loaded earlier can pre-seed it and so decide `instanceof Predicate` and the prototype that `brandPredicate` installs, getters included. This is the same trust model as MonadicError, but nobody has signed off on it for a brand that type dispatch reads. Record the decision in `docs/runtime-fusion.md`. Also, `Predicate` changed from `export class` to `export const` plus a type alias, which changes the .d.ts, and the docs/dx lenses were skipped. Needs a CHANGELOG note.
5. **Emitted Enum, Union, Exactly and FunctionPredicate are now functions.** `typeof`, spread and `Object.keys` all behave differently for consumers of emitted code. `toJSON` only restores JSON output. This needs a CHANGELOG "Changed" entry. Nothing guards against `Object.assign(f, t)` throwing in strict ESM if a stub ever gains an own `name` or `length`. Add that assertion.
6. **sideEffects "derived"**: the global-slot write in `predicate-brand.ts` runs in bundles (tjs-css, lang, browser and others) that are not in the `sideEffects` list. Nobody has checked that a consumer's tree-shaker cannot drop the slot claim and bring back B2's split-brand `instanceof`. Add a bundle-level test with a real bundler's tree-shaking.

*No cycle flag. B-1 is in new release tooling (aef1153), not in the remediation of a prior blocker, and no lens has blocked twice this cycle. The M3 remediation being incomplete is a major, not a blocker.*

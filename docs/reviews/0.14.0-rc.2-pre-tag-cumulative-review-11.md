## Blockers (confirmed)

### B1: A depth refusal is classed 'shape', so a remote server can halt any agent with an error it cannot catch
`src/vm/runtime.ts:737`, then `ingressValue` (around line 4957), then `haltRun`. *(Lenses: security and correctness, merged. Verified by both, and reproduced.)*

- `membraneValue` returns `kind: 'shape'` when `depth > MEMBRANE_MAX_DEPTH` (10,000), and `ingressValue` halts the run on any 'shape' refusal.
- Depth is set by the world's data, not by the host. httpFetch's global-fetch path (around line 7035) runs `JSON.parse` on the remote body. A host fetch capability that returns `JSON.parse(body)`, or a model's parsed JSON, is exposed the same way.
- Reproduced: a body of `'['.repeat(10050)+']'.repeat(10050)` (about 20KB) ends the run with "…exceeds the membrane depth limit", and the guest's `try { httpFetch(...) } catch {}` never runs. At depth 9000 the run completes normally.
- This is the same class round 36 fixed for size (review 10, B1), and this payload is about 1% of the size the size band needed.
- The docs disagree with themselves. DOCS-AJS and the CHANGELOG say the world's failures are catchable. The `ingressValue` docstring lists "nesting past the limit" under the host's contract.

**Fix:** classify a depth refusal as world-caused, using 'size' or a new catchable and billed 'limit' kind. Keep 'shape' for non-data only: function, symbol, bigint, accessor, class instance, exotic Map/Set, and values that cannot be cloned. Also check the `structuredClone` catch (around line 868, `kind:'shape'` for anything that cannot be cloned) for triggers the world controls. Add a membrane-halt row in which httpFetch over a stubbed global fetch returns deep JSON inside `try`: the catch must run and the walk must be billed. Fix the docstring and DOCS-AJS.

### B2: A thrown AgentError skips `reduceThrown`, so a live host object or an uncapped message reaches the guest through `try`
`src/vm/runtime.ts:5410` (defineAtom catch) and `:5711` (tryCatch bind). *(Lens: correctness, verified and reproduced. Merged with the security lens's unverified minor "tryCatch bind trusts producers".)*

- `ctx.error = e instanceof AgentError ? e : new AgentError(reduceThrown(e), op, e)`. When the thrown value is an AgentError, it is kept as thrown.
- The AgentError constructor reduces only non-string messages. It never caps a string and never touches `op`.
- tryCatch binds `ctx.error.message` and `ctx.error.op` without reducing them.
- Reproduced with `transpile()` output:
  1. `throw new AgentError('m', sharedObj)`: the guest's `errorOp === shared`, and it comes back in the result by identity.
  2. `throw new AgentError('z'.repeat(1e6), 'boom')`: the guest gets a 1,000,000-character string (5M also reproduced, about 5.7 fuel), well past the 8KB cap.
  3. A forged `Object.create(AgentError.prototype, { message: { get } })`: the host getter runs inside tryCatch, and the guest receives a live host object.
- Also possible, by inspection: an atom that sets `ctx.error` directly, or mutates `.message` after construction, bypasses exec's catch entirely.
- The new parse guard (`membrane-doors.test.ts`, `catchClausesBuildingFromCaught`) cannot see the pass-through branch.

**Fix:** reduce where the value enters guest scope. tryCatch should bind `reduceThrown(ctx.error)` plus a string-coerced, capped `op`. Optionally, also have the AgentError constructor cap strings and coerce `op`, and replace `instanceof` with a private brand (a WeakSet of errors the VM minted). Add membrane-halt rows for all three reproductions. Strengthen the parse guard: it should flag `ctx.error = e`, values derived from `e` through intermediate variables, and the instanceof pass-through, and a mutation check should prove it can go red.

**Re-review scope:** correctness plus security over the remediation diff (the `kind` classification at every membrane refusal site, and every route by which a thrown value reaches the guest), plus the strengthened membrane-doors parse guard.

## Round 37 — plan (written before any code, per the cycle STOP)

**The underlying problems.**
1. **B1: the classification had no stated criterion.** I sorted refusals into "host" and "world"
   by instinct, and depth went to the wrong side. The criterion has to be one testable sentence:
   **a refusal that plain JSON can trigger is the world's** (it says nothing about the host's code
   and everything about the data), and **a refusal that JSON cannot express is the host's**
   (functions, symbols, bigints, accessors, class instances, exotic Map/Set). So `kind` becomes
   `'limit' | 'shape'`: size, depth, and a `structuredClone` stack overflow (a `RangeError`, which
   very deep JSON can cause) are `'limit'`. The criterion is pinned by a property-style row:
   generated JSON values (deep, wide, long, mixed) may be refused, but never as `'shape'`.
2. **B2: reduction at the producer cannot be complete.** Anything can construct or forge an
   `AgentError`, or set `ctx.error` directly. The value is dangerous only where it ENTERS GUEST
   SCOPE, and there is exactly one such place, the `try` bind. So the reduction moves to that
   consumer:
   - the bind receives `reduceThrown(ctx.error)` and `reduceOp(ctx.error)`;
   - both read OWN DATA properties only, never a getter and never `String()`/`toString` (host
     code), and both cap;
   - the sub-agent rethrows (`childCtx.error.message`, `result.error.message`) use the same reducer.
   - **Ratchet** (parsed, in `membrane-doors.test.ts`): every read of `.message` or `.op` on an
     error-valued expression in `src/vm/**` is an argument of `reduceThrown`/`reduceOp`, or is
     allowlisted with the reason it never reaches a guest. Apparatus: a planted raw read fails it.
3. **Low-fuel shape refusal:** bill, then a `'shape'` refusal ends the run with ITS reason whatever
   the fuel. The halt does not depend on how much fuel was left.
4. **One fuel-charge helper** (`chargeWalkFuel`) for the inbound bill and the outbound `bill`
   (Infinity guard, floor at zero), replacing two hand-written copies.
5. **Rows:**
   - deep JSON returned by a capability inside `try` is caught and billed (the review's 20KB
     body);
   - the JSON-producible property row;
   - a low-fuel shape refusal halts with its own reason;
   - B2's three reproductions: an `op` that is an object, a 1M-char message, and a forged
     `AgentError` with a getter (it never runs, and the guest gets capped strings);
   - mutation-checked.
6. **Docs:** the criterion goes into the `ingressValue` docstring, DOCS-AJS and the CHANGELOG
   ("could JSON have done this?").

Re-review scope: correctness + security over the round-37 diff.

## Blocking (verified majors, correctness/security)

1. **Round 33 regression: a NaN fuel meter under `fuel: Infinity`** (security/correctness, `src/vm/runtime.ts:4816`, `bill()` in `egressValue`). **Verified.**
   - `spent = Infinity - Infinity` gives NaN, so `owed` is NaN and `ctx.fuel.current` becomes NaN.
   - One refused `storeSet` caught by the guest still ends the run with `{ $error, message: 'Out of Fuel', op: 'catch' }` and `fuelUsed: NaN`. The same program at `fuel: 1e9` returns normally.
   - Admission documents `Infinity` as "no limit" (`admission.ts:85`). Round 32's `current -= budget*F` kept Infinity, so this is new in this diff.
   - It fails closed, so it is not an isolation hole. It does break the stated invariant "Out of Fuel only when fuel actually reaches zero", and it is exactly what `checkedCost` exists to prevent.
   - **Fix:** in `bill`, skip the arithmetic when fuel is not finite. Add an `egress-cost.test.ts` row: a caught refused egress under `fuel: Infinity` returns the catch result, and `fuelUsed` is never NaN.

2. **A refused egress of a wide object, Map or Set is billed at most the budget for O(N) synchronous work** (security, `src/vm/runtime.ts:877`, `overBudget()` / `readOwnData`). **Verified.**
   - `readOwnData` runs `Object.keys` and one `getOwnPropertyDescriptor` per key before the budget is checked. Map/Set entries are all pushed before any check. Only `readArrayData` bails per element.
   - Measured with a 300k-key object through `storeSet`:

     | `membraneMaxBytes` | Extra refusals | Time | Fuel billed | Rate |
     |---|---|---|---|---|
     | 1024 | 49 | about 1.5–1.9 s | about 287 | about 30 ms per refusal for about 6 fuel |
     | 4 MB (default) | 49 | about 1.8 s | about 10.5k | — |

   - The amplification is about object bytes divided by the budget. A host that hardens with a small budget gets the *worst* ratio. Atom timeouts cannot interrupt synchronous work.
   - The flaw predates round 33, but round 33 is the change that documents refusals as "billed exactly the work done". The repo's rule is that "it predates this" is not a reason to defer.
   - **Fix:** bail per key in `readOwnData` (and per entry for Map/Set), or report `walked` as the bytes actually tallied. Add a row: a refused egress of an N-key object under a small budget costs fuel ∝ N.
   - **Re-review scope:** correctness plus security over the membrane walk and the remediation diff.

## The user's question: could pure atoms be synchronous? (preliminary, nothing measured)

**Is there a reason they can't be?** Nothing in pure atoms themselves requires async. The cost comes from the shared wrapper: every atom, `effects: 'pure'` included, goes through `exec = async (step, ctx) => …` in `defineAtom` (`runtime.ts` ~5032). That wrapper:
- allocates a Promise for every step;
- `await`s the body, which costs at least one microtask hop per step, and more through nested `seq`/loop awaits;
- unless the timeout is 0 or Infinity, arms a `setTimeout` plus a `Promise.race` per step (the default timeout is 1000 ms), then clears it.

For a pure math atom, the timer and the race are pure overhead. They also cannot do their job: a synchronous body cannot be interrupted by a timer anyway.

**Upside.** Likely real for compute-heavy agents: tight loops of `binary`/`math`/data atoms pay the Promise, microtask and timer cost per step. A sync fast path would avoid three things:
- Promise and timer allocation;
- `setTimeout`/`clearTimeout` per step, which is probably the largest piece;
- scheduler hops.

Order of magnitude is unknown until measured. The usual pattern is an exec that returns `T | Promise<T>`, with callers that check for a thenable and only `await` when they get one.

**Downsides and constraints.**
1. **Starving the event loop.** The run deadline (`timeoutMs`) and `ctx.signal` aborts are delivered by timers and events. A long chain of sync steps never yields, so the deadline cannot fire. Today every step yields at least once. A sync path needs a forced yield every N steps or every K fuel. Fuel still bounds total work, so this is about wall-clock timeouts and host responsiveness, not safety.
2. **Composite atoms** (`seq`, `if`, loops, `map`/`filter` callbacks, `memoize`) can only stay sync if every child is sync. That means "sync when possible, async on the first thenable" plumbing through the step runners, which is a larger change than tagging leaf atoms.
3. **Public contract.** CLAUDE.md says "atoms are always async". Embedder atoms from `defineAtom` must stay valid. Keep `exec`'s external type async-compatible and add an internal sync path for core pure atoms only (the `EFFECTFUL_CORE_OPS` classification already separates them).
4. **Guardrails that would need re-checking:** `run-teardown.test.ts` (timer cleanup), `cost-invariant` (the fuel charge must stay the same on both paths), the `allocFrame`/heap frame push and pop (must stay balanced on both paths), `guest-fuzz` ("wall time tracks fuel"), and the per-step abort check.
5. **Two execution paths are a divergence risk**, the same class of problem as the inline runtime vs the real runtime. It would need a differential test: the same corpus through the sync and async paths, with identical results, fuel and errors.

**Suggested next step:** benchmark a pure-arithmetic loop (for example 1e5 iterations) with the per-step timer skipped for `effects: 'pure'` atoms. That is the cheapest change and probably most of the win. Then decide whether the full sync fast path is worth its complexity. File it as a card; it is a separate design task, not part of this release.


## Round 34 — plan (written before any code, per the cycle STOP)

**The underlying problem.** Rounds 31–34 all blocked on billing a REFUSED crossing, and every
time the defect was a gap between the work a refusal did and what it was billed. Each gap
mattered only because a guest can CATCH the refusal and loop on it, so every imprecision is a
repeatable amplifier, and exact billing has to hold on every path. Four rounds show that does
not converge by patching.

**Tonio's decision (2026-10-04): a refusal at the capability boundary ENDS THE RUN.** That covers
the outbound copy being refused, including a heap- or fuel-limited copy, and an input that does
not match the atom's declared schema. A guest cannot loop on a refusal, so imprecision costs at
most one walk per run, and that walk is bounded by the budget and by a guest heap the guest
already paid to build. It fits "the VM is correct and safe, not friendly": the transpiler catches
bad calls before they run.

1. **Halting is run state, not an error flag.** A flag on the error object would be dropped
   wherever an error is re-wrapped (`agentRun` re-throws a child's failure as a plain `Error`).
   - `vm.run` creates a shared `halt: { error? }` on the run context, which every child context
     shares because each is a spread of its parent.
   - A membrane refusal records itself there (`haltRun`, first one wins).
   - **Every step checks it** at the one point all steps pass, beside the existing abort check, so
     a halted run takes no further steps: no catch block, no parent step, no sub-agent step.
   - `vm.run` reports the halting error as the run's error and output.
2. **NaN under `fuel: Infinity`** (verified major): `bill` does no arithmetic on non-finite fuel.
   Row: a refused egress under `fuel: Infinity` halts with its own reason, and `fuelUsed` is never
   NaN.
3. **Honest `walked` on wide values** (verified major), still needed because the docs claim it:
   - `readOwnData` checks the budget per key (`Object.keys` itself is unavoidable and is
     tallied), and Map/Set check per entry;
   - an over-budget refusal reports the bytes actually tallied, so the bill is one definition on
     every path (the review's minor).
   - Row: a refused egress of an N-key object costs fuel ∝ N.
4. **Rows, built from transpile() where AJS can say it:**
   - a refusal inside `try` is NOT caught, and the run ends with the refusal's own message;
   - a refusal in a sub-agent (inline `agentRun`) ends the parent too, with the parent's
     `try` uncaught;
   - nothing after the refusal runs (a capability spy counts zero later calls);
   - existing rows that caught refusals are rewritten to expect a halted run.
   - Mutation-check each: no halt check per step, halt not shared, the result not reporting the
     halt.
5. **Docs.** The CHANGELOG (breaking: membrane refusals end the run; catching them is no longer
   possible), DOCS-AJS (custom atoms and try/catch), CLAUDE.md (security model), and
   vm-budgets.md.
6. **Carried:** the review-8 minors (format denylist pinned to tosijs-schema behaviour, a false
   refusal on `dependentRequired` keys named `pattern`, `ioSchemaOf` not caching a failed
   admission, CHANGELOG notes on non-JSON values and size) are handled in this round where
   trivial and carded otherwise.

Re-review scope: correctness + security + blast-radius over the round-34 diff.

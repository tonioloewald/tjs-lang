## Blocker

### B1. The positional-call refusal also rejects zero-argument calls (major, confirmed; treated as release-blocking)

- **Where:** `src/vm/runtime.ts:4745`. The `exec` check is `if (Array.isArray(inputData.args))` and throws when the schema names its inputs and none of them is `args`.
- **Cause:** `extractCallArguments` (`src/lang/emitters/ast.ts:2310`) emits `args: []` for `foo()`. An empty array passes `Array.isArray`, so the call is refused.
- **Reproduced at HEAD:** `function f() { const r = random()\n return { r } }` fails with "'random' takes named arguments: random({ min, max, format, length })". At `60cc51a` it returned a float.
- **Blast radius:** the documented builtin `random()`, and every embedder `defineAtom` whose object schema has only optional properties, when called with no arguments. The error message also wrongly implies the caller dropped arguments.
- **Fix:** refuse only when `inputData.args.length > 0`, meaning positional values would actually be lost. Add a guest-values row next to the positional-refusal row asserting that `random()` still runs (zero arguments, all-optional schema). Build the row from `transpile()` output, as CLAUDE.md requires for VM rows.
- **Re-review scope:** correctness and blast-radius over the remediation diff only.

## Remediation plan (round 15, filed before acting)

**Underlying problem (STOP flag):** both findings come from a rule with two interpretations.
- `Date`: the method table's `dateLike` admission, the `Date()` factory and `timeOf` each decided
  what a date is. They disagreed: a guest Date passed admission and then failed in the factory.
- Positional calls: the emitter writes `args: []` for every zero-argument call, and the VM read
  "has an `args` array" as "positional values were given".

**Fix: one definition per rule.**
- `timestampOf(v)` is the single meaning of "a date value": a number, a string that parses, a
  guest Date, or a plain object with a finite numeric `timestamp` (a Date after JSON, a store or a
  capability). The `dateLike` signature check, the `Date()` factory, `Date.parse`, `diff`,
  `isBefore` and `isAfter` all call it. A refusal names `Date(x.value)` or `Date(x.timestamp)`.
- Positional calls: the emitter stops writing `args` for a zero-argument call (an empty call
  has no positional values). The VM refuses only a NON-EMPTY `args` for an atom with named
  inputs, so persisted ASTs that carry `args: []` keep working.
- Rows, built from `transpile()` output: `random()`, `Date(d)`,
  `Date(JSON.parse(JSON.stringify(d)))`, `Date(d.value)`; a refusal row for the non-empty case.

  is not at fault.

## Blockers

### B-1. `quotaUsed` is never validated, so the per-atom quota fails open. Security, confirmed (tagged major, blocking)
- **Where:** `src/vm/runtime.ts:2677-2690` (the quota gate `used = ctx.quotaUsed[op] ?? 0; if (used >= quota) …; ctx.quotaUsed[op] = used + 1`). `src/vm/vm.ts:474` passes `options.quotaUsed ?? {}` straight through. `src/vm/admission.ts:74` validates `quotas` but not `quotaUsed`.
- **Repro (verified):** `quotas: { ping: 1 }`, and an agent calls `ping` 4 times.
  - `quotaUsed: { ping: NaN }`: all 4 calls run.
  - `{ ping: -100 }`: all 4 run, and the counter ends at -96. A negative count grants extra calls.
  - `{ ping: 'x' }`: all 4 run, and the counter becomes `'x1111'`.
  - Control `{}`: 1 call runs, then `Quota exceeded`.
- **Why it matters:** CLAUDE.md documents `quotaUsed` as the way to hold a cap across nested runs, so hosts share it and may restore it from a store. A corrupted counter silently turns `llmPredict: 3` into unlimited model spend. `quotaUsed` is also missing from `BUDGET_NAMES`, and rule 5 of the guard trusts `ctx.quotaUsed[op]` on the premise that ctx budget fields were validated. For this field, that premise is false.
- **Fix:** In `validateRunOptions`, require `quotaUsed` to be a plain object whose every value is a finite number ≥ 0. Refuse anything else; do not default. Add `quotaUsed` to `BUDGET_NAMES` in `src/budget-funnel.test.ts`. Add hostile-shape rows (NaN, negative, string, non-object) to `src/admission.test.ts`.
- **Re-review scope:** correctness and blast radius, over the remediation diff only.
- **Per the STOP line:** before patching, the remediating agent should ask why a fourth budget input escaped the funnel. The likely root cause is that `BUDGET_NAMES` is a closed list of names, so G-7 and F-1 below belong in the plan. The goal is to fix the whole class, not this one site.

## Blockers (verified majors; fix before tagging)

1. **[security, verified] httpFetch forwards a guest-chosen `Host` header and other forbidden request headers on the default path** (`src/vm/runtime.ts` ~6330).
   - `admitFetchUrl` checks only the URL hostname, and the guest `headers` object is spread onto every hop unchanged.
   - Reproduced through the VM against a local Bun.serve: with the allowlist `['127.0.0.1']` and a guest header `Host: admin.internal`, the server saw `host=admin.internal`.
   - Behind a reverse proxy or ingress that routes by Host, this reaches virtual hosts that are not on the allowlist. `Content-Length`, `Transfer-Encoding` and `Connection` also pass through, which exposes a request-smuggling surface.
   - Fix: refuse (do not silently drop) guest header names, matched case-insensitively, that are in the Fetch forbidden request-header set: host, content-length, transfer-encoding, connection, keep-alive, upgrade, te, trailer, `proxy-*`, `sec-*`.
   - Add a fetch-admission row asserting the server never sees a Host header chosen by the guest.
2. **[correctness/blast-radius, verified] The per-run capabilities copy drops prototype and accessor capabilities** (`src/vm/vm.ts:328`).
   - `Object.assign(Object.create(null), caps)` copies only own enumerable properties.
   - Reproduced with `class Caps { get store() { return real } }`. The guest's `storeSet` succeeds, the host store stays empty, and the only signal is the warning "Using default in-memory store". So the upgrade causes silent data loss.
   - The same mechanism drops a prototype `fetch`, so httpFetch falls back to the default fetch, and drops a prototype `llm` the same way.
   - Own getters are now invoked eagerly at run start, outside the try block. A getter that throws therefore rejects `vm.run` instead of producing an AgentError, which contradicts the "never run a host getter" stance.
   - Fix: shadow the host object instead of flattening it: `Object.create(admitted.capabilities ?? null)`. Alternatively, refuse non-plain capabilities objects by name.
   - Add test rows for a class-instance or prototype-getter `store` and `fetch`, and add a CHANGELOG note.

## Fix in the same remediation (verified minors on the same boundary)

- [ ] **[security, verified] A cross-origin redirect hop re-sends the guest's Authorization, Cookie and Proxy-Authorization headers** (`runtime.ts` ~6326). The old `redirect:'follow'` stripped them; this was confirmed in Bun with two origins. Drop them whenever `new URL(next).origin !== new URL(target).origin`, and add a fixture test.
- [ ] **[security, verified] A guest can bypass the X-Agent-Depth guard by changing the header's case** (`runtime.ts` ~6332 and the custom-capability path ~6303). A guest header `x-agent-depth: '0'` merges into the value `'0, 1'`, which `parseInt` reads as 0. Before adding the VM's value, delete or refuse any guest header whose name matches case-insensitively, on both paths.
- [ ] **[correctness, verified] In browsers every redirect is now refused** (`redirect:'manual'` gives `opaqueredirect`), but the CHANGELOG says redirects are "followed by the VM… each hop admitted again".
  - Document this in the CHANGELOG and the httpFetch atom docs.
  - Make the error message name the escape hatch: a custom `fetch` capability, or pointing the URL at its final location.
  - Optionally consider `follow` plus a post-hoc `res.url` admission in browsers.
  - The doc site's three example endpoints currently return 200 with no redirect, so the site is not broken today. This last point is unverified.

## Plan (round 21, filed before acting)

**Underlying problem:** round 20 made the VM the HTTP client for redirects, which takes on the
duties the platform's `fetch` performed: stripping credentials across origins and refusing
forbidden headers. Separately, guest-supplied headers were never ADMITTED: the URL was checked,
the request around it was not. And the capabilities copy flattened an object whose capabilities
can live on its prototype.

**Fix:**
- **One `admitHeaders(guestHeaders)`**, run once before any hop. It refuses (never silently drops),
  case-insensitively:
  - the Fetch forbidden request headers: `host`, `content-length`, `transfer-encoding`,
    `connection`, `keep-alive`, `upgrade`, `te`, `trailer`, `proxy-*`, `sec-*`;
  - the VM's own `x-agent-depth`.

  Used on the default path AND the custom-capability path (the depth header there too).
- **Per-hop request headers:** guest headers go to the first origin only. A hop to a DIFFERENT
  origin carries no guest headers, only the VM's depth header. That is stricter than the spec's
  Authorization-only rule, and simpler: nothing the guest chose follows it across origins.
- **The 3xx body is cancelled before every exit from the loop** (try/finally per hop).
- **Browser:** an opaque redirect is refused with a message naming the escape hatches (a custom
  `fetch` capability, or the final URL). Documented in the CHANGELOG and the atom docs.
- **Capabilities:** `Object.create(hostCaps)` shadows the host object instead of flattening it.
  Reads fall through to prototype members and getters, read when used, exactly as before rc.2.
  Writes (the default store) land on the shadow, so the host object is still never written.
- **Rows:**
  - a guest `Host` header is refused, and the server never sees it;
  - the depth header is refused in any case;
  - a cross-origin hop carries no guest `Authorization`;
  - a class-instance `store` and `fetch` are used;
  - the positive allowed-to-allowed redirect, the 303/POST→GET downgrade and a relative
    `Location`;
  - the redirect cap;
  - a `content-length` over the cap is refused before the body is read.

## Round 21 — implemented (2026-10-03)

- **Host header (major).** `admitHeaders` refuses, case-insensitively and before any request:
  the Fetch forbidden request headers (`host`, framing, `connection`, `upgrade`, `te`,
  `trailer`, `expect`, `via`, `proxy-*`, `sec-*`) and the VM's `x-agent-depth`, on both the
  default and the custom-capability path. Rows show the server never sees a request.
- **Capabilities copy (major).** `Object.create(hostCaps)` shadows the host object instead of
  flattening it: a class-instance `store` (a prototype getter) is used. The default store is
  defined on the shadow with `defineProperty`, so a frozen host object with `store: undefined`
  works. The `guest-key-writes` allowlist entry records why its literal key is the VM's own.
- **Minors.**
  - A cross-origin hop carries none of the guest's headers.
  - Each hop's body is released on every refusal.
  - The browser opaque-redirect refusal names the escape hatches and is documented in the
    CHANGELOG and `guides/patterns.md`.
  - Positive redirect rows: a relative `Location`, 303 turning POST into GET, the redirect cap,
    and a declared `Content-Length` over the cap.
- **Mutation:** 5 of 5 caught. **Lanes:** format, lint, make, test:fast, dogfood, and the full
  suite without the live LLM (7086, 0 fail).
- The remaining unverified items are on one card.

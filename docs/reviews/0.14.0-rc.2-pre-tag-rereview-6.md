## Blockers

### B1. "One admission, every path" leaves out the URL scheme, so the documented host fetch reads local files (security, confirmed)
- **Where:** `src/vm/runtime.ts` ~6388–6436. `admitHeaders` and `admitsMethod` run before the `if (ctx.capabilities.fetch)` branch. `admitFetchUrl`, the only scheme check (http and https only), runs only on the built-in path.
- **Repro (Bun 1.4.2):** use the safeFetch from `guides/safe-eval.md:72` (`allowed.includes(new URL(url).host)` → `fetch(url, init)`) and run `httpFetch({ url: 'file://api.example.com/etc/hosts' })`. Eval returns the host's `/etc/hosts`. `.host` is `api.example.com`, so the check passes, and Bun serves `file://`. The `src/lang/eval.ts:74` JSDoc wrapper has no check at all. Both documented wrappers also keep `redirect: 'follow'`, so an open redirect on an allowed domain reaches internal addresses. The built-in client stopped following redirects in round 23 for that reason.
- **This is the B1 class** (file:// on Bun) that was closed for the built-in client and is still open on the path the docs recommend. Rereview-5 asked for both (a), admission on every path, and (b), fixing the documented examples. (a) shipped without the scheme check. (b) was not done.
- **Fix:**
  1. Move the scheme check (the first part of `admitFetchUrl`) above the `capabilities.fetch` branch.
  2. Fix `guides/safe-eval.md`, the `eval.ts` JSDoc, `README` (~92), and `createSecureFetch` / `createFetchCapability` in `guides/patterns.md` and `DOCS-AJS.md`. Each must check the protocol, pass `redirect: 'manual'` and `credentials: 'omit'`, and say that `init.method`, `init.headers` and `init.body` are guest-chosen.
  3. Add a row (via `safe-eval-doc.test.ts`) that runs the **documented** safeFetch against `file://` and against a redirecting `Bun.serve`.
- **Re-review scope:** security plus docs/dx over the httpFetch host path and every documented host-fetch example, plus `doc-snippets` and `safe-eval-doc` tests. Per the STOP, run it as a **cumulative** pass against `v0.14.0-rc.1`.

## Majors (confirmed; must close before the tag; they are folded into the B1 remediation)

- **M1. The host-path method gate has no test that fails without it (correctness, confirmed).** `src/vm/fetch-admission.test.ts:535–584` sends `method: 'PROPFIND'` **and** `headers: { Cookie }` in one row. It accepts `/cannot be set by an agent|not allowed/`, and header admission runs first, so the Cookie refusal hides the method refusal. Mutating the gate to `verb !== undefined && !ctx.capabilities.fetch && !admitsMethod(...)` leaves fetch-admission, recursive-fetch and integration at 93/93, and all of src/vm plus src/use-cases at 1509/0. That is exactly the re-review-5 BLOCK regressing silently. **Fix:** split the row. Send `method: 'DELETE'` with no extra headers and assert `/method 'DELETE' is not allowed/` and `got.length === 0`. Send a GET with a forbidden header as its own row. Confirm by mutation that each row fails when its gate is removed.
- **M2. Eval and SafeFunction cannot declare `allowedFetchMethods` or `allowedRequestHeaders` (security, confirmed).** `src/lang/eval.ts:294` and `~387` call `vm.run` with `{ fuel, timeoutMs, capabilities, argsMaxBytes }` and no run `context`. Eval's own `context` option becomes guest **variables**. So `Eval({ ..., capabilities: { fetch: hostFetch } })` POSTing fails with "use … context.allowedFetchMethods", and the host fetch is called 0 times. Following that message with `Eval({ context: { allowedFetchMethods: ['POST'] } })` just creates a guest variable. The gate fails closed, so this is not a hole, but every write-through Eval integration broke with no remedy. **Fix:** add a host-only option (e.g. `fetchPolicy: { methods, headers }`) forwarded to `vm.run`'s context and kept separate from guest `context`. Make each entry point's error name its own knob. Add an Eval row that POSTs once the method is declared. Add a CHANGELOG note under Eval.

## Diagnosis (filed before acting; HELD for Tonio)

"One admission of the agent's request" was applied to PART of the request: the method and
headers, but not the URL. The request is the scheme, the destination, the method, the headers and
the body. Each partial application has been the next review's blocker.

**Proposed:**
- The SHAPE of the agent's request (scheme http/https, method, headers) is admitted on every path,
  always.
- The DESTINATION policy (`allowedFetchDomains` and ports) is enforced on every path WHEN SET, so
  a configured setting never silently stops applying; a host fetch without it owns its
  destination policy.
- `Eval` and `SafeFunction` get a host-only `fetchPolicy` option, kept apart from guest
  `context`.
- The documented host-fetch examples are fixed and tested as written.
- The next review is CUMULATIVE over the fetch/capabilities boundary since v0.14.0-rc.1, not a
  one-commit delta.

## Minor

1. **(unverified) `createAgent` exists in two copies, and the new test covers only one.** Two lenses reported this (correctness and blast-radius); merged here.
   - `src/lang/index.ts:438` is the copy the main `tjs-lang` entry exports, and it is also reached through the deprecated `src/transpiler`.
   - `src/lang/core.ts:113` is the copy reached through `tjs-lang/lang`.
   - Round 19 had to add `transpile(source, { atoms: vm.atoms })` to both copies.
   - `src/vm/call-shape.test.ts:21` imports only `../lang/core`. If the index.ts copy loses `atoms`, then for `import { createAgent } from 'tjs-lang'`:
     - a misspelled host input is no longer caught;
     - a host override with a wider schema (e.g. `httpFetch({ url, cache })`) is refused again;
     - the suite stays green.
   - The header comment at `src/lang/index.ts:188-191` records that the `transpile` copies already drifted in exactly this way.
   - Best fix: make index.ts re-export `createAgent` from `./core`, as it already does for `transpile`. The existing TODO card already names this.
   - Minimum fix: run the "misspelled host input is refused" row and the "host override with a wider schema is accepted" row against both exports.

## Nits

2. **(unverified) The core-name refusal hint can point at the wrong fix** (`src/lang/emitters/ast.ts:2353`). `fromCore` is true whenever `options.atoms` lacks the name, so the message gets two cases wrong:
   - `transpile(src, { atoms: { greet } })` followed by `storeSet(...)` is told "transpile with `{ atoms: vm.atoms }`", but the caller already passed `atoms`; the map is just partial.
   - `createAgent(src, vmWithoutAtoms)` is told to call `transpile`, which that caller never calls.

   Suggested fix: word the hint differently depending on whether `atoms` was passed at all.
3. **(unverified, no action needed) Notify custom-atom consumers.** When the rc ships, point snowfox-app at the CHANGELOG line about open schemas and `required`. Its custom atoms are the population this change will now reject.

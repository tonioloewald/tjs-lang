## Blocker

### B1. A guest Date has two JSON forms, and the host form depends on the host's time zone (major, confirmed by two lenses, treated as release-blocking)
`src/vm/runtime.ts:1637` (`makeGuestDate`), `:1608` (`dateAsIso`), `:3106` (`jsonOf`), `src/vm/vm.ts:654`

The correctness and blast-radius lenses reported this separately; it is merged here.

**What changed**
- Round 13 deleted the Date wrapper's `toJSON` and the result `egressData`.
- `dateAsIso` is applied only to the guest builtin `JSON.stringify`.
- `jsonOf` calls plain `JSON.stringify`. It is used by the default httpFetch body, and through `stringifyInput` by hash, console and storeProcedure.
- The run result is returned raw.

**What happens**
- Every host-side serialization writes the frozen 9-field object.
- The `year/month/day/hours/dayOfWeek` fields come from `get*()` local-time getters.

**Reproduced**
- A midnight-UTC Date sent as an httpFetch body reached the capability as an object with `hours: 2` under Europe/Berlin.
- The same value through guest `JSON.stringify` is `"2020-01-01T00:00:00.000Z"`.
- With TZ=America/Los_Angeles, the run result carried `hours: 2`, so the same program returns different bytes on a UTC Cloud Function and on a laptop.
- At base, every path wrote the ISO string.

**Consequences**
- Remote APIs receive an object where they expect a timestamp.
- `hash(d)` cache keys change.
- procedureStore, HTTP and worker consumers see a new result shape that also varies by machine.
- `DOCS-AJS.md:788` and `CHANGELOG.md:103` ("JSON writes it as its ISO string") are false on the host side.

**Fix (plan before patching, per the STOP line)**
- Use a single serializer. `jsonOf`/`stringifyInput` should use `dateAsIso`.
- Choose one host-visible result contract and state it:
  - either the result egress writes `value`/ISO,
  - or the calendar fields are computed with `getUTC*`, and the CHANGELOG lists the result-shape break with its migration (`d.value`).
- Tests: a Date crossing an io capability (httpFetch body), hash, and the run result, each in the documented form. Run them under a non-UTC `TZ`.

Re-review scope: correctness and blast-radius over the remediation diff.

## Remediation plan (round 14, filed before acting)

**Root cause of B1:** round 13 made a Date data, then gave it a SPECIAL JSON form (`dateAsIso`) in
one serializer. Every serializer that did not get the special case wrote the other form, and the
fields were local-time. Fixing serializers one by one recreates a list that has to be kept in sync.

**Fix by removal:** a guest Date has ONE form everywhere: the data object itself.
- Delete `dateAsIso`. Guest `JSON.stringify`, `jsonOf`/`stringifyInput`, capability bodies,
  `structuredClone` and the run result all see the same frozen object. A guest that wants the
  ISO string writes `d.value`. Breaking relative to rc.1's wrapper `toJSON`; CHANGELOG states the
  migration.
- Every calendar field and every method (`add`, `format`) uses UTC (`getUTC*`/`setUTC*`), so the
  bytes a program produces do not depend on the host's time zone.
- Test: the same program under `TZ=UTC` and `TZ=America/Los_Angeles` (subprocesses) produces
  identical results; a Date through an io capability body, `hash`, and the run result has the
  same form as guest JSON.

**Follow-ups taken in the same round:**
- The agentRun inline-AST bypass applies only in v1. In v2, the agentId is an EXPRESSION whose
  value is the AST, so evaluating it in the caller is correct. Rows are built from `transpile()`
  output.
- One `guestMember(obj, prop)` for a Set's `size`, used by the `member` node, the v1 dot-path and
  `pick`.
- Positional `agentRun(id, input)`: verify what the transpiler emits; map or refuse.
- Delete the dead `JSON.stringify` replacer branch.
- `MAX_VALIDATION_STEPS` stays fixed. It is named in the refusal and in vm-budgets.md.
- Lens "same value, every egress" goes in `docs/review-lenses.md`. CLAUDE.md gets "VM rows are built
  from `transpile()` output".

## Round 14 — implemented (2026-10-02)

- **B1** — `dateAsIso` is deleted. A Date has one form everywhere, with all fields and methods
  in UTC. `src/vm/date-tz.probe.ts` runs one program under `TZ=UTC`, `America/Los_Angeles`,
  `Asia/Kolkata` and `Pacific/Kiritimati`. The results must be byte-identical, and a
  capability's input must equal the guest's JSON. It includes an `add` across the US
  daylight-saving change. Before the fix the program reproduced `year: 2019, hours: 16`. Four
  mutants were caught: local field, local `add`, local `format`, and a reinstated special
  serializer.
- The agentRun inline-AST bypass applies in v1 only. A transpiled v2 row captures the caller's
  `k`.
- A positional call to an atom with named inputs is refused in `exec`, naming the shape. This
  applies to every atom, not just agentRun: `extractCallArguments` emits `args` for any
  positional call.
- One `guestMember` reads members for `member`, the v1 dot-path and `pick` (`size`).
- The dead `JSON.stringify` replacer branch is deleted.
- Lens 8 ("same value, every egress") is in `docs/review-lenses.md`. CLAUDE.md requires VM rows
  built from `transpile()` output.
- Lanes: format, lint, make and test:fast are green. Dogfood graduation improved to 125 (floor
  raised). The CSS theme perf ceiling moved from 8ms to 16ms: it measures 7.3ms at both 54e113e
  and HEAD, so this is not a regression, but the 8ms ceiling flaked under load. #2767 is the
  card to bring it back down.

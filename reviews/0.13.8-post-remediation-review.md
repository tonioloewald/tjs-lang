## Blockers (must clear before the next tag)

### B-1 — Second transpile-time ACE (review item M1) is live in shipped 0.13.8, untracked, and the CHANGELOG reads as though it were fixed

_(blast-radius / correctness — CONFIRMED)_
A `.tjs` return-type annotation is **evaluated**, not parsed, on the main transpile path (`tjs check` / `types` / `emit`, the bun plugin `.tjs` onLoad, the module loader, playground auto-transpile). No `test` block is involved, so the 0.13.7 `vmTarget` gate does not touch it. The verifier reproduced a filesystem write via `tjs check` (exit 0, `✓`) against HEAD, and confirmed the payload is present in the published `dist/` (6 live `new Function(\`return …\`)`sites in`dist/index.js`+`dist/tjs-lang.js`, 3 in `dist/tjs-eval.js`) — the exact `src`-vs-`dist` split 0.13.8 exists to fix. Blast radius is developer + CI machines (not the Cloud Functions endpoint — the AJS path rejects the carrier). It is in **no tracker** (`TODO.md`and`gh issue list`both empty for it), and`src/lang/eval-no-transpile-execution.test.ts`asserts test extraction is "the **only** dynamic-execution site in the entire parse path" while scanning only four`parser\*`/`core` files — the emitters, which hold the live sites, are outside its scan.

**Before next tag:** (1) file it in `TODO.md` under open findings **and** a GitHub security issue; (2) add a scoping line to the 0.13.8 CHANGELOG SECURITY section — the fix covers the VM-target path only, `tjs check`/`tjs()` on untrusted `.tjs` still evaluates annotations; (3) fix by **parsing** — walk the annotation with acorn (already a dep) and accept only literal / array / object / unary-numeric nodes; (4) correct the "entire parse path" claim in `eval-no-transpile-execution.test.ts` and extend its scan to the emitters; (5) add a guardrail test asserting a side-effecting annotation leaves host globals + filesystem untouched.

### B-2 — Every version ≤0.13.6 carries the same escape; none deprecated, no security advisory

_(blast-radius — CONFIRMED)_
The verifier ran the documented exploit against published tarballs: 0.13.6 / 0.13.1 / 0.12.0 / 0.10.0 all → `PWNED:true`. `npm audit` inside a tree pinned to 0.13.6 reports **zero** vulnerabilities; `gh api …/security-advisories` is `[]`. So a consumer on a lockfile or a resolved `^0.12.0` range gets no signal from any automated channel. Two aggravations the verifier found: the bug is **not** Node-only on prior versions (Bun resolves to `src/`, which was also vulnerable pre-0.13.7), so the 0.13.7 deprecation text misleads Bun users; and the existing 0.10–0.12 deprecations say "Upgrade to 0.13.1", which is **itself vulnerable**.

**Before next tag (Tier-0, post-publish distribution action):** `npm deprecate 'tjs-lang@<=0.13.6' "SECURITY: transpiling untrusted source executes it — upgrade to 0.13.8"`; publish a GitHub Security Advisory with the affected range (verify the lower bound — 0.10.0 confirmed) and fixed version — that is the only path to `npm audit`/Dependabot; amend the 0.13.7 deprecation string so it doesn't imply 0.13.7 was uniquely affected; correct the "upgrade to 0.13.1" advice on 0.10–0.12. (snowfox-app is a known production VM consumer.)

## Majors (confirmed — schedule, do not ship silently again)

### MJ-1 — Bootstrap self-hosting canaries are RED in CI right now

_(correctness — CONFIRMED, severity raised from minor)_ `src/use-cases/bootstrap.test.ts:650` and `:781` transpile 275KB of parser modules at ~79% of bun's 5s default and have **no explicit timeout** (sibling at 389 has `}, 60_000)`). This is not a latent flake — the last five CI runs, including both 0.13.8 commits, fail on exactly these two (`timed out after 5000ms`), so `test:fast` is red on `main` and masks every real failure behind a known-red baseline. Locally reproducible on an idle machine. Not caused by this diff (parser change measured within noise). **Fix:** add `}, 60_000)` to both. _(Per the standing rule, this red test is scheduled, not waved off as pre-existing.)_

### MJ-2 — Public endpoints transpile unbounded attacker input before any budget applies (review item M2)

_(blast-radius — CONFIRMED)_ `agentRun` (onCall) and `run` (onRequest, `ACAO:*`) validate only `typeof code === 'string'`; `Eval` transpiles before `vm.run`, and `preprocess` is quadratic. Verifier measured 500KB → 5.4s, 2MB → 79s, all spent before the parser rejects — no valid AJS needed. Event-loop stall for co-tenants + denial-of-wallet on the GCP project, drivable by any Google account, on a bundle `d96ee6b` actively redeployed (`/health` confirms live). The sibling `functions/src/demo-llm.tjs` already has `MAX_PROMPT_CHARS = 8000`; the endpoints that execute code got nothing. Untracked. **Fix (deploys without a release):** cap `code` length before it reaches the transpiler; reuse `claimQuota` for a per-uid cap; set `maxInstances`. Also correct CLAUDE.md's Security Model ("Fuel meters work, so it is the time budget" is untrue for submitted source — the transpiler runs unmetered ahead of the fuel budget).

### MJ-3 — Functions deploy path skips the build; `functions/lib/index.js` has no freshness guard

_(correctness — CONFIRMED)_ `functions/lib/index.js` is a tracked, deployed artifact bundled from `functions/src/*.tjs`; `firebase.json`'s `functions` block has **no `predeploy` hook**; the CLAUDE.md-documented `npx firebase-tools@latest deploy` path does not run the build; `src/functions-bundle.test.ts` asserts hardening _markers_ but never source↔artifact agreement (verifier proved the previous vulnerable 0.13.6 bundle passes all its assertions). CLAUDE.md's premise is also stale — the global firebase CLI is now 15.28.2, so `bun run functions:deploy` (which does build) likely works today. **Fix:** add `"predeploy": ["npm --prefix functions run build"]` to `firebase.json`; add a content-diff guard (re-emit each `functions/src/*.tjs`, compare to committed `.js` — I confirmed all nine are currently in sync and this runs in seconds with no install); fix CLAUDE.md's npx workaround to include the build.

### MJ-4 — Freshness lesson applied to `dist/` only; the guard cannot fire at the publish boundary

_(blast-radius — CONFIRMED)_ Three interlocking gaps: (a) `functions/lib/index.js` — largest blast radius in the repo — has no rebuild-and-diff guard (see MJ-3); (b) the new `src/dist-freshness.test.ts` is structurally vacuous in CI (`bun run make` rebuilds `dist/` before the tests run, so every bundle is newer by construction — it can only fire on a dev machine / pre-push tag gate); (c) `scripts/prepublish-check.ts` (the one gate at the harmful moment) is blind to `dist/` because it is gitignored, and the test `return`s silently when `dist/` is absent — a partial `make` (which starts `rm -rf dist`) can leave a tree that passes every gate and publishes a tarball whose `exports` point at missing files. **Fix:** move the assertion into `prepublish-check.ts` (assert `dist/` exists, contains the bundles named in `exports`, carries `dist/src/**/*.d.ts`, and is newer than the newest tracked non-test `src/` file); add the `functions/lib` content-diff guard from MJ-3.

## Minor / nit (unverified leads — sanity-check before acting)

- **MN-1 (reproduced by me) — nested-`given` switch loses its advice.** `switch-transform.ts:73` `return`s on recognising a lowered `given`, skipping the whole subtree, so an author-written `switch` inside a `given` arm gets `warnings: []` — the C-fallthrough diagnostic is suppressed for exactly the switch that is still a trap. _Unverified by the adversarial pass, but I reproduced it directly._ Fix: skip only this node's `out.push`, keep walking children; add a nested row to `given-semantics.test.ts`.
- **MN-2 (confirmed by me) — `dist-freshness.test.ts` + CHANGELOG 0.13.8 call `dist/` "committed"; it is gitignored (`.gitignore:92`), zero tracked files.** The docstring says "COMMITTED and PUBLISHED" and the analogy to `editors/**` (which really is committed) is the reasoning the next person reuses. The real enforcement point is the `.githooks/pre-push` tag gate, not CI. _Correctness, unverified by the pass; the "gitignored" fact I confirmed._ Fix wording in both; restate the enforcement point.
- **MN-3 (deduped: two findings, one issue) — the 0.13.7 review landed in top-level `reviews/` not `docs/reviews/`.** All prior reports live in `docs/reviews/` (which CLAUDE.md names, `package.json` excludes via `!docs/reviews`, and `src/docs-index.test.ts` globs `docs/**/*.md`). The new top-level `reviews/` dir is unindexed, unguarded, and is the only written record of M1/M2 — invisible to the tooling that looks for open work. _Unverified by the pass; dir existence + glob confirmed._ Fix: move to `docs/reviews/0.13.7-pre-release-review.md`, delete `reviews/`; consider widening the docs-index glob to catch top-level markdown in any new directory.
- **NIT-1 — a `test` block submitted to `Eval` fails with a bare "Unexpected token"** instead of a message explaining AJS has no test blocks (`parser.ts:543`). _Unverified._ Optional: throw a named error at the `vmTarget` gate when a `test` block is present.

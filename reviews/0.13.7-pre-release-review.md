## Blockers — must fix before tagging

### B1 · `Eval` / `SafeFunction` execute arbitrary host JavaScript at transpile time, before any fuel, timeout or capability check — live on the public `run` / `agentRun` Cloud Functions

`src/lang/parser.ts:519` → `src/lang/parser-transforms.ts:4376` · _security_

`parse()` unconditionally calls `extractAndRunTests(source, options.dangerouslySkipTests)`, which runs every `test '…' { body }` block with `new Function(body)()`. **No shipped caller sets `dangerouslySkipTests`** — the default is fail-open. `Eval` (`src/lang/eval.ts:87`) and `SafeFunction` (`:160`) call `transpile()` on the _submitted_ code, before `vm.run`.

Re-reproduced on HEAD just now:

```
Eval({ code: "test 'x' { globalThis.__PWNED__ = true; globalThis.__ENV__ = Object.keys(process.env).length } return 1",
       fuel: 10, timeoutMs: 1 })
→ {"result":1,"fuelUsed":0.1999999999999993}   __PWNED__: true   env keys read: 52
```

Full ambient authority, 0.2 fuel charged, `timeoutMs: 1` irrelevant — the payload ran during transpile, so the entire fuel/timeout/capability/membrane apparatus is downstream of the breach.

`functions/src/index.tjs:143` and `:244` pass user-supplied `code` straight into `Eval` from `agentRun` (onCall) and `run` (onRequest, `Access-Control-Allow-Origin: *`, Bearer ID token). The deployed bundle carries it (`functions/lib/index.js:8749`), and `/health` confirms the running function is built on this code path. `firebase-admin` is initialised with admin credentials in the same process; `users/{uid}` holds users' encrypted provider API keys **and** the `encryptionKey` that decrypts them. Anyone who can sign in with Google gets arbitrary code execution there.

The irony is in the repo: `parser-transforms.ts:5096` rejects user `new Function()` because it "evaluates arbitrary source with full ambient authority", and `:5089` points users at `Eval()` as the sandboxed alternative.

Pre-existing (not introduced in this range) — but this release **re-ships the vulnerable bundle** to a live endpoint, so it is in scope.

**Fix:** flip the default — `extractAndRunTests` runs nothing unless `runTests: true` is passed, with the CLI `test`/`check` paths passing it explicitly. Two-line stopgap today: `Eval`/`SafeFunction`/`createAgent` pass `dangerouslySkipTests: true`. Add a guardrail test (class of `membrane-invariant.test.ts`) asserting `Eval` on source with a `test` block cannot touch a host global. Rebuild and redeploy `functions/lib/index.js`, and **rotate project service-account / secret material** if the endpoints have been reachable in production.

### B2 · `return (x: 0) => …` and `export default (x: 0) => …` no longer parse — regression from a character-only look-back

`src/lang/parser-params.ts:765` · _correctness_

Re-reproduced on HEAD:

```
FAIL return arrow         -> Unexpected token at <source>:2:11
FAIL export default arrow -> Unexpected token at <source>:1:17
OK   const arrow (control)
```

`isCallArgs` decides "this `(` opens a call's argument list" from the single preceding **character** (`/[A-Za-z0-9_$)\]]/`), so the `n` of `return` and the `t` of `default` read as a callee. The arrow's parameter list is never transformed, `: 0` survives into acorn, and the file is rejected. All four shapes transpile cleanly at v0.13.6 (verified against a `git archive` tree); the guard arrived in `5522151`/`a42f8e3`, both post-tag.

Blast radius is **wider than reported**: `throw (x: 0) => x`, `yield (x: 0) => x`, and the curried factory `const f = (a: 0) => { return (b: 0) => a + b }` all fail too. Negative controls hold — `const f = (x: 0) => x`, `run((x: 0) => x)`, `{ f: (x: 0) => x }`, and the ternary shape `5522151` was fixing all still work, so the JS subset is intact and this is not a `PRINCIPLES.md` violation.

The same file already defines `EXPRESSION_PREFIX_KEYWORDS` (`:69`) for exactly this problem in the method-head path (`:659-668`) — a second, word-aware guard that `isCallArgs` never consults. **Note:** that set does _not_ contain `default`, so merely reusing it leaves `export default` broken.

Nothing caught it: no test has an annotated arrow after `return`/`export default`, and the compat corpus structurally cannot — `fromTS` emits `return (x) => x + 1`, i.e. `tsc` strips the inner annotation before our parser sees it.

**Fix:** extract one shared `precedingToken(source, i)` helper used by both guards; exempt `EXPRESSION_PREFIX_KEYWORDS` plus `default`, `else`, `do`, `try`. Add regression rows to `src/lang/parser.test.ts` for `return (x: 0) => x`, `return (x: 0): 0 => x`, `export default (x: 0) => x`, `throw (x: 0) => x`, `yield (x: 0) => x`. **Re-review scope:** correctness + blast radius over the remediation diff, plus `test:fast` and `test:dogfood` — the guard is on the hot scan path (see M6).

### B3 · Every `given` emits a warning telling you to use `given`, with the internal lowering leaked into the suggested source — and it fails `tjs check --max-warnings 0`

`src/lang/emitters/js.ts:1651` · _correctness_

`given` is lowered to a C `switch` in `parser.ts:407-416` **before** acorn; `switchAdvice(program, preprocessed.source)` then walks that lowered AST and cannot distinguish it from an author-written switch. Re-reproduced verbatim on HEAD:

```
⚠ g.tjs: `switch` here keeps JavaScript's semantics — arms fall through unless you write
  `break`, and they share one scope. `given` is the .tjs form and fixes both:
    given __tjs.swKey(x) {
      'first', 'second' { … }   // several values, no fallthrough
    } else { … }
```

So the release's headline construct (a) tells users to use the construct they already used, (b) shows them `__tjs.swKey(...)` — compiler internals — as their own code, and (c) makes `--max-warnings 0` exit 1 on any file using it. Emitted runtime code is correct, so this is diagnostic quality, not a miscompile — but it fires on 100% of uses with no workaround short of not using the feature.

The dialect gate is inverted from a mitigation: `dialect: 'js'` → 0 warnings, native `.tjs` → 1, and `given` is native-only. The existing assertions in `given-semantics.test.ts:124-128` and `:144-148` filter on the string `'falls through implicitly'`, which no longer exists in `switch-transform.ts` after the `#43` revert — **both pass vacuously.**

**Fix:** skip switches whose discriminant is a `__tjs.swKey(...)` call, or have `transformGiven` hand its synthesised source offsets to `switchAdvice`. Add a test asserting `tjs(givenSource).warnings` contains no switch advice, and a CLI test that `check --max-warnings 0` exits 0 on a `given` file. Fix the two vacuous assertions while you are there. **Re-review scope:** correctness over the remediation diff, plus a spot-check that an author-written `switch` still warns exactly once.

### M1 · `tjs check` executes the file it is checking — `new Function('return …')()` in the signature machinery _(security)_

`src/lang/emitters/js.ts:1131`, plus `src/lang/emitters/js-tests.ts:443,505,524,593,644`

### M2 · `run` / `agentRun` accept unbounded `code` and transpile it before any fuel or timeout — and transpilation is quadratic _(security)_

`functions/src/index.tjs:130` (and `:227`)

Both endpoints validate only `typeof code === 'string'` and `fuel <= 10000`. No length cap, no rate limit, no per-user quota. `Eval` transpiles before `vm.run`, so neither budget covers it. Measured: `core.transpile` 50 KB 0.18 s → 100 KB 0.44 s → 200 KB 1.44 s → 400 KB 4.65 s (~3.2× per doubling; ~28–30 s at 1 MB). Through the public API, `Eval({ code: <500 KB>, fuel: 1, timeoutMs: 1 })` blocked **6.88 s** and then returned `Out of Fuel` with `fuelUsed: 1.008`.

The burn is synchronous JS, so it blocks the instance event loop; with gen-2 default concurrency one request stalls the others multiplexed onto that instance. No `maxInstances`, no concurrency setting, no App Check anywhere. `firebase.json` rewrites `/run` to the function, so it is reachable at the site root. DoS plus denial-of-wallet from any free Google account.

The contrast is inside this diff: the _new_ `functions/src/demo-llm.tjs` has `MAX_PROMPT_CHARS = 8000`, a transactional `claimQuota` and two daily caps, with a comment articulating this exact threat model. The endpoints that execute attacker-supplied code got none of it.

_(One overstatement in the original: the "`page` is worse, no auth at all" parenthetical is half right — `page` skips auth for `public` stored functions, but its `code` comes from Firestore-stored owner-authored functions, not the request. Not an equivalent vector.)_

**Fix:** cap `code` length at both endpoints (tens of KB is generous) and reject before touching the transpiler; add a per-uid daily quota reusing `claimQuota`; put `page` behind a rate limit or App Check. And **document in CLAUDE.md's security model that the transpiler runs unmetered ahead of the fuel budget** — today the model says fuel is the time budget, which is untrue for anything submitted as source.

### M3 · `given` silently steals a braceless `if`'s `else` — and `graduate()` manufactures the poisoned shape _(correctness)_

`src/lang/given-transform.ts:175`

The `/^\s*else\s*\{/` lookahead after the `given` body allows arbitrary whitespace including newlines, with nothing checking whose `else` it is. For `if (c) given x { 'a' { return 1 } }\nelse { return 99 }`, the lowering emits `if (c) switch (…) { case 'a': …; default: { return 99 } }` — the `if` loses its `else` entirely. Measured with a real runtime: `f(false,'a')` returns 0 instead of 99. Syntactically valid, no warning, no diagnostic.

**Escalation the original finding missed:** the toolchain manufactures this itself. `switchToGiven` — reached via `graduate`, **both publicly exported** from `tjs-lang/lang` — converts legal JavaScript into the poisoned form. Input `if (c) switch (x) { case 'a': return 1 }\nelse { return 99 }` graduates to `given` with no `else`, directly abutting the `if`'s. Measured before: `f(false,"a")=99, f(true,"z")=0`. After: `f(false,"a")=0, f(true,"z")=99`. **Behaviour inverted, `notes: []`** — no decline, no warning. That violates both `graduate.ts`'s stated contract ("where that provably means the same thing") and `switch-to-given.ts`'s ("declines with a note at the site where an arm genuinely cascades").

Braced `if (c) { given … } else { … }` is safe; `else if` is safe; a `given` with its own `else` correctly takes its own.

**Fix:** only attach an `else` when the `given` is unambiguously a standalone statement — require the preceding non-whitespace character (masked view) to be `{`, `}`, `;`, or start-of-input; otherwise leave the `else` alone and warn. Add rows to `given-semantics.test.ts` and `switch-to-given.test.ts` pinning the emitted control flow.

### M6 · Transpile throughput regressed 1.5–3.3×; the backwards look-back in `transformParenExpressions` is the whole cost _(efficiency)_

`src/lang/parser-params.ts:640`

Measured HEAD vs a clean v0.13.6 tree, same `node_modules`, Bun 1.4.0, calling `transformParenExpressions` directly:

| input                        | v0.13.6  | HEAD     | ratio     |
| ---------------------------- | -------- | -------- | --------- |
| 10 KB                        | 3.9 ms   | 5.1 ms   | 1.31×     |
| 40 KB                        | 27.4 ms  | 40.1 ms  | 1.46×     |
| 80 KB                        | 79.8 ms  | 144.8 ms | 1.81×     |
| 157 KB (`src/vm/runtime.ts`) | 259.8 ms | 879.3 ms | **3.38×** |
| 313 KB                       | 964 ms   | 3,150 ms | 3.27×     |

End to end: `tjs()` on `src/builder.ts` 20.4 → 33.3 ms (+63%); `src/lang/inference.ts` 46.7 → 56.6 ms (+21%).

**Causally isolated, not profiler-attributed.** `prevNonWs`/`prevWord` feed only `isMethodDecl`, read only inside `if (methodMatch && isInClassBody() …)`. Gating the backwards look-back on that same condition is semantics-preserving — verified byte-identical output (including thrown-exception messages) across all 309 `.ts` files under `src/`. With the gate: 157 KB **879 → 34 ms** (96% removed), 313 KB **3,150 → 131 ms** (24×), and end-to-end `tjs()` on `builder.ts` 33.3 → 16.7 ms — _faster than v0.13.6_. The loop is not merely the regression; it is the dominant term in the whole pass.

**Mechanism refinement:** the loop's _iteration count_ is small (it breaks at the first non-whitespace char). The O(n²) term is per-**access**: `result` is built with `result +=` (a JSC rope), and `result[k]` forces a full flatten copy once per source character. The loop body is byte-identical to v0.13.6 — HEAD did not introduce the quadratic, it made each access more expensive.

`docs/parser-primitives.md:99` documents the quadratic but asserts _"It has never been localised to any single transform"_ — this measurement refutes that; update it.

**Fix:** (a) gate the look-back on `methodMatch && isInClassBody()`; (b) structurally, maintain the last-non-whitespace index incrementally as `result` is appended to; (c) hoist `isCallArgs` (`:760`) inside the `source[i] === '('` branch and move its regex literals to module scope so nothing allocates per character. This is the hot path for the CLI, the bun plugin, and the playground. **Coordinate with B2** — both touch this function.
